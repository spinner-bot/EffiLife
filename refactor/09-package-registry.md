# 09 包注册表与 ID 分配

- 日期：2026-10-27
- 状态：已确认（D-025），细节待设计文档补充

## 1. 原则

**ID 属于软件，不属于主题。**

- 主题包只提供内容与元数据：名称、版本、作者、许可、权限声明、校验和。
- 安装时由软件注册表分配 ID；ID 是本地安装编号，不是全局身份。
- 换设备、重装、重新导入都可能得到新 ID。
- 注册表同时负责权限登记、启停状态、激活指针、审计与墓碑。

这样第三方作者不需要协调全局唯一 ID，离线制作和导入也不会冲突。

## 2. ID 区段

建议按 kind 独立发号（theme / resource / function / data）：

| 区段 | 用途 |
|---|---|
| 0–9999 | 系统内置包，固定分配 |
| 10000+ | 用户与第三方包，注册表自动分配 |

规则：

- 已卸载的 ID 进入墓碑，不复用；
- ID 一旦分配，在本次安装生命周期内不变；
- 升级是否保留原 ID，取决于“更新识别”规则（见第 6 节）；
- 设置、激活指针、审计记录引用注册表 ID，不引用文件名。

## 3. 注册表记录

```json
{
  "schemaVersion": 1,
  "nextId": 10003,
  "entries": [
    {
      "id": 1,
      "kind": "theme",
      "name": "Paper & Ink",
      "version": "1.0.0",
      "author": "EffiLife",
      "source": "builtin",
      "path": "builtin://paper-ink",
      "checksum": "sha256:...",
      "status": "active",
      "enabled": true,
      "requiredPermissions": ["appearance.tokens", "appearance.css"],
      "grantedPermissions": ["appearance.tokens", "appearance.css"],
      "compatibility": {
        "formatVersion": 1,
        "apiVersion": 1,
        "minAppVersion": "3.0.0"
      },
      "installedAt": "2026-01-01T00:00:00Z",
      "updatedAt": "2026-01-01T00:00:00Z"
    }
  ],
  "activeByKind": { "theme": 1 },
  "tombstones": [1024, 1031],
  "audit": []
}
```

字段说明：

- `id`：注册表分配，本地有效。
- `kind`：包类型；各 kind 独立发号。
- `source`：builtin / official / third-party。
- `status`：active / disabled / broken / pending-consent。
- `requiredPermissions`：来自包 manifest。
- `grantedPermissions`：用户实际授权，宿主写入。
- `checksum`：内容指纹，用于完整性与重复识别。
- `activeByKind`：当前主题、资源包、功能包。

## 4. 生命周期

1. **安装**：读取包 → 校验格式 → 分配新 ID → 写入注册表 → 权限确认 → 启用。
2. **启用**：解析器按 ID 加载；失败则标记 `broken` 并回退。
3. **禁用**：停止沙箱、恢复安全主题，保留注册表记录。
4. **卸载**：删除包与缓存，ID 进入墓碑，不回收。
5. **升级**：见第 6 节“更新识别”。
6. **重装**：若按新包处理，分配新 ID；若识别为同一主题的升级，保留原 ID。

## 5. 权限登记

权限四方分离：

| 来源 | 负责 |
|---|---|
| 宿主能力目录 | 定义能力、级别、版本 |
| 包 manifest | 声明必需/可选能力 |
| 注册表 | 记录用户实际授权、时间、撤销 |
| 解析器 | 计算生效权限 = 必需 ∩ 授权 ∩ 应用策略 |

规则：

- 注册表由宿主独占，主题（包括 L3）不能直接写注册表、授权记录或审计日志。
- 升级后如果必需能力增加，标记 `pending-consent` 并禁用，直到用户重新确认。
- 撤销授权立即生效；依赖该能力的主题进入 `disabled`。
- L3 写操作进入审计；注册表本身不在 L3 可写的数据域内。

## 6. 待确认：更新识别

ID 由软件分配后，**软件如何判断“这是同一个主题的新版本”**需要定规则：

- 方案 A：按 `name + author` 匹配，命中则保留 ID、更新版本；
- 方案 B：按内容指纹（checksum）匹配，相同内容视为同一包；
- 方案 C：每次导入都视为新包，由用户在界面上选择“替换已有主题”；
- 方案 D：包内提供一个可选的 `slug`（仅用于更新匹配，不作为身份），由作者填写。

建议：**A + 用户确认**。默认按名称+作者提示“检测到同主题的新版本”，由用户选择更新或并存；`slug` 作为可选辅助，不强制。

## 7. 待确认：跨设备与存档

- 设置与存档里的主题引用是本机 ID，换设备后可能不存在。
- 可选策略：
  1. 存档只保存主题名称+作者+校验和，导入时按本机注册表重新解析；
  2. 数据包可选携带主题包，导入时一并安装并分配新 ID；
  3. 主题选择不进入存档，只保留本机偏好。
- 这与数据大改直接相关，等 schema 定稿后决定。

## 8. 不做

- 不要求第三方作者申请全局唯一 ID；
- 不把 ID 写进主题包的 manifest 作为身份；
- 不允许主题修改注册表或自己的授权；
- 不回收已卸载的 ID。

## 9. 与数据大改的关系

注册表是数据层的一部分：schema、存储位置、迁移策略都应在数据大改中统一定义。本文件只固定“ID 由软件分配、注册表管权限”的原则；具体表结构在数据 schema 定稿后实现。
