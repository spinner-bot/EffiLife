# 10 用户设计文档模板

> 这是模板，不是决策。复制一份改成 `refactor/11-user-design.md` 后填写；不需要懂前端，用自然语言、例子和截图即可。

## 写作规则（先读）

1. **写决定，不写形容词。** “现代、专业”不够；写“像 Linear 的命令面板，但更安静”“首页第一屏只放今天要做的三件事”。
2. **一条决定一个编号。** 例如 `R-001`、`R-002`，方便我逐条实现和验收。
3. **区分必须与可选。** 用“必须 / 应该 / 可以”标注；没有标注的默认不做。
4. **写状态。** 每个页面至少写：空、加载、失败、禁用、有数据。
5. **写失败路径。** 用户点错、服务不可用、数据损坏时看到什么。
6. **给例子。** 一段真实文案、一个真实流程、一张标注过的截图，比十句描述有用。
7. **不要写代码结构。** 你写“用户看到什么、怎么操作、什么算完成”，技术实现交给我。
8. **不确定就标“待定”。** 不要为了完整而编一个决定；我会在实现前集中问你。
9. **术语统一。** 先给一份词汇表，避免“计划/任务/待办/记录”混用。
10. **控制在 5–15 页。** 先写核心页面和流程，细节可以后续补。

## 7. 核心流程

每个流程写“起点 → 步骤 → 成功 → 失败/取消”。

1. 记录一条时间
2. 创建一个计划并拆任务
3. 完成一条待办
4. 导入/导出存档
5. 安装/切换/卸载主题
6. 首次启动

格式示例：

```
流程：完成一条待办
起点：首页今日待办
步骤：点击勾选 → 立即反馈 → 同步计划任务
成功：待办消失/进入已完成，计划任务同步完成
失败：提示原因 + 重试按钮；不丢失已输入内容
取消：恢复原状态
```

## 8. 组件与交互规则

- 按钮：主/次/危险各用在什么场景；是否允许图标按钮。
- 表单：标签在上还是在内；错误提示位置；是否即时校验。
- 弹窗：什么情况用弹窗，什么情况用页面；是否允许嵌套。
- 通知：Toast 停留多久；同时最多几条；失败是否必须手动关闭。
- 导航：当前页如何标识；返回逻辑；快捷键。
- 焦点与键盘：Tab 顺序；Esc 关闭；Enter 提交。
- 动效：哪些操作需要动画；时长感觉；是否尊重减少动画。

## 10. 运行逻辑

- 启动时先显示什么？加载多久可以接受？
- 数据加载失败时：整页错误、局部错误还是静默重试？
- 草稿：哪些输入需要自动保存；离开页面时如何处理。
- 跨窗口/多标签：哪些状态需要同步。
- 离线：哪些功能可用；恢复后如何处理。
- 删除/归档：是否需要回收站、撤销、二次确认。
- 状态变化：列出关键状态和允许的转换（可用表格）。

## 11. 数据与持久化假设

> 不需要写 schema；写“哪些东西必须保存、保存多久、能否导出”。

- 核心数据：计划、任务、待办、时间记录、分类、设置、主题、授权。
- 哪些数据必须跨设备/跨存档保留？
- 哪些可以重建？
- 导入旧存档时，哪些可以丢，哪些绝对不能丢？
- 删除后是否可恢复？保留多久？
- 主题/包的授权记录是否需要随存档迁移？

## 12. 非功能要求

- 窗口尺寸：最小宽度/高度；需要支持哪些尺寸。
- 性能：启动、切页、主题切换的可接受时间。
- 无障碍：键盘、对比度、读屏；是否有硬性要求。
- 多语言：中文/英文是否必须同步；主题元数据是否要翻译。
- 安全：第三方主题/功能包允许做什么；哪些必须禁止。
