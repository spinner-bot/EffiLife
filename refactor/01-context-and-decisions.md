# 01 背景、范围与决策记录

## 1. 当前状态

- 产品版本：1.7.0（统一工作台，Vue 3 + Tauri 2 + Python sidecar）
- 自动化：全量 Python 测试 1285 passed；发布预检 `ok: true`
- 视觉审计：[../docs/audit/2026-10-26-视觉审计.md](../docs/audit/2026-10-26-视觉审计.md)
- 审计后确认的两条非缺陷：
  1. 启动时补发预警是设计行为，不是过期弹窗 bug。
  2. 切分制的背景类别会把未记录时间计入，8/24 ≈ 33% 是正确计算；问题只是默认模式选择，已列入暂缓项。

## 2. 为什么要重构

用户的实际使用感受：页面布局混乱、交互与动效生硬、窗口尺寸变化后结构重叠、主题切换突兀、整体像课程设计而不是现代专业工具。

审计确认这不是单页 bug，而是结构问题：

- 12 个视图约 15,316 行，其中约 6,300 行是页面私有 CSS；
- 共享组件只有 12 个、约 1,524 行；
- 主题是 `ThemeEngine.ts` 内 2,750 行的 25 个源码分支，不是可分发资源；
- 计划详情左栏 280px / 内容 480px，重叠 200px；记录页标签竖排；移动端 FAB 遮挡内容；
- 字体规范未落地（实际 Microsoft YaHei + Segoe UI），字号出现 7–10px，41/49 个按钮回落到浏览器默认字号。

结论：需要重写**表现层 + 页面布局 + 运行逻辑**，并把主题升级为可扩展的包系统。

## 3. 重构范围

### 范围内

- 全部视图、应用壳、导航、移动端壳（仅作为桌面布局的响应式形态）
- 页面私有 CSS、空状态、弹窗、Toast、表单控件
- 主题引擎、主题运行时、主题包格式与权限系统
- 布局体系、响应式约束、动效系统、可访问性
- 信息架构：一套导航、合并设置、移除重复模块标签
- 页面布局与运行逻辑（具体方案等待用户设计文档）
- 包格式：数据包、资源包、主题包、功能包

### 范围外

- 数据层重构本身（另行进行；本重构只定义接口与文档，不抢先改 schema）
- 移动端原生技术栈、Android/iOS 实现
- 发布签名、应用商店、远程分发渠道
- Python sidecar 的业务逻辑

### 保留

- 领域服务、存储、数据协议、恢复链路
- 现有行为测试覆盖（替换 DOM/结构断言，不降低覆盖）
- 构建与发布链路
