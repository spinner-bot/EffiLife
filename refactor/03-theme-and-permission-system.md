# 03 主题系统与权限模型

## 1. 目标

- 主题不再是源码里的 25 个分支，而是**可打包、可分发、可第三方设计**的资源。
- 主题由**解析器**加载：校验、解析、权限裁决、过渡、回退。
- 主题表达力不设上限式收紧：可以带 CSS、JS、装饰层、动效、参数，甚至（在最高权限下）调整布局。
- 但**权限必须可控**：不受信任的主题可以被禁用，危险能力默认关闭。
- 布局稳定性优先：主题默认不能改几何结构；改布局必须走 3 级权限与宿主 API。

## 2. 分层

```
.t3el 主题包
   manifest.json      身份、版本、兼容范围、声明权限、能力
   tokens.json        语义 token（颜色角色/字体/间距/圆角/阴影/透明度）
   layers.json        声明式装饰层（渐变/纹理/噪点/粒子/模糊/暗角）
   motion.json        动效配置
   options.schema.json 用户可调参数的 JSON Schema
   styles/            可选 CSS（按权限启用）
   scripts/           可选 JS（按权限启用，沙箱运行）
   layout.json        可选布局覆盖（仅 3 级权限）
   assets/            本地图片、纹理、字体
   preview.webp       预览图
        │
        ▼
解析器（Theme Runtime）
   schema 校验 → 兼容性 → 权限裁决 → token 解析 → 对比度校验
   → 资源加载 → CSS/JS 沙箱 → 布局覆盖校验 → 过渡 → 持久化 → 回退
        │
        ▼
设计 token 层 → 布局原语 + 组件层 → 页面
```

## 3. 权限级别

权限从 0 到 3 递增。主题包在 manifest 中声明所需级别；解析器计算**生效权限 = 声明 ∩ 应用策略 ∩ 用户授权**。

| 级别 | 能力 | 是否可执行代码 | 说明 |
|---|---|---|---|
| L0 | 纯声明式 token：颜色、字体角色、间距、圆角、阴影、透明度 | 否 | 建议定义：最安全的皮肤层，可供不受信任主题使用 |
| L1 | 额外允许作用域内 CSS（禁止几何属性与外链） | CSS | 建议定义：视觉增强，但仍不能改变布局 |
| L2 | 允许自有 JS 逻辑，运行在沙箱中：可交互背景、电子宠物、装饰动画 | JS | 已确认：2 级权限 |
| L3 | 允许通过宿主 API 读写**软件自身应用系统**的数据与页面布局（不涉及操作系统） | JS + 宿主 API | 已确认：3 级权限，高于 JS 逻辑 |

> L0 / L1 的具体边界待用户确认。L2 / L3 由用户明确指定。

### 权限与信任

- **内置主题**：随应用发布，按包内声明的级别启用。
- **第三方主题**：默认不受信任，只启用 L0；用户按能力逐项授权。
- **禁用**：不满足权限、签名或校验失败时，主题可以安装但不启用；不可用时给出明确原因。
- **降级**：缺失高级能力时，优先降级到较低级别；如果主题核心依赖该能力，则拒绝加载。
- **审计**：L2/L3 启用、授权变更、加载失败都应有可见记录。

### 授权粒度（D-016）

采用**按能力逐项授权**，不默认整包全信任。能力清单由宿主定义，主题只能申请已知能力；未知能力直接拒绝。

建议的能力清单（最终以实现为准）：

| 能力 | 级别 | 说明 |
|---|---|---|
| `appearance.tokens` | L0 | 颜色、字体、间距、圆角等 token |
| `appearance.css` | L1 | 作用域 CSS，禁止几何属性与外链 |
| `overlay.canvas` | L2 | 装饰层绘制 |
| `overlay.interactive` | L2 | 可交互背景、电子宠物 |
| `app.layout` | L3 | 声明式布局覆盖 |
| `app.navigation` | L3 | 导航与入口调整 |
| `app.settings.read` / `app.settings.write` | L3 | 读写应用设置 |
| `app.data.read` / `app.data.write` | L3 | 读写计划、待办、时间记录等应用数据 |
| `app.theme` | L3 | 切换或覆盖主题选择 |
| `app.events` | L3 | 订阅应用事件 |

授权模型：

- 安装时展示完整能力清单；默认只授予 L0。
- 用户可逐项勾选；提供“仅外观 / 标准 / 完全信任”预设，但预设只是批量勾选，具体能力始终可见。
- 主题声明为必需的能力未授权时，拒绝加载或降级，并在界面说明缺失项。
- L3 能力首次授权需要二次确认；写入类能力必须展示影响范围。
- 所有 L3 授权与写操作进入审计日志；用户可随时撤销。
- 未来签名主题可以提供“一键完全信任”，但仍保留能力列表与撤销入口。

## 4. 解析器职责

1. **包读取**：ZIP 读取、结构校验、路径安全（见 04）。
2. **Schema 校验**：manifest / tokens / layers / motion / options / layout 全部有 schema。
3. **兼容性**：`formatVersion`、`apiVersion`、`minAppVersion`、`maxAppVersion`。
4. **继承**：主题可 `extends` 基础主题，缺失 token 回落默认；检测循环继承。
5. **权限裁决**：声明权限、应用策略、用户授权取交集；生成能力清单。
6. **token 解析**：颜色角色、字体角色、间距、圆角、阴影、透明度、动效；禁止未定义 token 直接注入 CSS。
7. **对比度校验**：正文/背景、次要文字、按钮文字低于 WCAG AA 时警告或拒绝。
8. **资源检查**：本地资源、MIME、路径；默认禁止外链。
9. **CSS 处理**（L1+）：作用域化、拒绝 `@import`、拒绝外部 `url()`、拒绝几何属性。
10. **JS 沙箱**（L2+）：Worker / iframe 隔离；不暴露 DOM、存储、网络、文件系统；通过宿主桥接提供受限能力。
11. **布局覆盖**（L3）：只接受宿主定义的结构化覆盖，不由主题直接操作 DOM。
12. **切换过渡**：预加载 → 双层交叉淡化或 View Transitions → 成功后持久化；失败回退。
13. **卸载/清理**：停止沙箱、释放资源、恢复默认主题。

## 5. 3 级布局修改的边界

用户明确：主题可以修改默认参数（布局），但需要 3 级权限。建议实现方式：

- **声明式布局覆盖**：`layout.json` 只能引用宿主定义的区域（shell/header/sidebar/main/footer/overlay）和变体（密度、导航位置、面板顺序、尺寸范围）。
- 解析器按 schema 校验，拒绝未知区域、越界尺寸、破坏可访问性的覆盖。
- 不开放任意 DOM 操作或任意 CSS 几何属性；否则每套主题都要重新做全站布局验收。
- 如果用户确实需要“任意布局”，那已经属于功能包（`f3el`）或宿主插件范畴，需要单独的信任与安全模型。

> 该边界需要在用户的设计文档中最终确认。

## 6. L2/L3 代码执行沙箱（建议）

- **L2**：
  - 运行在 Web Worker + OffscreenCanvas，或隔离 iframe；
  - 无 DOM、无 `localStorage`/IndexedDB、无 `fetch`、无文件系统；
  - 宿主提供绘制层与生命周期事件（挂载、可见性、主题变量、尺寸）；
  - 限制 CPU/内存/帧率；`prefers-reduced-motion` 时降级。
- **L3**：
  - “系统”仅指软件自身的应用系统，**不涉及操作系统**；
  - 不直接访问 IndexedDB / localStorage / 文件系统 / 进程 / 注册表；
  - 只能通过宿主 API 读写应用数据；写入必须经过 schema 校验、事务或备份、可回滚；
  - 布局修改走声明式覆盖或受控 API；
  - 首次启用与每次写入类授权都需要明确用户确认；建议未来要求签名；
  - 所有 L3 操作进入审计日志，用户可撤销授权。
- 任何级别都不得静默访问网络；需要网络的场景应作为显式能力另行设计。

## 7. 主题切换与动效

- 切换前预加载目标主题的资源；
- 使用 View Transitions API 或双层交叉淡化，先切换背景/表面，再切换文字与控件；
- 过渡期间禁止布局变化；
- 尊重 `prefers-reduced-motion`；
- 切换失败自动回退并提示，不白屏。

## 8. 内置主题与旧主题迁移

- 25 套旧主题**全部保留**，逐步转换为 `.t3el` 包。
- 内置主题也走同一解析器，不以源码分支存在。
- 建议先迁移 5 套作为参考样例（浅色、深色、跟随系统、2 套风格化），其余按视觉质量分批。
- 旧 `Config.theme` 的 `type` 与各预设参数映射为新主题的 `themeId + options`；旧 `.efl` 存档导入时走兼容迁移。
- 迁移脚本与映射表在 Phase 6/7 产出。

## 9. 包体积限制

- 用户决定：**暂时不设大小限制**。
- 仍建议保留与“大小限制”不同的结构性安全校验：路径穿越、符号链接、外部 URL、压缩比异常、条目数异常。
- 是否保留这些结构性校验，以及是否需要流式解压，见 07 待确认事项。

## 10. 与数据大改的关系

主题的持久化字段（`themeId`、主题版本、options、授权记录）属于数据层；必须等数据 schema 定稿后实现。Phase 6 可以先做解析器与运行时，但持久化与旧配置迁移要等数据层冻结。
