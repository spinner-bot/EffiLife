# 0002 — 持久化与存档兼容阶段

- 日期：2026-11-11
- 作者：Codex  (sqs_A100)
- 产品版本：3.0.0（开发中）

## 已实现

- 应用服务通过存储接口提交统一命令；IndexedDB 对工作区和上一有效备份采用同一读写事务。
- 独立窗口的写入由数据库串行化，重试凭据随实际数据共同保存，重启后继续去重。
- 结构与引用校验覆盖持久化工作区；损坏主数据可由已有有效备份恢复。
- 新数据包含清单与 SHA-256，导入先预览、后由应用服务替换，替换前保留备份。
- 兼容旧多数据集 EFL、archive.json 与 JSON；原始数据留存在 legacy 字段，便于后续继续迁移设置。
- 保留旧计划分节、嵌套分组、软删除条目、原编号及日志精度；归档快照采用独立身份范围。

## 失败与修复

迁移测试首次运行暴露两处问题：软删除子项被跳过，导致日志无法关联；活动与归档计划复用旧 ID，导致日志身份重复。现已分别保留历史节点并隔离归档命名空间。模糊日志不参与精确时长参考的生成。

## 验证

- 自动化：6 个测试文件，37 项通过。
- 严格 TypeScript 检查：通过。
- 存储测试使用 fake-indexeddb，覆盖双连接并发、事务中止、重启去重、备份替换和损坏恢复；真实浏览器验证在界面阶段补齐。
- 存档测试覆盖往返、篡改检测、旧数据、归档身份、路径穿越、大小写冲突、符号链接与未来 schema 拒绝。
