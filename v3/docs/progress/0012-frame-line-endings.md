## 已完成的换行修复

独立复核指出 Windows CRLF 检出有两条失败路径：--check 比较原始 CRLF 与生成 LF 导致误报；重新生成后按 CRLF 原始字节计算的 SHA-256 与浏览器把内联脚本规范化为 LF 后的文本不一致。修复前集成测试复现了 CRLF、单独 CR 两项失败。

sync-frame.mjs 在哈希和嵌入 HTML 前规范化 CRLF 与单独 CR 为 LF；检查生成文件时也按此规范化比较，写出始终为 LF。没有放宽真实内容变化的检查，JS/CSS 实质变化仍会拒绝 --check。v3/.gitattributes 将两个源文件、生成 HTML、Tauri 配置及生成脚本固定为 LF。
