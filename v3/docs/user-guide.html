EFFILIFE · 3.1.0

时间与事件，连成生活的脉络。

持续管理生活中的投入、主题进展与零散事项。一次记录行动，在需要的视角中查看，不必在时间侧和事件侧重复登记。

开始使用

目前提供 Linux amd64 的桌面验收包。已在本地 Ubuntu SDK、GTK 3.24.33 和 WebKitGTK 2.50.4 下运行验收；Windows、macOS、移动系统尚未实测。仓库中的旧版代码保留，新版使用独立的数据身份；导入旧存档前可先备份。

在具有图形桌面及相应软件源的 Debian/Ubuntu 目标机上，可从安装包所在目录执行：

sudo apt install ./EffiLife_3.1.0_amd64.deb

从桌面应用菜单打开 EffiLife，或者运行 effilife-desktop。首次启动为空数据。浏览器预览在仓库根执行 python3 v3/scripts/run.py npm run dev，访问本机 http://127.0.0.1:3420。

浏览器与桌面各自保存数据。不同浏览器地址或端口也可能属于不同存储空间。当前通过导出、导入交换数据，尚无账号与自动云同步。

用同一个入口，记录一次行动

  1. 点击醒目的统一记录按钮，说明这次做了什么。
  2. 需要关联时，选择计划及具体条目，或选择一项待办；吃饭、通勤等日常行动可以独立记录。
  3. 知道实际区间时填写开始、结束时间，用时随之更新；编辑用时会按结束时间反算开始时间。再次修改区间仍会重算用时，空值和不一致值不能保存。关联类别会自动带入，可在本次记录中调整。
  4. 计划尚未完成时照样记录进展。只有确实完成时才勾选完成任务；待办的本次记录也可同时完成事项。

计划条目和待办旁的记录操作会打开同一界面，并预选关联事项。保存一次，就能从事项看到投入，也能从时间记录返回原事项。

没有明确用时的计划进展，可以只写日志。上次观测到本次行动的间隔是参考：如果中间穿插了其他任务，不能把整段间隔自动当作实际投入。只有确认区间后才产生相应时间记录。

为重要的事保留结构，为小事保留轻便

主题计划

一份 Plan 围绕课程、项目、旅程等持续主题组织，通过分组与子项组织。创建计划时选择背景时间类别，分组可选自己的默认类别，未指定时继承上一级；子项名前显示有效类别标签。稳定编号保留在内部，不占据主列表。

日志记录本次推进；任务完成状态独立。日志可编辑，关联时间说明同步更新。删除本次行动时会确认并移除直接关联的时间记录。

独立待办

快速记下一件事，按需要再补充子清单、置顶、类别、标签、安排和优先属性。子清单勾选不等于整项完成。

重复待办完成后保留历史，只创建下一个未来实例。重新打开再完成不会再复制一份下次安排；错过的周期不批量补造。

拖住三横线手柄可调整顺序和层级；分组会携带完整子树。灰色占位表示松手后的落点，左右移动选择更浅或更深的归属。松手即保存，无需额外确认；键盘方向键也可调整结构。

计划标题旁的类别按钮设置整份计划的默认时间类别，并保留已有显式选择；分组菜单的统一设置直接覆盖下方全部分组与子项，单项菜单只修改该子项。历史用时始终保留原有类别。各类别选择框提供“＋新建时间类别”，创建后返回原表单。类别难度仅用于待办排序，不改变时间统计。

区分实际投入、分配与派生背景

总览保留全天一个圆环；时间详情按类别分别显示圆环，彩色分段对应每条具名记录，点击图例可定位该记录。记录采用类别标签＋名称、粗体时间＋描述两层展示。跨日记录仅计入所选日期部分，重叠区间会提示；中心总时长按区间去重，组成分段保留每条记录的时长。跨午夜的行动可以从计划直接定位到时间记录，再返回具体条目与日志。

  • 分配制：对比当天计划分配与实际投入，计划本身不会生成实际记录。
  • 切分制：把当天已经过去、尚未观测的区间归入背景类别，并明确标记为派生值。
  • 日期方案：当日手动指定优先于有顺序的日历规则，最后才使用默认方案。可配置每周、每月、每年和每月第几周等规则。编辑模板默认只修改模板；要同时指定当前日期，请明确勾选该选项。之前已有的当日指定保留，需要时在时间面板右上菜单的“修改日程方案”中恢复自动匹配；两个日期选项旁的问号可查看含义。

“更多”中直接进入时间类别、分配方案管理、日程规则和主题外观；末项“设置”收纳语言、时区、顶栏时钟、数据与扩展维护。时间分配面板用于展示，删除方案须进入管理页；普通日程规则通过手柄拖动决定匹配顺序，背景兜底固定底部且不可删除。删除兜底引用方案时须先选择替代方案。

设置中的时区决定日期边界和显示。不存在的夏令时时刻会被校验，避免把用户输入静默变成另一个实际时间。

备份、迁移与恢复

3.0.1 修复了午夜夏令时和旧数据时间换算问题。若曾用 3.0.0 迁入这些日期的旧数据，请先导出备份并核对原始来源；此次更新不会猜测并自动重写已有 UTC 记录。

  1. 在“更多 → 设置”中导出数据存档。桌面端选择文件路径，浏览器端下载文件。
  2. 导入支持新版 .d3el、兼容的旧 .efl 和旧 JSON。先查看内容数量与迁移提示，再确认替换当前工作区。
  3. 每次有效提交保留上一份有效快照。需要撤销一次替换时，可使用“恢复上一份有效备份”。

恢复是整个工作区的替换，之后再次提交也会更新这份备份；它不是长期多版本历史。重要节点应另外导出存档，应用会校验包内容的 SHA-256。卸载程序、清理浏览器站点数据前，请保留所需导出文件。

当前导入默认限制输入为 64 MiB，ZIP 单条解压为 32 MiB、累计为 128 MiB；超出处理预算会停止并提示。预算由运行环境配置，不改变存档格式。

不存在的旧当地时刻会在导入预览中明确警告，相关记录或完成时刻不迁入，原始来源保留。旧模糊时间、已删除条目的历史引用和原始迁移输入会尽量保留；不会为旧勾选状态补造一个完成时刻。导入数据包后，扩展高级权限需要重新授予。

语言、字体和主题可以扩展

“更多 → 主题与外观”提供本地字体和 25 套主题。卡片外观可选实色、通透玻璃、磨砂柔光，选中框上的齿轮悬停或聚焦后显示“高级设置”。在弹窗中调整该材质支持的透明度、模糊、染色或圆角等参数，预览后保存。每套主题有自己的默认值，也可单独恢复默认；动画速度、背景强度和粒子密度仅在支持的动画中提供，并遵循系统减少动态效果设置。“更多 → 设置”中调整语言和时钟的日期/时间、12/24 小时制、AM/PM 与居中/右置。主题、语言与字体通过共享目录加载，失败时回退到可用的默认资源。

安装扩展时先阅读包信息和能力请求。布局、数据和系统级能力需要明确授权；可以在设置停用或卸载。外观出现异常时，使用独立恢复控件，或按 Alt+Shift+0 进入安全模式；URL 的 safe=1 也可跳过扩展启动。

扩展作者可阅读 扩展开发 HTML 指南。AI 自然语言/语音录入、日报周报、智能穿戴、云同步与后续客户端仍属于远期范围。

验收时可以顺着这条动线

  1. 新建主题计划和条目，设置默认类别，记录一段未完成进展并关联实际用时。
  2. 从日志进入时间页，再返回具体日志；刷新后确认记录保留。
  3. 建立带子清单的重复待办，记录用时并完成，检查历史和下次事项。
  4. 导出存档，再新增事项；导入旧存档后恢复上一份备份，确认新增事项回来。
  5. 切换主题与语言，尝试扩展授权和独立恢复；缩小窗口检查高频入口是否仍可直接操作。
