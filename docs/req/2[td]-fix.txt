1.优先级是int（0,1,2,3，……）。你设计的那个紧急与重要2*2，可以作为2个新属性存在（紧急、重要的选择框）、
2.为什么“yyyy/mm/日”？why not“yyyy/mm/dd”????（这个问题我似乎在其他模块也看到了）
3.分类是自定义的。预先提供100+种精美图标和62种ASCII图标（大小写字母，数字），用户创建新分类时可以选一个图标，然后搭配不同配色（配色可以自己选择推荐配色，也可以自定义）
4.对于每一个事件，增加“难度”设定（int）（0表示：该类别下的任何任务默认为瞬间可完成。）默认的难度为5
5.任务也有开始时间。在制定任务时，默认的开始时间是制定的时间，但是也可修改
6.定义事件的“优先排位分”：

评估时间=(1-(50/(事件类别难度+50))^优先级)*(DDL-开始时间)
评估充裕度=（DDL-当前时间）/评估时间，
标定时间=min（DDL-开始时间，预估时间需求）
标定充裕度=（DDL-当前时间）/标定时间
时间充裕度=0.65*exp（0.5ln评估充裕度+0.5ln标定充裕度）+0.7评估充裕度*标定充裕度/（评估充裕度+标定充裕度）
基础优先度=（(145+事件类别难度) if 重要==True else 0）+（(1335+3*事件类别难度) if 紧急==True else 1000）/时间充裕度
优先排位分=int(基础优先度*（1.06^优先级+1.35*(x^1.5)-1）+0.5)
（映射规则：如果优先排位分>10^10,则映射到：int(10^10+100*lg(优先排位分)+0.5)）

优先排位分是事件排序和提醒等的一个核心依据。

在计算前，必须进行校验，否则将会导致崩溃（0级-除零；超过DDL仍计算-负数开方……）
7.类别的优先排位分：sum（优先排位分，事件）/sqrt（类别中事件总数）。左侧栏中动态调整类别展示排序，统计栏固定在下方。到达临界后的部分可以滚轮滚动。排位前X的类别展示，排位X+1及以后的有有效待办类别折叠收纳（也可直接展开），没有有效待办的再单独在更下方折叠（空类或者全是已完成的事项）。也可以对类别进行置顶
8.每个事项直观展示其优先排位分（但在外面不直接写这个名字“优先排位分”，直接写数。你看看怎样设计好一点。在详情页可以写上这个名，并且这个是重点）
9.优先排位分实时计算，动态更新。设置中可指定更新频率
10.如果优先排位分>=10^10，则在空间较小处展示为EL+number，其中number为（优先排位分-10^10）/100。  else if>=10^8, 则转换为EL+number，其中number为lg(优先排位分)+0.5）（以上两种情况都保留到1位小数）但在详情中展示完整分数
