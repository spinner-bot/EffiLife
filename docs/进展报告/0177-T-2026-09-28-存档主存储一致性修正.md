# 0177-T-2026-09-28 存档主存储一致性修正

## 1. 发现

统一工作台已将配置、时间计划、日程规则和手动计划迁移到 IndexedDB 主存储，但 `.efl` 收集逻辑仍直接读取 localStorage 镜像。两者在迁移、异常写入或旧版本残留时可能不同，导致导出的存档不是当前工作台实际加载的数据。

## 2. 调整

- 新增 `readCoreJSON`：优先读取 IndexedDB，只有 IndexedDB 不可用或无值时才回退到 localStorage。
- 配置、计划、日程规则和手动计划的存档收集改用该读取路径。
- 记录、待办和 plan-helper 快照原有的 IndexedDB/快照优先逻辑保持不变。
- 新增存档主存储契约测试。

## 3. 约束

- 不改变 `.efl` manifest、dataset 名称或导入格式。
- 音频/事件等仍由现有服务以 localStorage 为主的模块不强行切换，避免把旧镜像误当作新主数据。

## 4. 验证

- `npm run build`：通过，1864 个模块转换成功。
- 存档主存储测试：1 passed。
- 完整 Python 回归测试：58 passed，9 warnings。
