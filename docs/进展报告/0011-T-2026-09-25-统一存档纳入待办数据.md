# 统一存档纳入待办数据

**文档性质**：临时实施报告
**创建时间**：2026-09-25（Asia/Shanghai）
**创建作者**：Codex

**触发原因**：统一待办已进入 time-helper，但原有 `.efl` 存档只覆盖时钟、计划、记录和设置。若不扩展存档协议，用户导出或导入时会静默遗漏待办数据。

## 1. 已完成

- `.efl` 存档版本从 `2.0` 升至 `2.1`。
- 导出时从 `TODOS` IndexedDB 对象存储读取全部待办，写入 `archive.json` 的 `todos` 字段。
- 导入时识别 `todos` 数组，清理当前待办对象存储后按稳定 `id` 恢复待办。
- “清除所有数据”同步清理待办对象存储。
- “清除设置”不清理待办，避免重置范围扩大。
- 旧版没有 `todos` 字段的存档仍可导入，保持向后兼容。

## 2. 数据边界

待办仍然以对象数组保存，保留子任务嵌套结构和完整扩展字段，不转换为仅有标题的简化记录。存档层只负责可靠搬运，不在导入时重算任务编号或改写计划引用。

## 3. 验证

- 使用 Vite 生产构建验证 `ArchiveService` 的异步导出和导入类型。
- 使用 `vue-tsc --noEmit` 检查本轮新增代码，未发现 `ArchiveService` 或待办服务相关新诊断。

## 4. 下一步

下一步将把待办统计接入首页工作台，并设计计划任务到待办的显式关联入口；完成后再处理跨旧模块数据迁移，而不是让不同模块继续各自维护隐式映射。
