# EffiLife 统一化改造基线

**文档性质**：重点架构基线

**创建时间**：2026-09-25（Asia/Shanghai）

**创建作者**：Codex

**触发原因**：项目从三个相对独立的效率模块，转向统一的个人时间管理软件。需要先固定目标、边界、迁移策略和验收标准，避免后续变成简单拼接。

## 1. 最终产品目标

EffiLife 最终形成一个统一应用，围绕“计划—行动—记录—复盘”闭环提供能力：

```text
计划与目标
    ↓
可执行任务 / 日程安排
    ↓
时间记录与实际投入
    ↓
待办状态与完成证据
    ↓
统计、复盘、调整下一步计划
```

三个现有模块的职责不再以三个应用呈现，而是成为同一产品中的领域能力：

- `time-helper`：时间记录、计时、日历/历史统计和主题视觉基础；
- `plan-helper`：计划、任务、日志、模板、归档和计划级统计；
- `to-dos`：任务执行队列、优先级、截止时间、子任务和待办状态；
- `common`：统一数据、事件、API、认证和跨模块引用。

## 2. 当前基线判断

### 已有资产

- `time-helper/desk` 已具备 Vue 3 + Tauri 桌面壳、主题引擎、主题画布、音频和动效基础。
- `plan-helper` 已具备原始 `Plan` 数据结构、Web UI、计划任务、日志、归档和 API。
- `to-dos/ui` 已具备 Vue 3 前端和待办领域界面。
- `common/` 已有统一模型、API Gateway、事件总线、DataManager 和跨模块适配器雏形。
- 项目已有集成测试、版本规范和 no-FF 合并要求。

### 当前主要问题

- 三个模块仍然拥有不同的启动方式和 UI 入口，用户感知不到统一产品。
- 统一模型存在，但没有成为唯一的跨模块数据边界。
- 存储路径、导入导出、备份和版本迁移尚未形成统一协议。
- `time-helper` 的丰富主题架构尚未成为其他模块可复用的视觉能力。
- 启动器使用方式不稳定，尚未具备可靠的环境探测、服务就绪检测和错误恢复。
- 多语言尚未建立资源层，界面文本仍散落在组件和 Python 页面中。

## 3. 架构方向

### 3.1 统一应用壳

以 `time-helper/desk` 的 Tauri + Vue 桌面壳作为第一候选宿主，但不直接把其他模块代码复制进去。统一壳负责：

- 全局导航、窗口、通知、主题、语言和设置；
- 启动各领域服务或调用统一 API；
- 统一导入、导出、备份和恢复；
- 统一错误、加载、空状态和快捷键体验。

### 3.2 领域模块化

应用内部保持领域边界：

```text
app-shell
├── dashboard
├── planning       ← plan-helper 能力
├── focus-time     ← time-helper 能力
├── tasks          ← to-dos 能力
├── insights       ← 跨模块统计
└── settings       ← 主题、语言、数据与系统设置
```

领域模块可以独立测试和演进，但通过统一 API、事件和模型协作。

### 3.3 数据统一但保留兼容层

不直接破坏原始 `plan-helper` 数据结构，也不强行让三个模块立即共享同一个内部对象。采用：

```text
旧模块数据 / 旧 JSON
        ↓ 适配与迁移
统一数据协议（canonical data）
        ↓
各领域服务与统一 UI
```

旧数据必须可导入；统一导出应包含 schema 版本、来源、时间戳和跨模块引用。

## 4. 视觉与主题目标

- 提供基础主题：浅色、深色、跟随系统。
- 继承 `time-helper` 的复杂主题引擎和主题画布能力。
- 将主题拆为设计令牌：颜色、字体、间距、圆角、阴影、动效、背景效果。
- 所有领域页面只使用设计令牌，不直接写死颜色。
- 主题切换必须即时预览、可保存、可恢复，并尊重减少动效设置。
- 高级主题的 Canvas/粒子效果应可按设备性能降级。

## 5. 后续阶段

### Phase 0：基础盘点与稳定入口

- 完成启动器修复；
- 明确统一应用运行方式；
- 建立统一配置、数据目录和日志入口。

### Phase 1：统一协议与数据管理

- 固定 canonical schema；
- 设计版本迁移；
- 统一导入、导出、备份、恢复和冲突处理。

### Phase 2：统一应用壳与主题桥接

- 将导航、主题、语言、通知和设置抽到统一壳；
- 让 plan-helper、to-dos 逐步进入同一工作区。

### Phase 3：功能融合

- 计划任务自动生成待办；
- 待办完成可产生时间记录；
- 时间记录反向更新计划进度；
- 形成今日工作台、专注模式和复盘视图。

### Phase 4：现代化体验与多语言

- 完善响应式布局、快捷键、可访问性和动效降级；
- 建立中英文资源层，并为后续语言扩展保留命名空间。

## 6. 当前验收原则

- 用户从一个入口进入，不需要理解三个模块的内部边界。
- 旧数据可安全导入，导出后可恢复。
- 主题在统一应用中至少支持浅色、深色及 `time-helper` 的高级主题。
- 计划、待办、时间记录之间存在真实数据关联，不是三个页面的并列展示。
- 任意跨模块操作都有可追踪事件和可解释的失败反馈。
- 每个阶段有进展报告、测试证据和独立提交记录。
