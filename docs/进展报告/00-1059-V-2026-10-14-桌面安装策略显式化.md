# [完成] 桌面安装策略显式化

## 背景

本轮方向自检聚焦产品化交付链，而不是重复审查页面。当前 EffiLife 已具备 Windows NSIS、Linux deb/AppImage 与 macOS DMG 的发布配置，但尚未接入自动更新插件；因此现阶段升级方式是通过同一应用标识的新版安装包覆盖安装，用户数据仍由应用存储层和 `.efl` 存档负责迁移与恢复。

此前 Tauri NSIS 的“当前用户安装”是默认值，却没有写入项目配置。默认值一旦随工具链变化，可能导致安装权限、安装位置和升级行为发生漂移。

## 实施

- 在 `time-helper/desk/src-tauri/tauri.conf.json` 显式设置 NSIS `installMode: currentUser`。
- 显式关闭安装器语言选择弹窗，保持当前单语言安装器的确定性启动流程。
- 在 `scripts/check_release_config.py` 增加上述两项发布门禁，防止后续配置被无意删除或改变。
- 保持当前正式边界：未伪造自动更新能力；自动更新、签名和真实跨版本覆盖安装仍属于后续发布环境验收项。

## 验证

- `python scripts/check_release_config.py`：通过。
- `python scripts/check_mobile_release_config.py`：通过。
- `python -m pytest -q tests/test_release_metadata.py tests/test_ci_workflow.py tests/test_mobile_release_config.py`：26 passed。
- `python -m pytest -q`：1190 passed，1 个既有 ZIP 重复条目告警（测试专门覆盖该拒绝场景）。
- `npm run build`（`time-helper/desk`）：通过。

## 结论

桌面安装器的权限策略现在是显式、可审查、可被 CI 阻断的。该改动不改变数据协议、不改变应用数据目录，也不把开发启动器冒充成正式安装包。后续真正发布前仍需使用旧版与新版安装包在 Windows runner 上完成覆盖升级及数据保留验收。
