# 启动器配套服务失败处理

**文档性质**：临时实施报告  
**创建时间**：2026-09-25（Asia/Shanghai）  
**创建作者**：Codex  
**触发原因**：检查统一启动器偶发不可用的失败路径。

## 1. 发现的问题

统一工作台启动前会拉起 plan-helper API 配套服务。若 Python 解释器、工作目录或命令不可用，原逻辑会让 `Popen` 异常直接冒泡，启动器缺少明确提示，也不会执行已启动配套进程的清理。

## 2. 本次修复

- 为配套服务启动增加 `OSError` 处理。
- 启动失败时输出可读错误，并清理本轮已经成功启动的配套进程。
- 保持已由用户提前启动的外部服务不受影响。
- 增加回归测试，验证失败返回 `None` 且不会误终止外部进程。

## 3. 验证

- `python -m pytest -q --disable-warnings --maxfail=1`：`26 passed`。
- `python -m py_compile launcher/start.py`：通过。
- `git diff --check`：通过。

## 4. 后续

可继续增加启动器的日志文件和端口冲突诊断，但当前失败路径已不会无提示地中断统一入口。
