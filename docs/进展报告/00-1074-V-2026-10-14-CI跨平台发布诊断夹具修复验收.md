# CI 跨平台发布诊断夹具修复验收

日期：2026-10-14  
阶段：0  
类型：V（验证与验收）

## 问题

GitHub Actions 的 Ubuntu `EffiLife CI` 在全量 Python 测试步骤持续失败，而 Windows 本地回归通过。定位发现，Android 签名工具测试固定创建 Windows 后缀文件，POSIX 下生产诊断逻辑无法识别，造成跨平台测试误报。

## 修复

测试根据 `launcher.os.name` 创建平台正确的 Android 工具夹具，并用实际生成的文件名断言。生产代码未被迫放宽工具识别规则，避免把错误命名的工具误判为可用。

## 验证

- Windows 本地全量回归：修复前后均通过。
- POSIX 命名模拟：覆盖到此前失败的签名诊断测试。
- 前端构建和发布配置不受影响。
- 推送后继续观察真实 GitHub Actions CI 结果，确认 Ubuntu runner 不再在该测试失败。

## 边界

Windows 正式签名证书、Android 正式 keystore 仍属于受控发布环境配置；本修复不改变其“未配置即不具备正式发布资格”的状态。
