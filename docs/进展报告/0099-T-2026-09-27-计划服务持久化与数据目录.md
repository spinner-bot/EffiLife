# 0099-T-2026-09-27 计划服务持久化与数据目录

## 问题

Plan Helper Web API 之前只更新进程内 `Plan.registry`。创建、编辑或删除计划后，如果服务重启而未显式导出，变更可能丢失；这不满足统一软件的数据可靠性要求，也不利于未来 sidecar 运行时。

## 处理

- Web 服务支持可选 `--data-dir`，并在启动时创建运行时目录结构。
- 启动时自动加载已有 `data/system/registry/registry.json`。
- POST、PUT、DELETE 成功写操作在返回成功前统一保存注册表。
- 保存失败转换为明确的 HTTP 500 业务响应，避免报告虚假的成功状态。
- 未指定数据目录时保留原有开发工作目录行为。

## 数据语义

持久化仍使用原有 `Plan.save_registry()`，没有重写 `head/main/log`，没有改变软删除槽位、日志引用或嵌套组结构。

## 验证

- 新增临时目录回归测试：写入计划、清空内存、重新加载并验证任务内容。
- 相关服务测试：2 passed。
- `py_compile` 和 `git diff --check`：通过。
