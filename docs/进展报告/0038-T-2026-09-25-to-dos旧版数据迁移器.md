# to-dos 旧版数据迁移器

**文档性质**：临时实施报告  
**创建时间**：2026-09-25（Asia/Shanghai）  
**创建作者**：Codex  
**触发原因**：统一数据管理需要接收历史 to-dos 导出数据，同时避免迁移过程直接改写现有数据。

## 1. 本次目标

- 为旧版 to-dos JSON 增加无副作用的迁移入口。
- 同时接受 `{version, todos, categories}` 包装对象、原始任务数组和 JSON 字符串。
- 通过 `TodoAdapter` 生成统一任务结构，保留高级字段、子任务和关联引用。
- 为严格导入和预检导入分别提供可预测的错误策略。

## 2. 实施结果

- 新增 `common/migrations/todos.py`：提供 `migrate_legacy_todos` 和 `TodoMigrationError`。
- 新增 `common/migrations/__init__.py`：集中暴露迁移入口。
- 严格模式遇到非法任务时整体失败；宽松模式跳过非法项并返回 `warnings`。
- 迁移器不读写磁盘、不覆盖现有数据，实际导入由上层统一存档流程负责。
- 新增设计依据：`docs/设计方案/0016-to-dos旧版导出迁移方案.md`。

## 3. 验证

- `python -m pytest -q --disable-warnings --maxfail=1`：`25 passed`。
- `python -m py_compile common/migrations/todos.py common/migrations/__init__.py`：通过。
- 覆盖包装输入、裸数组输入、任务字段保留、严格失败和宽松警告路径。

## 4. 风险与后续

- 当前迁移器只负责内存转换，尚未接入前端 `.efl` 导入按钮；这样可以先稳定数据契约，再接入界面流程。
- 后续应在统一导入流程中增加迁移预览、重复任务策略和用户确认，并记录原始来源版本。
