# 0152-T-2026-09-27 事件计划导入缓存对称落地

## 实现

- 导入 `.efl` 时，只要包含有效事件计划快照，就先写入 IndexedDB `PLAN_HELPER_SNAPSHOT`。
- 桌面端 PH 服务不可用时，导入的数据不会因服务写回失败而丢失；服务恢复后仍可继续同步。
- 移动端既有本地写入路径保持兼容，服务端写回协议不变。
- 本地快照写入失败会进入导入 warning，不影响其他数据的原子回滚流程。

- `npm run build`（`time-helper/desk`）：通过，`1863 modules transformed`。
- `git diff --check`：通过。

## 数据边界

导入仍保持 `head/main/log` 原始快照，包括嵌套组、软删除槽位和日志；本次只补充缓存落盘时机。
