# 0169-T-2026-09-28 启动器进程树清理增强

## 1. 发现

统一启动器通过 `npm.cmd` 启动 Vite 时，launcher 只持有 npm 外层进程。Windows 下直接终止外层 PID 可能留下由 npm 派生的 Node/Vite 子进程，表现为开发端口仍被占用、下一次启动失败或误复用旧服务。

## 2. 调整

- 前端主进程和 plan-helper companion 均使用 launcher 专属进程组/会话启动。
- Windows 退出时按 launcher 持有的 PID 使用 `taskkill /T /F` 回收该进程树；失败时保留普通 terminate 回退。
- POSIX 使用独立 session，沿用现有 terminate 路径，避免影响启动器之外的服务。
- 增加启动器进程组配置回归测试。

## 3. 边界

- 只清理由当前 launcher 创建并持有的 PID，不扫描或终止其他项目的服务。
- 已运行且被复用的前端仍不由当前 launcher 终止；launcher 只监测其退出并清理自己启动的 companion。
- 本次不改变正式 Tauri sidecar 的生命周期逻辑，仍需在具备 Rust/Cargo 的发布环境完成安装包验证。

## 4. 验证

- `python -m pytest -q tests/test_launcher.py`：预期覆盖进程组配置及既有 9 个启动器行为测试。
- `python -m py_compile launcher/start.py`：应通过。
