# 启动器稳定性修复

**文档性质**：临时实施报告

**创建时间**：2026-09-25（Asia/Shanghai）

**创建作者**：Codex

**触发原因**：统一启动器在 Windows 环境下存在启动不稳定、重复安装依赖、无法正确打开 plan-helper、Node/Python 路径依赖过强等问题。该问题阻碍三个模块进一步统一入口。

## 1. 本次目标

- 让 Windows 启动过程不依赖 `shell=True` 的不稳定参数转发；
- 仅在前端依赖不存在时执行 `npm install`；
- 使用真实 HTTP 就绪检测，而不是依赖某一种终端输出格式；
- 正确打开 Vite 和 Python Web 服务；
- 改善 Node.js 路径和 Python 启动脚本的可用性；
- 不修改已有的 `time-helper/desk/package-lock.json`。

## 2. 已完成变更

### `launcher/start.py`

- 增加 Node/npm 探测与 `EFFILIFE_NODE_DIR` 环境变量支持；
- 统一构造子进程环境变量；
- 使用 `shell=False` 启动命令；
- 只有目标目录没有 `node_modules` 时才运行 `npm install`；
- 用后台输出线程转发子进程日志；
- 用 HTTP 轮询确认服务已启动，再打开浏览器；
- 兼容 `localhost` 和 `127.0.0.1` 类型服务地址；
- 处理启动器自身的 EOF 和 Ctrl+C；
- 改善服务提前退出和超时提示。

### `launcher/start.bat`

- 优先使用 Windows `py -3` 启动 Python；
- 没有 `py` 时回退到 `python`。

## 3. 验证

已执行：

```text
python -m py_compile launcher/start.py
python -c "import launcher.start ..."
git diff --check
```

结果：通过。当前环境探测到：

```text
Node v20.18.0
npm 10.8.2
```

并确认 npm 命令可在 `shell=False` 下成功执行。
