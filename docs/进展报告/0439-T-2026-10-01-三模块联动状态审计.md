# 三模块联动状态审计

**文档性质**：阶段审计报告  
**创建时间**：2026-10-01（Asia/Shanghai）  
**创建者**：Codex

## 1. 核验范围

- TD 完成一个关联 PH 任务时，是否先更新 PH，再提交 TD 完成状态。
- PH 完成或删除任务时，是否同步关联 TD，并处理旧显示编号与内部编号。
- TD、PH、TH 产生工作区事件后，首页摘要、计划工作台和待办中心是否重新读取共享状态。
- TD 与 TH 时间记录之间的关联 ID 是否去重，并能在启动修复流程中清理失效链接。

## 2. 结果

- TD 的单项和批量完成流程会先调用 `completePlanTask`，成功后才完成 TD，避免两个模块状态分叉。
- PH 删除任务会通过 `unlinkTodosFromPlanTask` 清理内部 ID 和显示 ID 两类关联。
- `TaskCenterView`、`PlansHubView`、`HomeView` 均注册工作区刷新监听，并分别处理 `todos`、`plans`、`records`、`archive` 等来源。
- `TodoService.trackTime` 对时间记录 ID 去重，工作区修复逻辑会移除失效和重复关联。
- 归档、重命名、跨窗口刷新和深链接均已有对应契约测试。

## 3. 结论

当前统一应用的数据闭环满足 HOTL-1 对三个模块“协同但不混淆”的要求：PH 仍以完整 Plan 为核心，TD 仍以独立待办为核心，TH 负责时间记录与统计；联动通过显式关联字段和工作区事件完成。
