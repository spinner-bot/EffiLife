# 计划任务稳定引用接入

**文档性质**：临时实施报告
**创建时间**：2026-09-25（Asia/Shanghai）
**创建作者**：Codex

**依据**：`plan-helper/modules/plan.py`、`plan-helper/modules/api.py`、`docs/设计方案/0003-计划任务级关联方案.md`。

## 1. 已完成

- 统一待办模型新增 `related_plan_task_id`。
- to-dos Python 模型、创建接口、更新白名单和存储层同步支持该字段。
- common schema 与适配器支持该字段的双向转换。
- time-helper `PlanGateway` 新增计划任务读取接口。
- 待办中心支持：
  - 选择计划后加载 active 任务；
  - 以 `display_id · content` 展示任务；
  - 保存 `internal_id` 作为稳定引用；
  - 编辑时修改或清空计划任务关联；
  - 计划服务不可用时仍可使用普通待办功能。
- 新增适配器测试，验证计划级和任务级引用不会丢失。

## 2. 关键不变量

- `display_id` 只用于界面展示，不作为外键保存。
- `internal_id` 保存原始槽位引用，软删除后不会误绑定到新的显示编号。
- 待办不复制或重排 plan-helper 的 section、group、log 结构。
- 取消计划关联时同步清空任务级关联，避免产生孤立引用。

## 3. 验证

- 全项目 Python 测试：`16 passed`。
- common 与 to-dos 相关 Python 文件编译通过。
- Vite 生产构建通过：`1842 modules transformed`。
- `vue-tsc` 中未出现 `TaskCenterView`、`TodoService` 或 `PlanGateway` 新诊断。

## 4. 当前限制

- 计划任务选择依赖 plan-helper companion 服务可用。
- 待办列表暂未缓存所有关联任务的显示摘要，因此服务暂不可用时显示内部引用兜底值；这不会影响数据正确性。
- 还需要补充跨模块“完成待办是否同步完成计划任务”的明确业务规则，暂不自动同步，避免改变原始 plan-helper 语义。
