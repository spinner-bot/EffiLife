# 0179-T-2026-09-28 音频设置主存储迁移

## 1. 目标

统一数据层已经为音频设置预留 IndexedDB 存储，但 `AudioManager` 仍只读写 localStorage，导致存档恢复后的主数据不能可靠地成为运行时状态。

## 2. 调整

- 音频服务启动时先同步读取旧 localStorage，随后异步从 IndexedDB 水合设置。
- IndexedDB 没有数据时，将现有 localStorage 设置迁移到 IndexedDB。
- 设置写入同时保留 localStorage 兼容镜像，并写入 IndexedDB 主存储。
- 保留同步的 `getSettings`、`updateSettings` 和播放 API；增加 `whenReady()` 供应用启动流程等待。
- 使用设置版本计数，避免异步启动水合覆盖水合期间发生的用户修改。

- 完整 Python 回归：63 passed，9 warnings。
- 前端构建：当前环境未提供 npm/node 命令。
