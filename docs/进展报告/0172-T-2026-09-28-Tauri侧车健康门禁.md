# 0172-T-2026-09-28 Tauri 侧车健康门禁

## 1. 发现

正式 Tauri 桌面版此前只验证 Plan Helper sidecar 的进程 `spawn()` 是否成功。PyInstaller 程序随后崩溃、监听失败或端口上的服务不是 Plan Helper 时，应用仍可能进入统一工作台，形成计划功能的“假成功”状态。

## 2. 调整

- Plan Helper HTTP 服务新增 `/api/health` 端点，返回明确的 `service: plan-helper` 标识。
- Tauri release desktop 启动 sidecar 后，通过本地 HTTP 健康请求等待服务就绪，最多约 30 秒。
- 健康检查失败时主动杀死 sidecar 并让 Tauri setup 返回错误，阻止应用以不完整状态继续运行。
- 保留现有 stdout/stderr 消费和退出事件清理逻辑。
- 增加静态发布契约测试，锁定健康端点、检查请求和失败门禁。

## 3. 平台边界

- 仅在非 debug desktop 构建启用；移动端仍不启动 Python sidecar。
- 当前机器没有 Rust/Cargo，无法进行本机 Tauri 编译；Rust 编译与安装包验收仍由发布 runner 完成。

## 4. 验证

- `python -m pytest -q tests/test_sidecar_build.py`：应覆盖 sidecar 构建、退出清理和健康门禁契约。
- `npm run build`：前端构建不受 sidecar Rust 改动影响。
- 完整 Python 回归测试将在提交前执行。
