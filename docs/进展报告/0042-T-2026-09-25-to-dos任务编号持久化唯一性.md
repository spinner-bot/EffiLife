# to-dos 任务编号持久化唯一性

**文档性质**：临时实施报告  
**创建时间**：2026-09-25（Asia/Shanghai）  
**创建作者**：Codex  
**触发原因**：统一联动测试发现 to-dos 重启后可能重新生成当日 `0001`，导致任务引用错配。

## 1. 根因

原 ID 生成器只保存进程内的日期计数器。服务或 CLI 重启后计数器归零，而持久化任务仍可能使用相同日期序号。新任务会与旧任务 ID 冲突，后续按 ID 查询、记录时间或计划关联都会命中旧任务。

## 2. 修复

- 保留既有 `TODO-YYYYMMDD-XXXX` 格式。
- 创建任务时以持久化任务集合的 ID 为最终唯一性依据。
- 发现生成 ID 已存在时递增序列并重试，不改变用户可见的编号语义。
- 增加存储重载后的唯一性回归测试。

## 3. 验证

- `python -m pytest -q to-dos/test_id_generation.py`：`1 passed`。
- `python to-dos/test_api.py`：`36/36` 通过。
- `python -m pytest -q --disable-warnings --maxfail=1`：`26 passed`。

## 4. 影响

该修复直接保护 to-dos 与 plan-helper、time-helper 之间的稳定任务引用；历史重复 ID 不会自动重写，后续如发现历史冲突应由专门的数据修复/迁移流程处理。
