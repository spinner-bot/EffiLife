# 0180-T-2026-09-28 打卡数据主存储迁移

## 1. 目标

打卡数据已存在统一 IndexedDB 存储表，但运行时 `CheckinSystem` 仍只使用 localStorage，造成恢复后的打卡状态可能直到旧镜像被覆盖前都不可见。

## 2. 调整

- 启动时先保留同步 localStorage 数据，随后从 IndexedDB 水合主数据。
- IndexedDB 无数据且存在旧数据时执行一次迁移；全新用户不创建空的打卡记录。
- 打卡写入继续保留 localStorage 兼容镜像，同时写入 IndexedDB。
- 增加 `whenReady()`，应用启动在自动补打卡和事件检查前等待水合完成。
- 使用版本计数避免异步水合覆盖期间发生的同步打卡操作。

## 3. 验证

- 契约测试：7 passed（含存档主存储契约）。
- 完整 Python 回归：64 passed，9 warnings。
- 前端构建：当前环境未提供 npm/node 命令。
