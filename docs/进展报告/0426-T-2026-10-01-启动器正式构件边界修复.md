# 启动器正式构件边界修复

**文档性质**：临时实施报告  
**创建时间**：2026-10-01（Asia/Shanghai）  
**创建者**：Codex

## 1. 发现

启动器的二进制候选同时包含 `release` 和 `debug`。正式 `--packaged` 模式此前会按候选顺序尝试它们；当 release 构件缺失而 debug 构件存在时，可能错误地把调试程序当作正式程序启动。

## 2. 修复

- `time_helper_binary_paths()` 增加 `include_debug` 参数。
- 开发模式保留 release/debug 兼容查找。
- `--packaged` 模式严格只查找 release 二进制；缺失时才允许使用已构建的静态 `dist/index.html`，不回退到 npm 开发服务器或 debug 二进制。
- 增加正式模式拒绝 debug 构件的回归测试。

## 3. 验证

- `python -m pytest -q tests/test_launcher.py`：通过。
- 后续执行全量测试并推送后，由 GitHub CI 复核。
