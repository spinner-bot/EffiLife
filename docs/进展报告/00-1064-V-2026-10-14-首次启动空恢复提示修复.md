# [完成] 首次启动空恢复提示修复

## 问题

移动端归档真实冒烟发现：干净运行时进入设置页会出现“当前数据为空，是否恢复”的确认框。根因是首次迁移无业务数据时仍创建 `pre_migration_full` 空备份，设置页将其误认为可恢复数据。

## 修复

- 迁移前仍收集完整 localStorage 快照。
- 只有检测到实际业务 workspace key 时才创建 `pre_migration_full` 检查点。
- 引导完成、语言、下载路径、事件标记等运行时元数据不会触发空迁移备份。
- 保留有旧业务数据时的迁移前备份和失败保护逻辑。

## 验证

- 新增“干净迁移不创建空恢复检查点”契约测试。
- 移动 `.efl` 分享冒烟路径中的首次恢复弹窗由产品根因修复，不再依赖冒烟脚本吞掉弹窗。
- 相关迁移测试与全量回归将在提交前执行。

## 边界

本次修复只影响首次迁移备份判定，不改变 IndexedDB 数据结构、`.efl` 协议或已有用户数据。历史版本已经生成的空检查点不会自动删除，用户仍可在数据恢复页管理它们。
