# 统一存档纳入 plan-helper 原始快照

**文档性质**：临时实施报告
**创建时间**：2026-09-25（Asia/Shanghai）
**创建作者**：Codex

**依据**：`docs/设计方案/0004-统一存档纳入plan-helper原始快照.md`。

## 1. 已完成

- plan-helper 新增 `/api/data/export`，直接输出 registry 中的原始 `Plan.plan` 快照。
- plan-helper 新增 `/api/data/import`，在校验全部快照后原子替换 registry；失败时恢复原 registry。
- `.efl` 存档版本 `2.1` 新增 `planHelper`：
  - `available` 标识导出时计划服务是否可达；
  - `plans` 保存原始快照数组。
- time-helper 导出会读取 plan-helper companion；导出不完整时在存档结果和设置界面明确提示。
- time-helper 导入会恢复 plan-helper 原始快照，并展示部分恢复失败提示。
- 重置全部数据或计划数据时同步请求清空 plan-helper registry；重置记录/设置不会误清理事件计划。
- 增加根级回归测试，验证空槽位、嵌套 group、日志引用和 JSON 数组化后的时间字段均可恢复。

## 2. 保真说明

导出的是 `Plan.plan` 原始结构，而不是 `get_plan_full()` 的展示结构。因此 `main[].plan` 的 inactive 槽位、`main[].group` 的字符串区间键和 `log` 中的任务引用均保留。JSON 持久化会将 Python tuple 转为 JSON array，这是协议允许且测试覆盖的表示变化。

## 3. 验证

- 全项目 Python 测试：`17 passed`。
- plan-helper 和公共模块 Python 编译通过。
- 真实启动 plan-helper HTTP 服务，完成创建计划、原始导出、原始导入闭环：`HTTP_RAW_ARCHIVE=ok`。
- time-helper Vite 构建通过：`1842 modules transformed`。
- ArchiveService、PlanGateway、TaskCenterView 相关 `vue-tsc` 无新增诊断。

## 4. 当前限制

- 统一存档的完整性取决于导出时 plan-helper companion 是否可达；不可达时会明确警告而不是伪造完整备份。
- 尚未把公共 Python `.effilife.bundle` 与前端 `.efl` ZIP 合并为同一物理格式；当前前端存档通过 plan-helper API 携带同等原始数据，后续需要统一协议版本和迁移器。
