# 统一 `.efl` 物理协议落地

**文档性质**：临时实施报告
**创建时间**：2026-09-25（Asia/Shanghai）
**创建作者**：Codex

**依据**：`docs/设计方案/0005-统一efl物理存档协议.md`。

## 1. 已完成

- time-helper 新导出改为公共层约定的 ZIP 结构：
  - `manifest.json`
  - `data/app.json`
  - `data/records.json`
  - `data/todos.json`
  - `data/plan_helper.json`
  - `README.txt`
- manifest 使用 `effilife.bundle` 和 `1.0.0` 协议版本。
- 前端导入优先解析 manifest 数据集，并兼容公共层的通用 dataset 文件。
- 前端保留旧版 `archive.json` 导入路径，历史存档无需转换即可恢复。
- plan-helper 快照、待办、时间记录和应用配置在物理协议层完成统一。
- 导出时 plan-helper 不可用会明确提示，避免生成“看似完整、实际缺计划”的备份。
- 设置页进入“数据恢复”时主动加载状态，恢复列表不再依赖未调用的函数。

## 2. 兼容策略

- 新导出只生成 manifest 协议。
- 旧版存档只在导入时兼容，不继续产生第二种新格式。
- 对通用 bundle 中未被 time-helper 消费的数据集不做破坏性改写；领域数据由对应服务负责。

## 3. 验证

- 全项目 Python 测试：`17 passed`。
- plan-helper 原始快照 HTTP 导出/导入：`HTTP_RAW_ARCHIVE=ok`。
- Vite 生产构建通过：`1842 modules transformed`。
- ArchiveService、SettingsView 相关 `vue-tsc` 诊断已清零。
- Python 公共层 `read_bundle()` 已验证 manifest/dataset 协议。

## 4. 当前限制

- 前端无法消费公共层任意业务 dataset 的领域语义，只能恢复约定的 `app`、`records`、`todos`、`plan_helper` 数据集；未知数据集保留在包内但不在 UI 中展开。
- 完整 `vue-tsc` 仍有热力图、旧存储测试、Tauri FS 等历史类型债务，已与本轮改动隔离。
