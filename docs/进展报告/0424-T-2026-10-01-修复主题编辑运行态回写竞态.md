# 修复主题编辑运行态回写竞态

**文档性质**：临时实施报告  
**创建时间**：2026-10-01（Asia/Shanghai）  
**创建者**：Codex

## 1. 问题

主题编辑器已经移除显式“保存”按钮，设计为编辑时预览、退出时弹窗确认并持久化。但应用切回前台或其他工作区刷新发生时，运行态配置会重新从持久化层加载；这可能覆盖正在编辑的主题预览，使用户看到主题退出后恢复旧值。

## 2. 处理

- 主题编辑器存在未提交草稿时，工作区刷新不再覆盖 `savedThemeSnapshot`。
- 刷新覆盖 Pinia 运行态后，立即重新应用本地草稿，直到用户在退出弹窗中确认。
- 编辑器干净时，才同步外部主题到控件和持久化快照。
- 增加主题配置监听，覆盖应用级可见性刷新路径。
- 保持主题编辑流程不增加保存按钮；退出按钮仍是确认提交入口，取消则继续留在编辑器。

## 3. 验证

- `python -m pytest -q tests/test_theme_persistence_contract.py tests/test_settings_theme_i18n.py`：24 passed。
- `python -m pytest -q`：614 passed。
- 当前执行环境未提供 `node`/`npm`，本次无法重新执行前端构建；此前桌面端构建已通过。

## 4. 后续边界

本修复只处理主题编辑草稿与工作区刷新之间的运行态竞态，不改变主题数据结构、主题引擎或统一存档协议。
