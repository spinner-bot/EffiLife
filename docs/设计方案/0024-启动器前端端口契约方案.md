# 启动器前端端口契约方案

**文档性质**：实施设计方案  
**创建时间**：2026-09-25（Asia/Shanghai）  
**适用范围**：launcher 与 time-helper / to-dos Vite 开发服务

## 1. 问题

Vite 默认会在端口被占用时自动选择下一个端口，但启动器的健康检查和浏览器入口使用固定端口。这样可能出现等待错误服务、打开旧服务或把端口冲突误判为应用启动失败。

## 2. 决策

- 启动器传入 `--host 127.0.0.1 --strictPort`，端口冲突直接失败，不允许隐式换端口。
- 健康检查 URL 统一使用 `127.0.0.1`，避免 `localhost` 的 IPv4/IPv6 解析差异。
- 端口冲突沿用已有子进程输出和退出码反馈，用户可据此释放端口或调整配置。
- 生产构建和已编译桌面端路径不受该开发模式契约影响。
