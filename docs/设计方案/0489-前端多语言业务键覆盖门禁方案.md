# 0489 前端多语言业务键覆盖门禁方案

## 背景

统一应用壳的页面、服务和组件持续合并，翻译键会同时出现在 Vue 模板和 TypeScript 逻辑中。现有测试只验证部分引导和存档键，无法防止新功能只补了一个语言目录，最终在另一种语言下显示原始键名。

## 方案

新增静态契约测试：扫描 `time-helper/desk/src` 中使用字面量参数调用 `t()` 或 `translate()` 的业务代码，排除 i18n 实现本身，然后要求每个键同时存在于中文和英文主目录。动态拼接键不纳入静态集合，由对应功能测试负责验证；这避免把合法的动态分类键误判为缺失。

## 验收

- 覆盖 `.vue` 和 `.ts` 业务源文件。
- 同时检查 `zh-CN` 与 `en-US` catalog 区域，而不是只检查整份文件是否出现过键。
- 忽略 i18n 自身的 `t` 实现与动态键。
- 当前所有业务字面量键通过门禁，并保留双语扩展基础。
