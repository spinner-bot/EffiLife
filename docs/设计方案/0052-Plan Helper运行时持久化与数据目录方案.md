# Plan Helper 运行时持久化与数据目录方案

## 问题

Plan Helper 的 API 层使用内存中的 `Plan.registry` 工作。原有 Web 服务没有在启动时加载注册表，也没有在 HTTP 变更后保存注册表，服务重启可能丢失刚刚创建或编辑的计划。

## 决策

1. Web 服务启动时接收可选 `--data-dir`，将其作为运行时数据根目录；未指定时保持开发环境现有工作目录行为。
2. 启动时创建 `data/system/registry` 目录，并尝试加载注册表；没有注册表文件视为首次运行，不阻断服务。
3. 每个成功的 API 写操作完成后保存注册表。保存失败时向调用方返回明确的服务错误，避免界面显示“成功”但数据未落盘。
4. 保存动作只调用原有 `Plan.save_registry()`，不改变 `head/main/log`、软删除槽位、嵌套组或日志引用；编号重排仍由现有读取/显示层负责。
5. 该持久化层同时服务开发 companion 和未来受控 sidecar，为正式打包提供稳定的数据目录入口。

## 兼容性

- 旧的 `python web/server.py` 启动方式继续有效。
- 旧的 `plan-helper/data` 目录继续作为未传 `--data-dir` 时的默认数据位置。
- `--data-dir` 只改变文件根目录，不改变 HTTP API 契约。

## 验证

- 新增“写入后清空内存、重新加载仍可读”的回归测试。
- 执行 Plan Helper/Python 全量测试。
- 执行统一前端构建，确认 API 契约未被破坏。
