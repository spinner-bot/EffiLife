# 0402｜计划工作台彻底合并方案

## 设计决策

- **美学方向**：沿用 Linear 式工作台结构。首页入口不再让用户在“时间计划”和“事件计划”之间做二选一，而是先展示今天，再按信息密度向下展开长期计划与归档。
- **信息架构**：`/plans` 是唯一计划工作台；上半区承载记录与日计划，下半区承载事件计划和归档。旧的 `?mode=time`、事件列表及详情路由继续可用，作为兼容入口而不是新的顶层分裂。
- **组件边界**：日计划/记录继续由 `PlanView` 管理，增加嵌入模式；事件计划继续由 `PlansHubView` 管理。嵌入模式只移除重复的页面头部，不改变数据结构、编辑流程或 PH 兼容逻辑。
- **视觉层级**：合并页面使用连续的垂直工作流，不再使用两个并列的大入口卡片。事件计划区保留独立标题、创建动作和归档区，确保用户能够快速定位。
- **响应式策略**：桌面端使用宽工作台与三列事件计划卡片；移动端自动折叠为单列，日计划和事件计划按顺序滚动浏览。
- **动效与可访问性**：复用现有主题 token、焦点态和减少动画设置；嵌入模式不增加新的跳转动画，避免页面内重复过渡。

## 验收标准

1. 默认 `/plans` 不再显示“时间计划/事件计划”二选一入口卡片。
2. 默认 `/plans` 同时显示日记录工作台和事件计划列表/归档。
3. 创建、编辑、归档、恢复、详情及 `?mode=time` 旧入口行为不变。
4. `PlanView` 的嵌入模式不产生重复页面头部，且不会改变其数据读写逻辑。
5. 主页导航卡片悬停仅强化边框与焦点环，不能用填充色覆盖文字。
