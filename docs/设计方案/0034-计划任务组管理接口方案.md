# 计划任务组管理接口方案

**文档性质**：实施设计方案  
**创建时间**：2026-09-25（Asia/Shanghai）  
**适用范围**：plan-helper group 管理与统一计划工作台

## 1. 背景

计划 group 不是普通标签，而是 section 内连续任务的区间结构：完全包含的区间可以嵌套，交叉区间必须拒绝。统一工作台此前只能查看 group，无法创建、编辑或删除。

## 2. 决策

- 增加 `POST/PUT/DELETE /api/plans/{id}/sections/{section}/groups...` 接口，服务层统一调用 `Plan.add_group`、原始 group 字典和 `Plan.pur_group`。
- 新建 group 只接受原始任务槽位区间，服务端负责校验 `end > start`、标题非空和交叉冲突；失败时返回 409，不写入部分数据。
- 编辑只修改标题和说明，不改变区间键；删除只删除 group 元数据，不删除任务、不重排任务、不修改 log 引用。
- 统一工作台使用任务的稳定 `internal_index` 作为接口边界，同时显示用户可理解的任务显示编号。

## 3. 不变量

- `section.group` 的字符串区间键保持不变，嵌套关系可继续由区间推导。
- 软删除后显示编号可以重新计算，但 group 与 log 的内部引用不被重写。
