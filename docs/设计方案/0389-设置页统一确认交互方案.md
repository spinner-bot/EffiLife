# 0389 设置页统一确认交互方案

## 背景

统一工作台的计划、任务、记录和历史页面已经使用主题化确认对话框，但设置页仍保留浏览器原生 `confirm`。这会使存档导入、恢复、数据清理和主题离开等高风险操作产生两套视觉、语言和键盘交互。

## 决策

1. 设置页全部通过 `confirmService.requestConfirm()` 请求用户决定，确认组件仍由应用壳中的 `ConfirmHost` 统一渲染。
2. 数据清理、存档导入和备份恢复使用 `danger` 风格；主题未保存提示和导入成功后的刷新提示使用普通风格。
3. Tauri 存档导入的预览回调允许返回 `boolean | Promise<boolean>`，在读取并校验预览后等待统一对话框结果，再进入实际写入流程。
4. 确认服务只负责展示和返回决定，不直接承担存档、恢复或清理业务。

## 验收

- 设置页不再直接调用浏览器原生 `confirm`。
- 浏览器文件导入、Tauri 文件导入、旧待办导入、备份恢复、重置数据和主题离开均保持原有业务顺序。
- 中英文、主题令牌、Esc 和焦点行为继续由 `ConfirmHost` 统一提供。
