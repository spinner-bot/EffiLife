# 统一运行时能力与移动端归档边界

## 目的

统一桌面、浏览器测试环境和移动端对 plan-helper 的能力判断，避免移动端把桌面专用的 `127.0.0.1:8765` 当作可用服务。此方案只约束运行时连接能力，不改变 plan-helper 的原始数据结构、编号规则、嵌套组语义或删除语义。

## 运行时分类

| 运行时 | plan-helper 当前能力 | 行为 |
| --- | --- | --- |
| Tauri 桌面正式版 | sidecar | 允许请求本地 plan-helper，并由 Tauri 启动 sidecar |
| 浏览器 / 开发测试 | 外部 HTTP 服务 | 允许请求配置的 `VITE_PLAN_HELPER_ORIGIN`，默认 `127.0.0.1:8765` |
| Android / iOS | 当前未提供本地 plan-helper 运行时 | 不请求 localhost；界面与归档明确报告事件计划暂不可用 |

## 归档约定

`.efl` 仍然保留 `datasets/plan_helper.json`。移动端导出时写入 `available: false` 和原因字段，保证归档格式完整且不会伪造空计划。移动端导入包含事件计划快照时保留其他数据，同时报告 plan-helper 尚未接入；不得静默丢弃用户数据。

后续移动端支持应实现兼容原始 plan 模型的本地运行时或协议适配器，再将第三类能力提升为可用；不能通过给任务增加单一 group id 等方式简化模型。

## 验收

- 移动端不发起对 `127.0.0.1:8765` 的 plan-helper 请求。
- 桌面和浏览器测试行为保持不变。
- 归档结果显式表达 plan-helper 是否可用及原因。
- Python plan-helper 测试和前端生产构建通过。
