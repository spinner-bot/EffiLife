# 0493 HOTL1 计划创建首个行动落地方案

## 背景

统一计划工作台的创建弹窗仍只提交名称和日期，实际生成空 plan。虽然详情编辑器可以补录内容，但这与 PH“围绕一份有明确主题、可执行内容的完整计划表”的定位不符，也让首次使用者无法从创建动作直接开始推进。

## 决策

- 创建弹窗增加首个分组、首个任务和预计分钟数三个字段；名称、日期、分组和任务均为创建所需的最小内容。
- 沿用 `InitialPlanSection[]` 和既有 `/api/plans` 协议，桌面与移动端都写入同样的 section/task 结构。
- 创建成功后仍进入详情编辑器，后续可继续增加分组、任务、嵌套组、日志和待办关联。
- 日期打开弹窗时重置为当前日期；取消或重新打开时清理上次草稿。
- 不改变 PH 的任务编号、软删除槽位、嵌套分组或原始 plan 数据结构。

## 验证

- 静态契约测试确认创建请求携带首个 section/task，而不是空数组。
- 前端类型检查与生产构建通过。
