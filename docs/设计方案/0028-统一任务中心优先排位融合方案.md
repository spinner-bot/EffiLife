# 统一任务中心优先排位融合方案

**文档性质**：实施设计方案  
**创建时间**：2026-09-25（Asia/Shanghai）  
**适用范围**：统一任务中心与 to-dos 优先排位能力

## 1. 背景

to-dos 已有基于截止时间、开始时间、类别难度、整数排位级别、紧急和重要属性的优先排位算法。统一任务中心此前只保存部分字段并按更新时间展示，合并后用户无法看到或使用原有事件排序能力。

## 2. 决策

- 在前端新增纯函数适配层，等价实现 `to-dos/src/priority.py` 的输入语义和分数显示规则；不把计算结果持久化，避免时间流逝后出现陈旧分数。
- `priority_rank` 作为整数排位级别保留；`urgent`、`important` 独立保存。旧数据只有 `priority` 枚举时，由适配层临时推导两个布尔值，保证兼容。
- 新任务的 `start_time` 默认固化为 `created_at`；没有截止日期、时间无效或任务已过期时，分别返回 0 或 -1，不进行危险计算。
- 待办列表每 60 秒刷新计算时钟并按分数降序排列；同分时按更新时间降序。分数仅在条目右侧显示，展开详情显示完整数值。
- `EL` 压缩显示只用于紧凑列表；数据模型和详情仍保留原始整数分数语义。

## 3. 非目标

- 不重写 to-dos 原有 Python 算法。
- 不用单个分类 ID 替换 plan-helper 的嵌套组结构。
- 不将实时分数写回统一存档，导入导出继续保留计算所需的原始字段。

## 4. 后续

后续可将刷新间隔接入设置项，并把分类分数用于任务中心的分类分组与侧栏折叠；这些变化不得改变单任务算法和旧数据兼容策略。
