# 0365 统一存档双向关联修复方案

## 背景

统一存档同时保存时间记录和待办。时间记录使用 `todo_id` 指向待办，待办使用 `related_time_record_ids` 反向索引时间记录。历史版本或外部导入数据可能只保留其中一侧，单向清理会导致导入后详情页和待办页显示不一致。

## 决策

1. 导入时先收集有效记录 ID，以及记录上的 `todo_id -> record ID` 反向信息。
2. 对每个待办过滤不存在的记录 ID，并合并记录侧反向发现的 ID。
3. 使用去重后的稳定顺序写回 `related_time_record_ids`；没有有效关联时保持 `undefined`。
4. 不修改记录侧的原始 `todo_id`，避免无依据地破坏用户历史数据。
5. 继续报告修复数量，供导入预览和完成提示使用。

## 验证标准

- 只存在待办侧的无效 ID 会被移除。
- 只存在记录侧的有效 `todo_id` 会补齐待办反向索引。
- 已经双向一致的数据保持不变。
- 统一存档导入数据协议不变。
