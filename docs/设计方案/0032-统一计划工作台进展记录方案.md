# 统一计划工作台进展记录方案

**文档性质**：实施设计方案  
**创建时间**：2026-09-25（Asia/Shanghai）  
**适用范围**：统一计划中心与 plan-helper log

## 1. 背景

plan-helper 的 `log` 是计划数据的一等组成部分，且 `plan` 字段必须继续保存稳定的内部任务编号，以支持软删除后的显示编号映射。统一计划工作台此前只显示任务完成状态，没有 log 的创建和查看入口。

## 2. 决策

- 通过已有 `/api/plans/{id}/logs` 接口写入，不直接改写 plan JSON，也不在前端复制日志数据。
- 用户界面只要求选择整体进展或具体任务、填写计划日和自然语言内容；时间使用后端的 `acc` 当前时刻语义，隐藏 `99` 等底层无精确度标识。
- 日志列表直接显示服务返回的 `index/day/plan/time/content`，不把 `plan` 解析成单个组 ID，保留嵌套组和软删除引用能力。
- 任务行提供快捷“记录”入口，进入编辑器后可修改关联任务；刷新计划详情以获得服务端最新 log。

## 3. 兼容性与边界

旧日志只读显示；本次不提供硬删除日志、不重排内部任务编号、不修改 `plan.py` 的底层时间解析逻辑。
