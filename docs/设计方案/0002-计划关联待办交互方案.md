# 计划关联待办交互方案

**文档性质**：前端设计方案（实施前置）
**创建时间**：2026-09-25（Asia/Shanghai）
**适用范围**：统一待办中心与 plan-helper 计划关联

## 1. 目标

让事件导向的待办可以引用时间导向之外的 plan-helper 事件计划，同时严格保留 plan-helper 的原始结构：计划 ID、section、显示任务编号、内部任务编号、嵌套 group 和 log 不在待办侧重新建模。

## 2. 交互方向

- 在创建和编辑待办表单中提供“关联计划”选择项。
- 计划列表不可用或 plan-helper 服务未启动时，选择项显示明确的“暂不可用”状态，不阻断普通待办创建。
- 关联值保存为稳定的 plan ID，不保存名称作为外键；计划重命名不会使关联失效。
- 待办列表只展示计划名称摘要，详细 section/task 结构在后续计划详情页查看。
- 不把 time-helper 的时间类别当作 plan-helper 计划，两个领域通过显式适配器连接。

## 3. 服务边界

- 前端通过 `PlanGateway` 访问 plan-helper 的只读 API：`/api/plans`。
- 统一启动器在启动主工作台时托管 plan-helper 兼容服务，主工作台关闭时回收该子进程。
- API 不可达时使用空目录并保留原始用户输入，错误只作为非阻断状态反馈。

## 4. 主题与状态

选择器、加载态、空态、错误态和聚焦态均使用 time-helper 主题令牌；不引入 plan-helper 独立颜色体系。选择器属于辅助字段，视觉权重低于待办标题。

## 5. 验收条件

- 可从统一工作台读取 plan-helper 计划摘要。
- 待办保存的 `related_plan_id` 为稳定 ID，更新时不丢失其他字段。
- plan-helper 未运行时待办基础 CRUD 仍可用。
- 计划原始嵌套结构在适配层测试中得到保留，不被扁平化。
