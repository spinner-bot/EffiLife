# 0082 事件计划导出缓存快照兜底

## 问题

统一工作台导出 `.efl` 时，如果 PH 服务暂时不可连接，原实现会将 `plan_helper` 标记为不可用并导出空计划列表。即使 IndexedDB 中存在最近一次成功同步的原始快照，也会造成事件计划静默缺失。

## 决策

1. 每次成功获取 PH 原始导出后继续写入 `PLAN_HELPER_SNAPSHOT`。
2. PH 服务请求失败时，统一导出尝试读取该快照；有快照则纳入 `.efl`，并标记 `stale: true`。
3. 导出结果通过 warning 明确提示“使用缓存快照”，不伪装成实时数据。
4. 没有缓存或本地存储不可用时，保持原有不可用结果和警告行为。
5. 不改变 PH 原始数据结构、服务端写回协议和移动端编辑逻辑。

## 验收

- 在线导出仍使用服务端最新快照。
- 服务离线但存在本地快照时，`.efl` 包含该快照并返回陈旧警告。
- 无服务且无缓存时，导出明确提示事件计划未包含。
- 前端类型检查与生产构建通过。
