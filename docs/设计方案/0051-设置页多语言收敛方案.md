# 设置页多语言收敛方案

## 背景

统一工作台已经具备 `zh-CN` / `en-US` 基础，但设置页仍保留大量历史中文文案。切换语言后，用户会在导航、数据管理、主题和反馈等区域看到中英混排。

## 设计决策

1. 设置页继续复用现有 `useI18n()` 与集中式语言目录，不在组件内建立第二套翻译机制。
2. 先收敛用户可见的主导航、设置分类、保存/返回操作、数据管理入口和主题分类；注释与内部变量不纳入翻译范围。
3. 主题选择继续通过现有 `theme.name.*`、`theme.desc.*`、`theme.category.*` 键生成显示文本，保留完整主题架构和主题类型值不变。
4. 数据导入、导出、恢复和重置的提示使用稳定的翻译键；错误对象中的技术信息保留，前置说明使用本地化文案。
5. 本阶段不改变设置数据结构、存档格式、路由或任何业务行为，只替换显示层文案。

## 视觉与交互约束

- 保持现有设置页的分层布局、主题预览和返回历史行为。
- 所有已有弹窗仍保留可见关闭路径与 Esc 行为；本次不引入新的阻塞式交互。
- 翻译后的长文案允许自然换行，不通过缩小字号解决溢出。

## 验证

- TypeScript/Vue 生产构建。
- 根目录 Python 回归测试。
- `git diff --check`。
- 检查设置页中文硬编码仅剩注释或业务数据默认值。
