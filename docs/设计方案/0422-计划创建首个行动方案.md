# 计划创建首个行动方案

## 背景

计划服务已经支持在创建请求中携带 `sections`，但统一工作台创建弹窗只提交名称和日期。用户创建后得到空计划，必须再次寻找分组和任务入口才能开始使用。

## 方案

- 创建弹窗新增“首个分组”和“首个任务”两个必填字段，以及预计分钟数。
- 创建请求通过现有 `InitialPlanSection[]` 传入一个分组和一个任务，不新增协议字段。
- 创建成功后仍进入详情页；详情页继续负责追加分组、任务、嵌套组、日志和待办关联。
- 移动端复用同一请求结构，由既有本地快照转换逻辑生成相同的 section/task 形状。
- 取消创建或重新打开弹窗时清理草稿，日期继续默认当前日期。

## 不变约束

- 不修改 plan-helper 原始数据结构、任务编号、嵌套组关系或软删除语义。
- 不把首个任务简化为单独的组 ID；仍由 section 包含任务，保持可嵌套模型。
- 不改变已有详情编辑入口和历史计划读取兼容性。
