# PH 执行日志稳定引用方案

## 范围

只规范“新建日志”写入，不迁移或重写历史日志。历史日志可能来自旧版本或原始 `Plan` API，必须原样保留。

## 规则

- `base` 日志保持 `base`。
- 任务日志的输入可以是内部编号或当前显示编号；API 在写入前通过当前活动任务投影解析为稳定 `internal_id`。
- 显示编号因软删除而变化时，后续通过显示编号新建的日志指向当时显示位置对应的活动任务；已存在的历史日志不受影响。
- API 响应保留调用者传入的 `task_id`，另提供 `resolved_task_id`，方便前端或同步层明确实际引用。
- 无法解析的任务编号直接返回错误，不写入半成品日志。

这样保留 PH 原始数据的历史兼容性，同时让新产生的跨模块执行记录具备稳定引用。
