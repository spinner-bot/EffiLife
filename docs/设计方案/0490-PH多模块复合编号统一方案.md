# 0490 PH 多模块复合编号统一方案

## 背景

PH 核心 `Plan.num2char()` 使用 Excel 风格的字母序列，支持 `A..Z、AA、AB...`。部分 API 和辅助模块仍通过单字符 ASCII 偏移生成 section 字母，超过 26 个模块后会产生非法字符，导致计划条目标识和分析结果不一致。

## 方案

所有从 section 数字生成展示字母的位置统一调用 `Plan.num2char()`：API section/task/full-plan 响应、数据完整性检查、文本渲染和模板冲突分析均复用同一底层规则。保留任务的内部下标、软删除和嵌套分组逻辑不变。

## 验收

- 第 0、25、26、27 个模块分别生成 `A、Z、AA、AB`。
- API 的 section、task、full-plan 响应使用同一字母规则。
- 文本输出、数据校验和模板分析不再生成单字符越界结果。
- 现有嵌套分组、软删除压缩显示编号和日志引用测试继续通过。
