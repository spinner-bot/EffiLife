# 0368 跨运行时存档规范化序列化

## 背景

统一 `.efl` 协议由 Python 公共层和 time-helper 前端共同读写。公共层在计算数据集 SHA-256 前使用 `sort_keys=True`；前端如果直接使用 `JSON.stringify`，对象的插入顺序差异会使相同数据产生不同摘要。

## 决策

前端导出数据集统一经过 `canonicalJson()`：递归排序对象键，保留数组顺序，并使用两格缩进和 UTF-8 输出。该规则与 `common.data_exchange._json_bytes()` 对齐。

不改变业务数据结构，也不排序数组；数组顺序属于计划、记录和待办数据的语义。旧版 `archive.json` 导入兼容逻辑保持不变。

## 验收

- 五个规范数据集均由 `canonicalJson()` 序列化后写入 ZIP；
- manifest 中的摘要和实际数据字节使用同一字符串来源；
- Python 公共层可验证前端导出的数据集摘要；
- 前端类型检查、生产构建及现有全量测试通过。
