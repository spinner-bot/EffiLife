# 计划详情编辑器表单语义方案

## 背景

统一计划工作区的创建计划已经使用原生表单，但详情页中的计划信息、进度日志、分区、任务和嵌套组编辑器仍依赖按钮点击。这样会让键盘和移动端软键盘在同一页面内出现不一致的提交行为，也容易在后续增加字段时遗漏回车提交路径。

## 决策

将详情页的五类编辑器分别改为原生表单：

- 计划元数据：`@submit.prevent="savePlanMeta"`；
- 进度日志：`@submit.prevent="saveLog"`；
- 分区编辑：`@submit.prevent="saveSection"`；
- 任务编辑：`@submit.prevent="saveTask"`；
- 嵌套组编辑：`@submit.prevent="saveGroup"`。

编辑器内的取消、返回和模式操作明确使用 `type="button"`，保存/提交按钮使用 `type="submit"`。移除日志输入框的独立回车监听，避免出现重复提交入口。

## 保持不变

本次不调整 plan-helper 数据结构、嵌套组语义、任务显示编号、软删除/重排逻辑、存储服务或权限判断；只统一视图层提交语义。

## 验证

- 增加静态契约，确认五个编辑器各自只有一个提交入口；
- 执行 Python 全量测试；
- 执行桌面端 Vite 生产构建。
