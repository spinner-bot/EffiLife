# 引导流程移除旧日历死代码方案

## 背景

`GuideManager.ts` 已在文件后半段把 `MAIN_GUIDE.steps` 替换为统一工作台步骤，但文件前半段仍保存旧的日历、旧管理标签和序号导航引导。虽然当前不会执行，却会误导维护者，并可能在未来重构时重新暴露已移除的日历入口。

## 方案

- 删除旧引导中的完整日历步骤和相关文案；
- 保留当前统一工作台引导：计划、待办、计划内时间工作台、设置；
- 其余历史管理步骤暂不影响运行，待后续引导重构时统一移除；
- 保留 `GuideConfig`、状态存储、备份恢复和引导控制器接口不变；
- 不删除打卡热力图等统计可视化，它们不是独立日历功能；
- 增加源码契约，禁止旧日历导航步骤和序号导航选择器回归。

## 验收

- 引导相关测试通过；
- 前端生产构建通过；
- 全量 Python 测试通过；
- 保持用户已有 `time-helper/desk/package-lock.json` 不变。
