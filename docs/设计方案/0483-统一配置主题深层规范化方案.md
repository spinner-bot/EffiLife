# 统一配置主题深层规范化方案

## 背景

统一存档和历史迁移允许配置来自多个版本。当前 `DataService.loadConfig()` 仅对顶层配置做浅层合并；当旧配置只保存了主题类型，或只保存某个主题的部分参数时，读取结果可能缺少其它主题子配置，设置页和主题引擎需要各自兜底，增加重启后状态不一致的风险。

## 方案

- 在数据服务层增加唯一的配置规范化函数；
- 顶层配置、主题对象以及 solid/gradient/glass/neon 四组可编辑参数分别与默认值深层合并；
- 保留高级主题的 `type`，不强行覆盖主题注册表中的预设；
- IndexedDB、localStorage 两条读取路径统一经过同一规范化函数；
- 保存接口保持现有 `.efl`、备份和跨窗口通知行为不变。

## 验收

- 部分主题配置读取后具备完整可编辑字段；
- 高级主题类型仍被保留；
- 两种存储回退路径复用同一规范化逻辑；
- 增加静态契约测试并通过全量测试和前端构建；
- 不改变用户已有配置的有效值，不修改 `package-lock.json`。
