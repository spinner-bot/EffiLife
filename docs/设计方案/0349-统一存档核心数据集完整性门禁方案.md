# 统一存档核心数据集完整性门禁方案

## 问题

规范 `.efl` 存档由应用、时间记录、待办、待办分类和 plan-helper 快照五个核心数据集组成。前端过去只验证 manifest 中声明的文件，部分包可能通过校验后以空值覆盖当前数据。

## 方案

解析规范 bundle 时要求 manifest 同时声明：`app`、`records`、`todos`、`todo_categories`、`plan_helper`。缺失任一数据集，在读取和写入前立即拒绝，并通过 i18n 返回缺失名称。

旧版单文件 `archive.json` 不属于规范 bundle，继续走现有兼容解析路径，不改变历史数据迁移能力。

## 安全边界

门禁发生在数据集读取和 `processArchiveData` 之前，因此拒绝不可能触发清空、恢复或工作区变更事件。
