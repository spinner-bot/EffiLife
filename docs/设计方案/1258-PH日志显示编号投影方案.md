# PH 日志显示编号投影方案

## 目标

软删除任务后，任务列表使用活动任务重新编号；执行日志也应在界面上使用同一套当前显示编号，但不能改写日志中保存的稳定引用。

## 方案

- 后端和原始 JSON 继续保存日志的 `plan` 内部编号。
- 计划详情前端根据当前活动任务列表，将日志内部编号映射到对应的 `display_id`。
- 若日志引用的任务已被删除、归档数据缺少任务，或日志是 `base`，则直接显示原始引用。
- 映射只存在于渲染投影，不回写 PH 数据，也不影响 TD 关联和深链接使用的内部编号。

## 结果

任务列表、日志列表和新建日志的解析规则分别承担显示、历史保存和写入职责，避免“为了显示连续编号而重写历史数据”。
