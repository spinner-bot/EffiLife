# 统一工作区记录与存档变更通知方案

## 目标

补齐工作区变更事件覆盖范围，使搜索和后续统计组件能够感知时间记录以及成功完成的存档导入。

## 写入边界

- `app` Pinia store 在 `DataService` 完成新增、编辑、删除并刷新状态后发布 `records`；
- `ArchiveService` 仅在完整恢复流程成功（包括可能的计划快照恢复和警告汇总）后发布 `archive`；
- 校验失败、写入失败或回滚失败不会发布成功事件；
- 预览存档不会发布事件，因为预览只读。

## 设计理由

把通知放在持久化成功之后，可以让订阅方把事件视为“可重新读取”的信号，而不是直接传输可能过期的数据。统一搜索无需了解 IndexedDB、localStorage 或 plan-helper API 的具体实现。

## 后续扩展

首页统计、最近活动和跨窗口同步可以复用相同事件名称；若需要跨浏览器窗口同步，再增加 BroadcastChannel 适配，不改变现有订阅接口。
