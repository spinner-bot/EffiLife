# 统一任务中心子任务详情方案

**文档性质**：统一任务域交互方案  
**创建时间**：2026-09-25（Asia/Shanghai）  
**适用范围**：time-helper 统一 TaskCenter 与 to-dos 原始任务模型

## 1. 目标

让 to-dos 中已经存在的子任务能力在统一工作台可见、可添加、可完成和可删除，避免导入后数据只能保存却无法使用。

## 2. 交互决策

- 每个任务卡提供“展开详情”入口；详情区域展示子任务进度和子任务列表。
- 子任务完成使用独立圆形复选按钮，不改变父任务状态；父任务仍通过原有完成入口完成。
- 添加子任务使用详情区内的小表单，提交成功后清空输入并保留详情展开状态。
- 删除子任务需要确认，完成/删除期间锁定对应操作，失败保留输入并显示错误。
- 空子任务提供明确添加提示；没有强制把所有任务卡默认展开，保持列表扫描效率。

## 3. 数据约束

- 使用原始 `TodoSubtask.id`，不重建或重新编号。
- 所有变更通过统一 `TodoService.update` 写回完整 `subtasks` 数组，保留其它字段。
- 不在本阶段改变 to-dos 的递归生成、优先级计算或后端事件语义。

## 4. 验收

- 导入含子任务的旧数据后能够展示。
- 能新增、切换完成状态和删除子任务。
- 刷新页面后状态保持，统一存档仍能完整导出。
