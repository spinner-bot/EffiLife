# 计划任务深链双编号解析方案

## 背景

plan-helper 同时存在稳定的内部任务 ID 和面向用户的显示 ID。统一待办通常保存内部 ID，但历史数据、手工链接或旧版本数据可能保存显示 ID。计划详情页当前只按内部 ID 处理 `task` 查询参数，导致深链只能打开计划，不能定位任务。

## 决策

- 解析计划深链时同时匹配 `task.internal_id` 和 `task.display_id`；
- 匹配成功后统一使用当前任务的内部 ID 作为 DOM 定位和高亮标识；
- 不把显示 ID 写回底层数据，不改变任务编号生成、软删除重排或嵌套组语义；
- 保持无匹配查询参数的现有行为。

## 验证

- 增加静态契约，确认双编号匹配并以内部 ID 定位；
- 执行 Python 全量测试；
- 执行桌面端 Vite 生产构建。
