# 旧版存档缺失记录字段保留方案

- 状态：[已实现并验证]
- 创建时间：2026-09-29
- 执行者：Codex
- 关联目标：统一存档导入的向后兼容与数据安全

## 1. 问题

旧版单文件 `archive.json` 可能没有 `records` 字段。当前解析流程把缺失字段归一化为 `{}`，而导入流程把 `{}` 视为“明确的空记录集”并清空当前记录，导致导入旧存档时误删本地数据。

## 2. 方案

- 对旧版存档区分字段缺失和字段明确为空：
  - `records` 为 `undefined`：不写入、不清空当前记录；
  - `records` 为 `{}`：按明确空数据集处理并清空当前记录；
  - `records` 为非法值：继续拒绝导入。
- 规范化待办关联时，缺失记录字段使用临时空映射校验，但不把该映射写回 `ArchiveData`。
- 将 `ArchiveData.records` 标记为可选，并让预览统计对缺失字段显示为 0。
- canonical `.efl` 仍要求 `records` 数据集存在，不改变新协议门禁。

## 3. 约束

- 不改变显式空记录集的替换语义。
- 不改变导入失败时的完整回滚机制。
- 不改变旧版其他字段的兼容处理。

## 4. 验收

- 旧版缺失 `records` 时导入流程不会进入记录清空分支。
- 旧版显式 `{}` 仍进入记录清空分支。
- 新版 canonical 存档仍必须包含 `records`。
