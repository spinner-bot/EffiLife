# 统一存档冲突预览方案

## 1. 目标与美学方向

采用 Linear 风格的“高密度、低噪声确认面板”：让用户在一次确认中同时看懂存档内容、本机将被覆盖的数据规模，以及校验和关联修复状态。重点是信息分组和风险显著性，不增加装饰性卡片。

## 2. 信息结构

导入确认文本按以下顺序组织：

1. 存档内容：计划、待办、时间记录、分类及关联修复数量。
2. 本机覆盖范围：当前本机对应数据数量。导入协议为整体替换，因此使用“覆盖”措辞，不伪装成合并。
3. 导出时间、PH 快照来源、完整性校验结果。
4. 最后显示现有的危险确认语句。

本机覆盖范围与存档内容使用相同的数量维度，避免用户在不同口径之间换算。PH 同时展示活动计划和已归档计划。

## 3. 状态与可读性

- 预览读取失败时维持现有阻断行为，不触发任何写入。
- 本机数据读取失败时不猜测为 0；预览应让导入继续失败并提示错误，避免误导用户。
- 沿用现有中英文翻译键，不引入硬编码文案。
- 预览仍是纯文本确认内容，不改变移动端和桌面端的确认组件布局。

## 4. 数据边界

预览读取当前统一存档中的 records、todos、todo_categories 和 plan_helper 快照，只计算数量，不比较具体 ID，也不改变导入的整体替换语义。后续若引入逐条合并，需另行设计冲突模型。

## 5. 验证标准

- ArchivePreview 同时包含存档数量和本机数量。
- 导入确认同时出现“存档内容”和“本机将覆盖”两组信息。
- 中英文键数量一致。
- 既有存档预览、完整性、别名迁移和前端构建测试继续通过。
