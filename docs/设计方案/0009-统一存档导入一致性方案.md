# 统一存档导入一致性方案

**文档性质**：统一数据协议实施决策  
**创建时间**：2026-09-25（Asia/Shanghai）  
**适用范围**：`common.data_exchange.import_bundle`

## 1. 问题

统一 `.efl` 包包含多个相互关联的数据集。逐个直接写入目标目录时，后续数据集失败会留下部分导入结果，用户无法判断哪些数据已经落地。

## 2. 决策

- 先完整读取并解析 manifest 与所有数据集。
- 在不覆盖模式下，先检查所有目标文件，任何冲突都在写入前失败。
- 在允许覆盖模式下，先在目标目录的临时目录中物化全部数据集，全部成功后再逐个原子替换目标文件。
- 无论成功或失败都清理临时目录；不改变现有目标文件命名和协议格式。

## 3. 边界

该策略保证进程内的“先验证后写入”一致性；若操作系统在多文件替换过程中突然断电，仍需要未来引入目录级 manifest/事务日志才能提供更强恢复能力。本阶段不改变协议版本。

## 4. 验收

- 目标文件冲突时，任何数据集都不应被写入。
- 覆盖导入成功后所有数据集内容完整更新。
- 临时目录不残留。
