# to-dos 旧版导出迁移方案

**文档性质**：统一数据迁移方案  
**创建时间**：2026-09-25（Asia/Shanghai）  
**适用范围**：`to-dos` legacy JSON 导出与统一 `todos` 数据集

## 1. 问题

to-dos 原生 JSON 导出使用 `{version, exported_at, todos, categories}` 包装，而统一存档的数据集直接承载任务数组。已有字段适配器可以转换单条任务，但缺少文件级迁移入口。

## 2. 决策

- 新增无副作用的迁移函数，接受文件内容、JSON 字符串或已解析对象。
- 接受旧版包装对象和裸任务数组两种输入。
- 输出统一任务数组、分类元数据和迁移来源信息，不直接写磁盘、不覆盖现有数据。
- 每条任务通过 `TodoAdapter` 规范化，保留子任务、关联计划、时间记录、优先级高级字段和重复规则。
- 非法任务条目报告索引与原因；默认严格模式整体失败，宽松模式跳过非法条目并返回 warnings。

## 3. 与 `.efl` 的关系

迁移器只负责把 legacy 数据变成 canonical payload；真正写入统一 `.efl` 或 IndexedDB 的事务由上层导入流程负责，避免迁移器产生隐式副作用。

## 4. 验收

- 旧版包装 JSON 和裸数组都能迁移。
- 完整任务字段往返不丢失。
- 严格/宽松错误策略可预测，并有自动化测试。
