# 0375 事件计划创建内容前置方案

## 背景

统一工作台原先的新建事件计划只提交名称和日期。`plan-helper` 的创建 API 实际已经支持 `sections`，但桌面壳没有传递该字段，因此用户会先得到一个空计划，再被迫进入详情页逐项补录。

## 决策

1. 新建流程在同一个工作台弹层中收集计划名称、日期、分组和任务。
2. 至少需要一个有内容的任务才能提交，避免再次生成空计划。
3. 分组说明和任务预计分钟数随创建请求一起提交，创建后仍可在详情页继续编辑。
4. 桌面服务路径使用已有 `POST /api/plans` 的 `sections` 字段；移动端路径将同一输入转换为原始 plan 模型的 `main[].plan`，保留首位 `null` 哨兵和 `t_m = minutes / 6` 的底层约定。
5. 不改变任务内部编号、软删除或嵌套分组模型；本次只负责创建时的初始数据写入。

## 结果

创建体验从“创建空壳再补录”变为“创建即有可工作的计划”，同时桌面和移动端保持同一输入语义。
