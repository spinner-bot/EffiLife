# 统一搜索快捷键焦点边界方案

## 背景

应用壳注册了全局 `Ctrl/⌘+K` 搜索快捷键，但当前不判断事件来源。用户在待办、计划、记录或设置输入框中编辑时按下相同组合键，会意外打开搜索并抢走编辑焦点。

## 决策

- 当事件目标是 `input`、`textarea`、`select` 或 `contenteditable` 元素时，不触发全局搜索；
- 在页面普通区域、导航和按钮上继续支持 `Ctrl/⌘+K`；
- `Escape` 仍可关闭已打开的全局搜索；
- 将焦点判断封装为小型纯函数，便于桌面与移动端键盘契约测试；
- 不改变搜索索引、路由或页面内表单行为。

## 验证

- 增加静态契约，确认可编辑目标保护和跨平台修饰键仍存在；
- 执行 Python 全量测试；
- 执行桌面端 Vite 生产构建。
