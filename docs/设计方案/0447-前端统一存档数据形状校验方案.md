# 前端统一存档数据形状校验方案

- 状态：[设计完成，待实现]
- 创建时间：2026-09-29
- 执行者：Codex
- 关联目标：统一前端与 Python 的 `.efl` canonical 数据校验语义

## 1. 问题

Python 侧已开始拒绝顶层类型错误的 canonical 数据集，但前端解析器对 `app`、`todos`、`todo_categories` 和 `plan_helper` 的部分错误类型会静默回退为空值。这会造成同一个存档在不同入口下结果不一致，并可能隐藏数据损坏。

## 2. 方案

在 canonical manifest 分支读取数据集后、领域归一化前增加基础形状门禁：

- `app`、`records`、`plan_helper` 必须为非数组对象；
- `todos`、`todo_categories` 必须为数组；
- `records` 每个日期桶必须为数组；
- `plan_helper.plans` 存在时必须为数组。

校验失败使用现有 `settings.archive.datasetInvalid` 文案，阻止任何写入。旧版 `archive.json` 继续使用兼容归一化逻辑，不扩大新协议限制。

## 3. 约束

- 不复制 Python 侧的领域字段校验和待办迁移逻辑。
- 不改变缺失旧版可选字段的保留语义。
- 不改变校验和、回滚和 canonical 数据集完整性门禁。

## 4. 验收

- 前端与 Python 对核心 canonical 数据集的顶层形状要求一致。
- malformed 存档在写入前失败，并指出具体数据集。
- 合法 `.efl` 和旧版兼容存档继续通过现有测试。
