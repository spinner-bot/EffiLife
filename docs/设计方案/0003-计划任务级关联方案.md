# 计划任务级关联方案

**文档性质**：前端与数据模型设计方案（实施前置）
**创建时间**：2026-09-25（Asia/Shanghai）
**适用范围**：统一待办与 plan-helper 任务级关联

## 1. 核心原则

plan-helper 的任务编号存在两种语义：

- `display_id`：根据当前 active 任务扫描得到的显示编号，例如 `A1`、`A2`；软删除后会重新紧凑显示。
- `internal_id`：原始有序槽位对应的稳定引用，例如删除 `A2` 后原 `A3` 仍是 `A3`。

待办必须保存 `related_plan_task_id = internal_id`，不能保存显示编号作为外键。界面可以展示 `display_id`，但提交时使用内部 ID。

## 2. 交互设计

- 先选择计划，再加载该计划的 active 任务。
- 任务选择器显示“显示编号 + 内容”，例如 `A2 · 撰写报告`。
- 取消计划关联时同步清空任务关联。
- 计划或任务服务不可用时，普通待办创建、编辑仍可用。
- 已保存的内部任务引用即使当前无法解析，也保留原值并显示 `#内部编号`，避免数据静默丢失。

## 3. 数据边界

- 不在 time-helper 重排 plan-helper 的任务数组。
- 不将嵌套 group 转换成单个 group ID；任务关联只引用任务，不改变组嵌套结构。
- 不在待办侧复制任务内容作为唯一依据；任务内容展示属于缓存摘要，plan-helper 是权威来源。

## 4. 验收条件

- 选择计划后可读取并选择 active 任务。
- 待办保存内部任务 ID，界面显示动态显示编号。
- 计划取消时任务引用清空。
- 软删除后重新加载不会把旧引用误绑定到新的显示编号。
- 适配器和服务测试覆盖 display/internal ID 区分。
