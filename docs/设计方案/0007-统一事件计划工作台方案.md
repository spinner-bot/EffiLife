# 统一事件计划工作台方案

**文档性质**：前端领域工作台设计方案（实施前置）
**创建时间**：2026-09-25（Asia/Shanghai）
**适用范围**：plan-helper 事件计划在 time-helper 统一壳中的首版工作台

## 1. 领域定位

time-helper 的日计划描述“时间如何分配”；plan-helper 的事件计划描述“要完成什么”。统一工作台同时提供两种视角，但不把时间类别伪装成事件任务，也不重写 plan-helper 原始数据。

## 2. 入口结构

- 首页“计划”进入计划中心，而不是直接跳入某个旧模块。
- 计划中心提供两个明确入口：
  - 时间计划：进入现有 time-helper `/plan`；
  - 事件计划：进入统一事件计划工作台。
- 事件计划页面支持列表、详情和编辑三种状态，均在统一主题壳中完成。

## 3. 创建与编辑

- 创建只要求名称和日期，日期默认当前日期。
- 创建成功后立即进入全屏编辑状态，不在小弹窗里塞入 section/task 表单。
- 详情页提供编辑计划元信息、增加 section、增加任务、编辑任务和完成任务入口。
- 任务显示使用 plan-helper API 提供的 `display_id`，写操作使用 `internal_id`。

## 4. 数据与删除

- section/task 操作通过 plan-helper API 完成。
- 删除任务使用软删除；界面重新读取动态显示编号，不显示跳号。
- group 和 log 首版只读展示，不在统一页面中改写其结构。
- 归档、恢复和硬删除继续由已有 plan-helper API 负责，统一页面只调用明确接口。

## 5. 状态与主题

- 所有加载、不可用、空状态和错误使用统一主题令牌。
- plan-helper 未运行时，计划中心显示服务不可用说明，不影响 time-helper 的时间计划和待办功能。
- 通过 i18n catalog 提供中英文核心文案。

## 6. 验收条件

- 可从统一首页进入计划中心并区分两种计划。
- 可创建空事件计划并进入全屏编辑。
- 可看到 section、任务、动态显示编号、稳定内部引用和 group 摘要。
- 计划服务不可用时有明确反馈且不阻塞其它模块。
