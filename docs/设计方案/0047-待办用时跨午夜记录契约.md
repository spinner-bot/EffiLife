# 待办用时跨午夜记录契约

## 问题

统一待办的“记录用时”会同时写入待办累计用时和时间记录。若一次记录跨过午夜，单条记录无法同时表达两个日期；直接写成 `23:50–00:15` 会被统计逻辑解释为负时长。

## 约定

- 记录按自然日拆分，每条记录只属于一个 `date`。
- 结束于当天午夜时，使用 `24:00` 作为结束边界；`timeStrToMinutes` 将其解释为 1440 分钟。
- 跨午夜产生的每条记录拥有独立 ID，并全部写入待办的 `related_time_record_ids`。
- 待办的 `time_spent` 仍只增加用户请求的总分钟数，避免拆分造成累计重复。
- 普通手工记录仍要求结束时间晚于开始时间，不改变既有输入契约。
