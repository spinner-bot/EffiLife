# 0404｜统一数据管理器原子持久化方案

## 背景

统一工作区的 `.efl` 存档已经使用临时文件和原子替换，但 `DataManager` 的跨模块引用、模块目录注册和全局备份仍直接覆盖 JSON 文件。进程中断或写入失败时，可能留下截断文件，破坏模块关联索引。

## 设计决策

- 所有由 `DataManager` 写出的 JSON 文档先写入同目录临时文件，再通过 `os.replace` 替换目标文件。
- 写入后先 `flush` 和 `fsync`，确保替换前临时文件内容已经交给操作系统。
- 临时文件始终放在目标文件同一目录，保持替换操作的原子性边界；异常时清理临时文件。
- 不改变数据结构、文件路径或模块引用语义，仅提升写入可靠性。

## 验收标准

1. 跨模块 `references.json` 使用原子写入。
2. 全局备份和模块目录注册沿用同一安全写入工具。
3. 现有 DataManager 查询、导出和引用行为保持不变。
