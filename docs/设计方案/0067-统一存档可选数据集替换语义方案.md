# 统一存档可选数据集替换语义方案

## 背景

统一 `.efl` 存档是完整恢复点。导出时某些应用数据可能不存在，因此 canonical `app.json` 会将对应数据集写为 `null`。如果导入时把 `null` 当成“跳过”，目标设备中旧的配置、音频、事件或打卡数据会残留，恢复后的工作区就不等于存档内容。

## 决策

前端导入对可选应用数据集采用三态语义：

- 值为对象/数组：同时写入 IndexedDB 主存储和 localStorage 兼容镜像。
- 值为 `null`：从 IndexedDB 和 localStorage 同时清除，表示存档明确要求该数据集为空。
- 值为 `undefined`：不操作，保留旧版 `archive.json` 缺少字段时的向后兼容行为。

记录、待办、分类继续使用各自的完整集合替换逻辑；plan-helper 继续根据 `available` 和服务能力返回恢复或警告。

## 验收标准

1. canonical 存档中的 `null` 应用数据集不会在目标设备留下旧值。
2. canonical 存档中的非空数据同时更新两个存储层。
3. 旧版缺失字段不因本次修复被误清除。
4. 导入事务失败时仍由现有 runtime snapshot 回滚机制恢复全部存储。
