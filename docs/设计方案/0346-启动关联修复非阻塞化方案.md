# 启动关联修复非阻塞化方案

## 背景

统一工作台启动时会清理待办与时间记录之间已明确失效的关联。该维护操作依赖多个本地存储读取，偶发失败不代表核心工作区不可用；若让异常继续冒泡，会把可恢复的数据维护问题错误地呈现为启动失败。

## 方案

- 核心初始化（音频、打卡、事件、应用存储和遗留待办迁移）仍失败即进入启动错误态；
- `repairTodoTimeRecordLinks` 在核心初始化后独立捕获异常，仅记录 `console.warn`；
- 工作台继续进入可用状态，用户可通过后续编辑或存档恢复再次触发数据修复；
- 计划任务关联修复本来就是启动后异步执行，继续保持不阻塞首屏。

## 原则

数据修复应尽量保证幂等，但不应成为用户进入工作台的单点故障。真正无法读取核心存储时，`appStore.init` 仍会按原有逻辑阻止业务壳渲染。
