# 统一存档导入前检查点方案

## 背景

统一 `.efl` 导入会替换多个 IndexedDB/localStorage 数据集。当前实现有进程内回滚，但成功导入并刷新页面后，进程内快照消失，用户无法从恢复面板找回导入前状态。

## 方案

- 在统一存档开始写入前，将当前运行时快照保存为 `archive_import` 备份；
- 复用现有备份列表、保留策略和桌面文件备份能力，不新增第二套备份协议；
- 恢复时同时清理并重建 localStorage 与 IndexedDB，确保双存储状态一致；
- 恢复成功后广播 `archive` 工作区变更事件，让其他窗口刷新；
- 检查点写入失败不阻断导入，因为当前导入仍有进程内原子回滚；失败仅记录诊断日志；
- 不改变旧模块备份格式和已有恢复行为。

## 验收

- 增加备份恢复契约测试；
- 增加统一存档导入前检查点契约测试；
- 运行全量 Python 测试与前端生产构建；
- 保持用户已有 `time-helper/desk/package-lock.json` 不变。
