# 统一计划生命周期方案

**文档性质**：领域交互与数据方案  
**创建时间**：2026-09-25（Asia/Shanghai）  
**适用范围**：统一计划中心中的 plan-helper 事件计划

## 1. 目标

让计划中心提供完整的“使用中 → 归档 → 恢复”闭环，同时不把 plan-helper 尚未完成的硬删除能力暴露给普通用户。

## 2. 交互决策

- 活跃计划详情提供“归档计划”入口，二次确认后调用既有归档 API。
- 归档后的计划从活跃列表移除，但保留在“已归档”区域。
- 已归档计划显示名称、日期和归档时间，提供“恢复”操作；恢复后重新加载活跃列表。
- 归档和恢复期间按钮禁用并显示加载状态，失败时保留当前视图和用户可继续操作的错误提示。
- 不在统一页面提供直接删除计划按钮。原因是原始数据模型的硬删除涉及编号与日志同步，当前 API 的删除操作虽为移出注册表，但不等同于完整可恢复删除。

## 3. 数据约束

- 前端只传递归档文件名，不拼接本地路径；服务端继续执行安全文件名校验。
- 归档保留完整 raw plan 快照，包括软删除槽位、嵌套 group 和 log。
- 恢复不修改快照内容；若需要新 ID，由后端按既有 Plan.load_from_json 规则处理。

## 4. 验收

- 能从计划详情归档计划。
- 能在归档列表看到并恢复计划。
- 归档/恢复失败有可见反馈，且不丢失当前页面状态。
