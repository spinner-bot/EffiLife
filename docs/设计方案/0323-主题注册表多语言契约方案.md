# 主题注册表多语言契约方案

- 状态：[已实现并验证]
- 创建时间：2026-09-29
- 执行者：Codex
- 关联目标：保证 th 丰富主题架构与可扩展多语言基础同步演进

## 1. 背景

主题注册表现在保存名称、描述和分类的 i18n key。类型检查只能保证字段存在，无法保证 key 已在所有语言目录中注册。缺失翻译时，界面会退化为显示原始 key 或回退语言，问题通常要到运行时才暴露。

## 2. 方案

- 在 Python 契约测试中读取 `ThemeEngine.ts` 的注册表元数据和 `i18n/index.ts` 的两套目录。
- 提取所有 `nameKey`、`descriptionKey`、`categoryKey`，要求每个 key 在 `zh-CN` 与 `en-US` 中均出现一次。
- 同时约束主题注册表中的 `type` 不重复，避免主题卡片 key 冲突。
- 测试只读源码，不改变运行时 fallback 行为，也不将语言目录耦合到主题引擎实现。

## 3. 约束

- 新增主题必须同时登记三类翻译 key。
- 兼容保留的 `name`、`description` 字段不作为多语言显示依据。
- 现有 fallback 机制继续保留，契约门禁负责尽早发现开发遗漏。

## 4. 验收

- 所有当前主题元数据 key 在两套语言目录中均存在。
- 主题类型无重复。
- 测试在新增主题但漏加翻译时失败，并给出缺失 key。
