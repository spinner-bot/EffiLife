# 统一启动器端口契约方案

**文档性质**：实施设计方案  
**创建时间**：2026-09-25（Asia/Shanghai）  
**适用范围**：`launcher/start.py` 及其启动的 Vite 开发服务

## 1. 问题

启动器根据固定 URL 等待服务，但旧 to-dos Web 的命令只传入 host 和 strictPort，端口依赖 Vite 配置文件。这样会让启动器的进程参数、等待地址和实际配置分散，后续配置变更时容易出现“启动成功但等待错误地址”或端口冲突处理不一致。

## 2. 决策

- 统一工作台显式传入 `--port 1420`。
- 旧 to-dos Web 兼容入口显式传入 `--port 1421`。
- 两个服务都保留 `--strictPort`，端口被占用时快速失败，不自动漂移到未知端口。
- 配置文件仍保留默认端口，便于直接进入模块目录开发；启动器命令是集成运行时的最终契约。

## 3. 验证要求

- 启动器单元测试同时校验 URL 与命令端口一致。
- 启动器兼容现有已运行的 plan-helper companion，不终止外部进程。
