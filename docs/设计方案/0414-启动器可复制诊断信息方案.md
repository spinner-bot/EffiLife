# 启动器可复制诊断信息方案

## 背景

统一启动器已经提供 `--diagnose`，但模块诊断只包含可用状态、端口和服务探测结果。启动失败时，用户仍无法从诊断结果直接确认工作目录、实际命令或依赖安装入口。

## 决策

为每个模块的诊断结果增加只读字段：

- `cwd`：启动工作目录；
- `command`：实际启动命令；
- `setup`：首次运行所需的依赖安装命令；
- `needs_setup`：是否需要执行依赖安装。

命令和路径统一转换为字符串，保证 JSON 可复制、跨 Windows/POSIX 可解析。诊断不启动进程、不安装依赖、不修改配置；现有端口探测和服务探测保持不变。

## 验证

- 扩展启动器静态/行为契约，确认诊断字段完整且保持只读；
- 执行 Python 全量测试；
- 启动器改动不涉及桌面前端构建，但继续执行现有前端构建作为整体验收。
