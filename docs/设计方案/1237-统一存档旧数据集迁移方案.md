# 1237｜统一存档旧数据集迁移方案

## 背景

统一交换层首版文档曾使用 `plans.json` 和 `time_records.json`，当前 canonical 协议使用 `plan_helper` 和 `records`，并要求 `todo_categories`。旧 `.efl` 若只做 canonical 名称检查，会被误判为缺少数据。

## 决策

- 在 Python 交换层的 workspace 读取边界增加一次性旧名称迁移：
  - `time_records` → `records`
  - `plans` → `plan_helper.plans`
  - 缺失 `todo_categories` → 空数组
- 迁移只改变数据集容器名称和缺失的可选空容器，不修改实体字段、任务编号、嵌套组、日志、TH 记录或 TD 引用。
- 若新旧名称同时存在，优先使用 canonical 名称，不静默覆盖；旧名称保留在非 workspace 通用读取接口中。
- 不对不明确的旧 plan 字段做猜测转换；结构仍由 canonical shape 校验负责拒绝。

## 边界

这是脚本/跨运行时交换层的兼容迁移。前端 `.efl` 读取器已有 `archive.json` 旧格式兼容逻辑，本次不改变其 manifest 校验和导入回滚策略。

## 验证

- 增加旧数据集别名读取、canonical 优先和不明确结构拒绝测试。
- 运行交换层、完整 Python 回归和集成测试。
