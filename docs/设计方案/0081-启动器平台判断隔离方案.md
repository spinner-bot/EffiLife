# 启动器平台判断隔离方案

## 背景

启动器测试需要模拟 Windows 与 POSIX 行为。直接修改共享 `os.name` 会影响 Python 标准库的 `pathlib.Path` 工厂：在 Linux 上后续创建路径时会尝试实例化 `WindowsPath`，导致 CI 测试失败。

## 方案

- 保留 `is_windows()` 作为启动器唯一的平台判断入口。
- 启动器内部的路径、工具名、进程组、安装包和日志分支统一调用该入口。
- 测试通过替换 `launcher.is_windows` 模拟平台，不再修改全局 `os.name`。
- 真实运行时 `is_windows()` 仍返回宿主平台的 `os.name == 'nt'` 结果。

## 边界

- 不改变 Windows、Linux、macOS 的实际启动行为。
- 不改变 Android/iOS 发布范围和签名资格判断。
- 不把平台模拟扩展为跨平台运行时兼容层；这里只隔离测试注入点。

## 验证

- Windows 本地启动器测试。
- POSIX 平台模拟与全量回归。
- 真实 Ubuntu GitHub Actions CI。
