# 发布预检与启动器运行时查找契约

## 背景

统一启动器支持优先使用 `EFFILIFE_NODE_DIR`（当前开发机为 `F:/dev-tools/node`）查找 Node/npm，但发布预检脚本只使用系统 `PATH`。同一台机器因此可能出现“启动器可运行、预检却报告 Node 缺失”的矛盾结果。

## 设计决策

- 发布预检的 Node/npm 查找顺序与启动器一致：先检查 `EFFILIFE_NODE_DIR`，再检查系统 `PATH`。
- 默认开发工具目录只作为兼容回退；CI 或正式发布环境仍可以通过 `EFFILIFE_NODE_DIR` 显式指定工具链，不改变 Rust、Java、ADB、Android SDK、Xcode 等真实门槛。
- 预检输出继续保持 JSON 结构和退出码语义不变，便于 CI 消费。
- 不把开发机的绝对路径写入仓库配置；默认路径只在 Windows 且环境变量未设置时使用。

## 验证

- 新增测试覆盖自定义 Node 目录优先级、系统 PATH 回退和缺失工具报告。
- 执行全量 Python 测试和启动器实际预检。
