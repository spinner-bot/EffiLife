# PH 完成任务联动 TD 方案

**文档性质**：产品一致性设计方案  
**创建时间**：2026-10-14（Asia/Shanghai）  
**适用范围**：统一工作台、计划中心、统一待办

## 1. 问题

计划中心和首页都可以完成 PH 任务，但此前只写入计划数据。若该任务已经生成了 TD 关联待办，TD 仍会显示为未完成，造成跨工作区状态矛盾。

## 2. 决策

- PH 计划任务是进度权威；完成 PH 后，将所有同时满足 `related_plan_id` 与 `related_plan_task_id` 的 TD 投影标记为完成。
- 只处理 `pending` 和 `in-progress` 待办，不恢复或覆盖已归档、已取消数据。
- 关系只使用 PH 的稳定 `internal_id`，不使用显示编号，不改变嵌套组、软删除和日志结构。
- 两个存储边界没有分布式事务。PH 成功后 TD 投影失败时保留 PH 成果，并通过现有错误提示告知用户，以便后续修复；禁止为联动失败回滚 PH。
- TD 独立完成入口的反向同步规则仍由既有 TD→PH 协调方案负责，本方案不把计划编辑权交给 TD 视图。

## 3. 实现边界

`workspaceSync.completeLinkedPlanTodo` 负责精确查找和投影；`PlansHubView` 与 `HomeView` 在 PH 完成成功后调用它。联动失败采用独立 `try/catch`，不污染 PH 完成结果。

## 4. 验收

- 无关联 TD 时，PH 完成流程不受影响。
- 存在多个同一稳定关系的 TD 时，所有活动 TD 均完成。
- 已完成、已归档、已取消 TD 不被重写。
- TD 写入失败时，PH 仍显示已完成并出现联动失败提示。
- Python 契约测试覆盖关系字段、状态过滤和两个入口的失败隔离。
