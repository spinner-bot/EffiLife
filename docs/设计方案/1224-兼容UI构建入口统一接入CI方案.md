# 1224｜兼容 UI 构建入口统一接入 CI 方案

日期：2026-10-10

## 背景

`to-dos/ui` 已有 `scripts/build_todos_ui.py`，可复用启动器解析的 Node/npm 环境，但普通 CI 和桌面发布工作流仍直接在子目录运行 `npm run build`，形成三套工具链行为。

## 决策

- 保留工作流在 `to-dos/ui` 执行 `npm ci`，确保锁文件和缓存边界清晰。
- 将兼容 UI 的构建步骤统一改为根目录 `python scripts/build_todos_ui.py`。
- 普通 CI 与桌面发布工作流使用同一入口；Tauri 移动构建继续使用其原生前端 before-build 协议。
- 发布门禁与契约测试同时接受并优先要求统一脚本入口。

## 收益与边界

本方案统一 Node/npm 查找、PATH 注入和缺失依赖诊断，降低 Windows 自定义 Node 环境导致的 run fail 风险；不改变 to-dos UI 的源码、模块边界、依赖锁文件或正式 Tauri 移动构建命令。

## 验收

- CI 与桌面发布 workflow 均调用 `python scripts/build_todos_ui.py`。
- 工作流契约、发布配置检查、兼容 UI 构建和全量测试通过。
