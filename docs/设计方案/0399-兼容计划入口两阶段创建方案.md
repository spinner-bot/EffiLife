# 兼容计划入口两阶段创建方案

## 背景

统一工作台已经采用“创建弹窗只收集名称与日期，创建后进入详情编辑”的流程，但旧版 `plan-helper` Web 入口仍在创建弹窗中预置章节和任务。两个入口的行为不一致，会让用户误以为创建时必须先填写计划内容，也会产生空白任务的清理成本。

## 设计决策

- 创建弹窗只保留计划名称和日期，日期默认当前日期。
- 创建接口提交空的 `sections`，随后打开已有的计划编辑界面，从空计划开始添加章节与任务。
- 计划编辑界面改为占满可用视口的编辑工作区，保留原有章节、任务和组数据编辑 API，不改变数据结构。
- 编辑器继续保留遮罩点击关闭、取消和保存；窄屏时使用视口宽度并允许内容滚动。
- 不删除旧的 `newSection`、`addNewTask` 等兼容辅助函数，避免影响模板或外部调试入口；创建流程不再调用它们。

## 验证

- 静态契约测试确认创建流程不预置内容、弹窗不渲染章节/任务输入，并确认编辑工作区使用全屏样式。
- 执行全量 Python 测试和前端兼容构建。
