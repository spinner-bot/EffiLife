# 计划待办完成状态同步方案

**文档性质**：实施设计方案  
**创建时间**：2026-09-25（Asia/Shanghai）  
**适用范围**：统一工作台计划与待办完成操作

## 1. 现状问题

统一待办已经保存计划 ID 和计划任务 ID，时间记录也能关联待办，但两个完成入口没有互相更新，用户会看到同一项工作在两个页面状态不一致。

## 2. 决策

- 从待办完成：先完成统一待办，再调用 plan-helper 完成关联计划任务。
- 从计划任务完成：先调用 plan-helper，再扫描统一待办并完成所有精确关联项。
- 同步器只使用已有的 `related_plan_id` 和 `related_plan_task_id`，不改变 plan-helper 原始编号、软删除或日志结构。
- 本地完成操作不因另一服务暂时不可用而回滚；失败通过当前页面的明确提示反馈，用户可稍后在另一入口重试。

## 3. 一致性边界

这是最终一致的双向同步，而不是跨 IndexedDB 与 Python 文件存储的分布式事务。计划和待办的原始数据仍各自由所属服务负责，协调层只执行幂等的完成操作。
