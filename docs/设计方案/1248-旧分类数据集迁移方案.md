# 1248｜旧分类数据集迁移方案

创建时间：2026-10-10  
执行者：Codex  
状态：[完成]

## 问题

早期统一存档和旧单文件 `archive.json` 使用 `categories` 表示 TD 分类，当前 canonical 数据集名称是 `todo_categories`。现有前端 legacy 解析会忽略 `legacy.categories`，Python 交换层也只在缺失时创建空 `todo_categories`，可能造成分类静默丢失。

## 迁移规则

- canonical 名称：`todo_categories`。
- 旧别名：`categories`。
- canonical 存在时始终优先，旧别名不得覆盖它。
- 旧别名值必须是数组；缺失时才使用空数组/默认分类补全。
- 单文件 `archive.json` 同样读取 `legacy.categories`，再走现有分类规范化和默认分类补全。
- 只迁移容器名称，不修改分类实体字段，也不改变 TD 与 PH/TH 的边界。

## 被否决方案

- 不把分类放进 `app` 数据集并另建一套读取分支，避免跨运行时协议继续分裂。
- 不在迁移层按名称猜测或重写分类 ID；实体规范化仍由现有 Todo 分类服务负责。

## 验证标准

- Python 能迁移 `categories` 数据集。
- 前端 manifest 和 legacy `archive.json` 都读取旧分类数据。
- canonical `todo_categories` 与 `categories` 并存时 canonical 优先。
