# 旧版存档缺失计划快照保护方案

- 状态：[已实现并验证]
- 创建时间：2026-09-29
- 执行者：Codex
- 关联目标：统一存档导入的向后兼容与跨模块数据安全

## 1. 问题

旧版单文件 `archive.json` 可能没有 `planHelper` 字段。当前解析器会补成 `{ available: false, plans: [] }`，导入阶段将其视为明确不可用并清空当前 plan-helper 数据，可能误删用户已有计划。

## 2. 方案

- 将 `ArchiveData.planHelper` 标记为可选。
- 旧版字段缺失时保留 `undefined`，处理导入时跳过 plan-helper 写入和清理。
- 明确提供 `planHelper.available === false` 或空计划数组时，继续执行现有清理/替换语义。
- canonical `.efl` 的 `plan_helper` 数据集仍始终存在；缺失数据集继续拒绝导入。
- 预览对缺失字段显示不可用，但不把展示默认值写回导入数据。

## 3. 约束

- 不改变移动端已有快照恢复和桌面端实时导入逻辑。
- 不改变显式不可用计划快照的警告提示。
- 不改变导入失败的完整回滚机制。

## 4. 验收

- 旧版缺少 `planHelper` 时不调用 `clearPlanHelperData()`。
- 旧版明确提供不可用计划数据时仍清理计划快照并给出提示。
- 新版 canonical 存档仍要求 `plan_helper` 数据集存在。
