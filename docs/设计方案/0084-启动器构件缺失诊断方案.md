# 启动器构件缺失诊断方案

## 背景

统一启动器在 `--packaged` 模式下只允许使用 Tauri 原生二进制或已构建的静态前端。若两者都不存在，模块会被标记为不可用，但原有提示没有区分“正式包构件缺失”和“开发环境依赖缺失”。

## 决策

- 增加统一的启动模式判断函数，避免命令行参数和环境变量在不同路径产生不一致。
- 构件缺失时为统一工作台写入明确的 `unavailable_reason`。
- 正式包模式提示需要安装包中的 Tauri 构件或重新构建安装包；开发模式提示准备 Node/npm、依赖或 dist。
- 诊断模式继续只读，不自动安装或启动任何服务。

## 验收标准

1. `--packaged` 与 `EFFILIFE_LAUNCH_MODE=packaged` 得到相同模式判断。
2. 正式包缺少原生构件时，模块状态和诊断 JSON 都包含明确原因。
3. 有构件时不标记错误，现有启动优先级不变。
