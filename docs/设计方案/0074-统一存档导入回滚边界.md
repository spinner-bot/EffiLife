# 0074 统一存档导入回滚边界

## 问题

`.efl` 导入会同时写入多个 IndexedDB object store 和 localStorage。解析阶段虽已先完成，但写入阶段任一存储失败时，旧数据可能只被部分覆盖。

## 方案

- 解析成功后、首次写入前捕获应用 localStorage 和 IndexedDB stores 的内存快照。
- 核心本地写入放入 `try/catch`；任一写入失败时，按快照清空并恢复原存储。
- 回滚失败时保留原始错误和回滚错误，明确提示恢复未完全成功，便于后续人工处理。
- plan-helper 的 HTTP 导入仍属于外部服务边界：请求失败不回滚本地数据，而是返回已有的“存档已导入但事件计划恢复失败”警告。
- 成功完成后释放快照，不新增持久化格式，不改变 `.efl` 协议。

## 边界

这是单进程、单客户端操作的回滚保护，不宣称跨进程或断电事务；强一致的文件级事务仍属于未来正式数据层演进范围。
