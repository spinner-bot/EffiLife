# 统一导入待办归一化方案

**文档性质**：实施设计方案  
**创建时间**：2026-09-25（Asia/Shanghai）  
**适用范围**：time-helper 前端 `.efl` 与旧版 `archive.json` 导入

## 1. 背景

统一存档协议可以承载多个模块的数据，但历史待办可能缺少新版本默认字段。若导入时直接写入 IndexedDB，任务中心需要为每个历史版本单独兜底，容易造成显示和更新行为不一致。

## 2. 决策

- 所有进入前端待办存储的导入记录，先经过 `normalizeImportedTodo`。
- 标题必须是非空字符串；任务编号如果存在必须是字符串。非法记录令导入失败，避免静默丢任务。
- 缺失的状态、优先级、时间戳、标签、子任务、重复规则等字段使用当前统一模型默认值。
- 已有字段保持原值，包括计划关联、时间记录关联、子任务和高级优先级字段。
- 该归一化只负责内存转换；导入流程仍由存档服务统一执行，不在解析阶段产生外部副作用。

## 3. 边界

该方案解决的是前端存储契约一致性，不替代 Python 侧旧版 JSON 迁移器。两者共享同一数据语义：Python 侧负责跨模块/批处理迁移，前端侧负责用户导入时的即时校验与默认值补全。
