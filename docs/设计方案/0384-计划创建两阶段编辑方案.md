# 0384 计划创建两阶段编辑方案

## 背景

原计划创建弹窗同时承载名称、日期、模板、待办开关、分组和任务编辑。该布局在小窗口中难以容纳完整的 plan-helper 语义，也容易让用户误以为创建计划必须一次填完所有细节。

## 决策

1. 创建弹窗只收集计划名称和日期，日期默认填充当前本地日期。
2. 提交后先创建允许为空的计划，再立即进入已有的全屏计划详情编辑器。
3. 分组、任务、嵌套组、进展日志和待办关联统一在详情编辑器中完成，避免两套编辑状态和两套数据转换。
4. 模板 API 和移动端原始快照能力保留在领域服务层，后续可在全屏编辑器中提供模板入口；本次不把模板选项塞回创建弹窗。
5. 待办优先级保持位于待办条目右侧的操作区，正文仍是条目视觉主体。

## 兼容性

`createEventPlan` 的 `sections` 参数仍保留默认空数组，服务端和移动端继续接受带初始内容的调用，兼容迁移工具和领域 API；统一工作台的新建入口改用空计划路径。

## 验收

- 创建弹窗只显示名称、日期和创建/取消操作。
- 创建成功后进入 `/plans?plan=<id>` 详情编辑器。
- 空计划可添加分组和任务，嵌套组与待办联动能力不受影响。
- 中文、英文提示完整，契约测试和生产构建通过。
