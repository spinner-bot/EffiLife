# CI 首个失败证据可见性方案

## 背景

GitHub Actions 的测试步骤已经把失败内容写入 step summary 和 artifact，但未登录查看运行详情时只能看到“Process completed with exit code 1”，无法判断失败测试。仅凭本地平台回归不能替代 Ubuntu runner 证据。

## 方案

- 保留完整 `pytest-failure.log` 与 step summary。
- 失败时取日志末尾 40 行，转义 GitHub workflow command 中的 `%`、换行和回车。
- 通过 `::error file=pytest-failure.log...::` 写入 check annotation，使首个失败上下文直接出现在公开检查结果中。
- 不跳过、过滤或降低 Python 测试门禁。

## 边界

这是 CI 可观测性改进，不改变应用运行时、测试断言或发布资格。

## 验证

- 静态 workflow 契约测试确认失败注释命令存在。
- 本地全量回归通过后，以真实 Ubuntu CI 运行结果作为最终证据。
