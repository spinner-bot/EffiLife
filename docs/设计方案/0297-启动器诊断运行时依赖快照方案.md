# 启动器诊断运行时依赖快照方案

## 背景

发布配置检查可以确认仓库配置，但启动器故障还常常来自运行时环境：Node/npm、Cargo/Rust、开发依赖目录和统一数据目录。现有 `--diagnose` 只显示部分模块状态，排查时仍需要手工重复检查。

## 决策

扩展诊断输出为可复制的运行时快照：

- 顶层保留 Node、npm、启动模式、统一数据目录和候选 Tauri 二进制；
- 每个模块输出工作目录、实际命令、setup 命令、是否需要 setup、端口与服务状态；
- 额外输出 Rust/Cargo 的可用性和桌面构建是否具备，以便区分“启动器问题”和“发布机工具链缺失”；
- 诊断保持只读，不启动服务、不安装依赖、不创建数据目录。

## 兼容性

新增字段只扩展 JSON，不改变已有字段和默认启动路径；旧脚本可继续忽略未知字段。

## 验证

- 增加启动器诊断契约测试；
- 执行 Python 全量测试与桌面前端构建；
- 运行发布预检，明确记录本机缺少 Cargo/Rust 时的结果。
