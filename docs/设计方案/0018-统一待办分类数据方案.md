# 统一待办分类数据方案

**文档性质**：实施设计方案  
**创建时间**：2026-09-25（Asia/Shanghai）  
**适用范围**：to-dos 分类模型、time-helper 统一任务中心、`.efl` 存档

## 1. 现状与问题

原 to-dos 模块除了任务数组，还维护分类数组；分类包含名称、颜色、图标和难度，用于筛选与优先级计算。统一任务中心此前只保留任务的 `category` 字符串，导入导出也没有单独保存分类数组，导致分类配置会丢失。

## 2. 决策

- 在统一 IndexedDB 中增加 `todo_categories` 数据集，分类以稳定 `id` 为主键。
- 分类字段保持与 to-dos 语义兼容：`id`、`name`、`color`、`icon`、`difficulty`、`created_at`。
- `.efl` 增加 `todo_categories.json` 数据集；旧版 `archive.json` 没有分类时使用默认分类，不阻断旧存档导入。
- 任务中心首期支持分类筛选和创建/编辑任务时选择分类；分类管理界面后续再独立展开，避免把任务编辑弹窗变成配置面板。
- 未知分类仍保留任务原始字符串，导入不会静默改写任务归属；界面显示时回退到该字符串。

## 3. 一致性与迁移

- 导入分类数组时校验对象、稳定 ID、非空名称和颜色字符串；非法分类导致导入失败，避免出现无法选择的孤儿配置。
- 没有分类数组的旧数据自动补齐 `default` 分类和任务中实际出现的分类占位项。
- 分类是待办域数据，不复制到计划或时间记录域；跨域关系仍通过任务的 `related_plan_id` 与时间记录引用维护。
