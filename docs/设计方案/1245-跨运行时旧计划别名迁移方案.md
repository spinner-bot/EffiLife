# 1245｜跨运行时旧计划别名迁移方案

创建时间：2026-10-10  
执行者：Codex  
状态：[完成]

## 问题

统一前端存档解析已经接受 `plan_helper`、旧版 `plans` 和早期 camelCase 的 `planHelper`；Python 交换层只接受前两者。由此产生运行时差异：同一个旧 `.efl` 文件可能在前端导入成功，却在 Python 校验、备份或恢复工具中被判定为缺少计划数据集。

## 迁移决策

- canonical 名称继续使用 `plan_helper`。
- 旧别名按优先级尝试：`plans`，再 `planHelper`。
- 当 `plan_helper` 已存在时始终优先使用 canonical 数据，忽略旧别名，保持已有安全原则。
- 旧别名的值必须是数组；迁移后包装为 `{available, plans, archives}`，不改写 PH 实体字段、编号、嵌套组或日志。
- 该迁移只发生在容器层，不改变导入覆盖和回滚语义。

## 被否决方案

- 不让 Python 直接读取前端 camelCase 数据并绕过 canonical 容器，否则会使后续校验分支出现两套数据结构。
- 不按实体字段重排或修正计划内容；计划编号和嵌套组属于 PH 领域逻辑，交换层不得擅自解释。

## 验证标准

- Python 能读取 `planHelper` 旧别名。
- canonical `plan_helper` 与任意旧别名同时存在时，canonical 优先。
- 原有 `plans`、`time_records` 迁移和跨运行时协议测试继续通过。
