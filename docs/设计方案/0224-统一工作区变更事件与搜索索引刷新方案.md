# 统一工作区变更事件与搜索索引刷新方案

## 背景

统一搜索会同时读取待办、事件计划、计划任务和时间记录。此前搜索面板打开后只建立一次索引，用户在其他面板或另一个窗口完成写入时，已打开的搜索结果可能继续显示旧数据。

## 方案

在前端数据层增加 `effilife:workspace-changed` 自定义事件，并通过 `workspaceEvents.ts` 提供类型化的发布与订阅 API：

- `TodoService` 和 `TodoCategoryService` 在写入成功后发布 `todos` 变更；
- `planGateway` 在移动端快照写入或桌面 API 的非 GET 请求成功后发布 `plans` 变更；
- `GlobalSearch` 仅在自身打开时订阅事件并重建索引，关闭时不产生后台请求；
- 事件只表示“数据已成功写入”，失败路径不会触发，避免搜索刷新到未提交状态。

## 兼容性与扩展

事件基于浏览器原生 `CustomEvent`，SSR/测试环境没有 `window` 时安全降级为空操作。后续时间记录、存档导入和首页统计可复用同一通道，不需要互相依赖具体服务实现。

## 验证

- 全局搜索契约测试覆盖事件定义、待办写入、计划写入和打开态刷新；
- 前端构建与 Python 全量测试作为提交门禁。
