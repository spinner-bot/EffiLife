# 计划创建弹窗可访问性与焦点回收方案

## 设计决策

- **美学方向**：沿用统一工作台现有的轻量浮层，不增加额外视觉装饰；弹窗只承担“名称 + 日期”的快速创建，创建后进入计划详情编辑页。
- **交互方向**：遵循桌面端对话框惯例。打开时将焦点放到计划名称，用户可以使用 Tab 导航、Enter 提交、Esc 关闭或点击遮罩关闭；关闭后焦点回到触发按钮。
- **语义方向**：弹窗使用 `role="dialog"`、`aria-modal="true"` 和标题关联，避免辅助技术把它当作普通页面内容。
- **移动端方向**：不改变字段数量和业务流程；保留当前窄屏自适应宽度，避免引入桌面专属交互。

## 范围与边界

- 只改进计划创建弹窗的焦点与语义，不改变计划数据结构、创建接口或“两阶段创建后进入详情编辑”的业务流程。
- 不在本阶段引入复杂焦点陷阱；弹窗内容短小，浏览器原生 Tab 顺序足够，后续若增加字段再评估焦点循环。
- 遵守减少动画与现有主题 token，不新增硬编码主题色。

## 验证

- 静态契约测试确认对话框语义、Esc 关闭、遮罩关闭、名称输入焦点和焦点回收逻辑存在。
- 执行全量 Python 测试与桌面端生产构建。
