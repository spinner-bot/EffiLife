# 0391 统一工作区跨窗口刷新方案

## 背景

统一壳已经使用 `BroadcastChannel` 和同窗口事件广播工作区变化，但此前只有具体页面主动刷新。应用壳中的 Pinia 状态没有统一刷新入口，用户在多个窗口或兼容入口之间切换时可能看到过期的计划、记录和设置。

## 决策

1. 在 `app` store 中增加 `refreshWorkspaceData()`，按配置、计划、规则、今日记录的顺序重新读取，作为跨窗口恢复的单一入口。
2. 配置、计划和规则成功保存后分别广播 `settings` 或 `plans`；记录沿用现有 `records` 事件，存档沿用 `archive` 事件。
3. 应用壳订阅工作区事件，仅对影响 Pinia 的来源触发刷新；待办仍由待办页面自己的订阅处理，避免重复读取。
4. 刷新失败只记录可恢复警告，不阻塞当前窗口，也不覆盖现有可用状态。

## 验收

- 第二个窗口修改计划、设置或记录后，当前窗口能通过事件刷新共享状态。
- 存档恢复完成后，应用壳能重新读取配置、计划、规则和今日数据。
- 订阅在卸载时释放，避免重复监听。
