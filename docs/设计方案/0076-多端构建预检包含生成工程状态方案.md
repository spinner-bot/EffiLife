# 多端构建预检包含生成工程状态方案

## 背景

`check_build_environment.py` 原先只检查 Node/npm、Rust、平台 SDK 及命令行工具。Tauri Mobile 的 Android/iOS 工程位于 `src-tauri/gen`，需要先执行对应的 `tauri android init` 或 `tauri ios init` 生成；仅有 SDK 并不代表移动工程已经具备构建条件。

## 方案

- 桌面目标保持原有工具链检查，不引入移动工程目录要求。
- Android 和 iOS 报告新增 `mobile_project` 与 `mobile_project_exists` 字段。
- 移动目标在工具、SDK 和生成工程三者任一缺失时均报告 `ready: false`。
- 缺失项明确提示对应的初始化命令，帮助发布人员区分“缺 SDK”和“尚未初始化工程”。
- 检查只读，不自动安装 SDK、不自动生成平台工程，避免预检改变工作区。

## 验收标准

1. 当前未生成 `src-tauri/gen/android` 或 `src-tauri/gen/apple` 时，报告明确列出对应缺失项；其中 iOS 使用 Tauri 的共享 Apple 工程目录。
2. 测试夹具同时覆盖缺失和完整移动工程两种状态。
3. 桌面发布流水线与既有桌面配置门禁不受影响。
