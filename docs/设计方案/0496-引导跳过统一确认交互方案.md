# 0496 引导跳过统一确认交互方案

## 问题

统一工作台的删除、归档、存档导入和设置离开等高风险操作已经使用主题化 `requestConfirm`，但引导浮层跳过操作仍调用浏览器原生 `confirm`。这会造成主题样式、键盘交互和多语言行为不一致。

## 决策

- `GuideOverlay` 的跳过动作改为异步调用 `requestConfirm`。
- 使用普通确认语气，不把退出引导误标为数据破坏操作。
- 确认后仍只调用既有 `GuideManager.skipGuide()`，不改变引导状态机。
- 统一确认宿主不可用时继续使用服务层已有的安全返回值，不增加浏览器原生对话框回退。

## 验收

- 静态契约测试确认引导不再调用全局 `confirm`，而是调用 `requestConfirm`。
- 前端类型检查和生产构建通过。
