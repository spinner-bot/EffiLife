# 0075 待办用时记录补偿一致性

## 问题

任务中心记录用时时，会先向 time-helper 时间记录写入一条或多条记录，再更新统一待办的 `time_spent`。后一步失败时，时间记录会成为没有对应累计时长的孤立数据。

## 方案

- 时间记录继续使用稳定 `id`，不按数组下标回删，避免并发或排序变化造成误删。
- 待办累计更新失败时，按本次操作产生的记录 ID 逐条补偿删除。
- 某条补偿删除失败时保留原始错误并提示用户，不能静默宣称操作成功。
- 成功路径和 `.efl` 数据格式不变；补偿只发生在本次联动操作失败时。

## 边界

这是统一前端内的补偿一致性，不宣称 IndexedDB 与其它进程的分布式事务；后续可在统一数据层提供批量事务接口后替换为原子提交。
