# 0714 统一工作区存档跨运行时协议

## 目标

`.efl` 是 EffiLife 统一工作区的交换边界。Python 工具链、浏览器前端、Tauri 桌面端和未来移动端可以拥有不同的存储实现，但不能因为运行时不同而改变存档的核心结构。

## 固定协议

- 格式名：`effilife.bundle`
- 格式版本：`1.0.0`
- 容器：ZIP
- 清单：`manifest.json`
- 数据文件：`data/<dataset>.json`
- 校验：每个数据文件使用 UTF-8 原始字节计算 SHA-256，记录在 `dataset_sha256`。

规范数据集固定为：`app`、`records`、`todos`、`todo_categories`、`plan_helper`。清单可以带 `metadata`，压缩包可以带供人阅读的 `README.txt`，但它们不是业务数据集。

## 数据形状

| 数据集 | 顶层形状 | 说明 |
| --- | --- | --- |
| `app` | object | 配置、旧版计划兼容字段、音频/事件/打卡等应用数据 |
| `records` | object | 日期到时间记录数组的映射 |
| `todos` | array | TD 独立待办及其显式 PH/TH 引用 |
| `todo_categories` | array | TD 分类 |
| `plan_helper` | object | PH 计划快照；`plans` 与 `archives` 若存在必须为数组 |

Python 的导出和导入边界、前端的导入解析器必须同时执行上述形状校验。校验只约束跨运行时容器形状，不替代 PH、TD、TH 各自的领域校验和迁移逻辑。

## 跨运行时职责

- Python `common.data_exchange`：负责 ZIP 安全、清单、版本、校验和、规范形状及可回滚物化。
- 前端 `ArchiveService`：负责浏览器/Tauri 文件选择、预览确认、领域归一化、IndexedDB/LocalStorage 恢复，以及桌面 PH 服务回写。
- 两端不得通过新增同名但不同含义的数据集解决领域扩展；需要扩展时先升级协议版本或在现有数据集内增加向后兼容字段。

## 兼容规则

新导出只能使用上述规范协议。旧版 `archive.json` 等格式仅作为读取迁移入口，不参与新包生成。未知协议版本必须拒绝导入，缺失规范数据集、重复数据集、非法名称和校验失败也必须在写入前拒绝。

## 验证

`tests/test_cross_runtime_archive_contract.py` 锁定 Python 与前端的协议常量、规范数据集顺序和核心形状检查；`tests/test_data_exchange.py` 覆盖缺失数据、非法形状、篡改校验和导入回滚。
