# 启动器发布签名边界

日期：2026-10-11
类型：T（实现与验证）

## 背景

本机已经可以完成桌面安装包和 Android unsigned APK 的构建、版本校验、checksum 与 manifest 校验，但没有正式发布所需的签名工具与凭据。原启动器只依据“存在版本匹配的安装包”显示 distribution ready，容易把内部验收产物误解为可正式分发产物。

## 目标与非目标

目标是让启动器诊断同时报告构建产物与签名状态，并在有人运行 `--doctor` 时明确区分内部验收和正式分发。非目标是生成证书、创建临时发布密钥、修改系统信任配置或执行真实签名。

## 实现

- 增加 Android 签名环境只读探测：`apksigner`、`zipalign` 和本地 debug keystore；
- 增加 Windows `signtool` 只读探测；
- 在机器可读诊断中增加 `release_signing` 与 `formal_distribution_ready`；
- 保留原有 `distribution_ready` 字段作为“版本匹配安装包存在”的兼容字段；
- 人类可读诊断在安装包存在但未签名时显示“签名未完成”，并给出受控发布环境提示；
- 不改变开发启动判定，签名缺失不会阻止本地开发和内部结构验收。

## 兼容性与边界

该改动不改变 PH、TD、TH 的数据结构和运行时边界，也不启用 iOS。签名状态只影响发布诊断，不会自动读取或创建正式密钥。

## 验证

```text
python -m pytest -q tests/test_launcher.py tests/test_launcher_startup_hints.py
89 passed in 6.55s
python -m py_compile launcher/start.py
python launcher/start.py --doctor
```

本机诊断结果：桌面安装包存在且版本匹配，但 Windows `signtool`、Android `apksigner`、`zipalign` 与 debug keystore 均不可用；启动状态仍为 READY，正式分发状态为 not ready。
