# [完成] TH 记录更新补偿

## 背景

`DataService.updateRecord` 在直接调用场景下会更新 TH 记录，再清理旧 TD 反向引用。若清理失败，可能同时存在新 TH 数据和旧 TD 引用，破坏跨模块一致性。

## 实现

- 更新前保留当日 TH 记录快照。
- 先提交新记录，再执行旧 TD 反向引用清理。
- 清理失败时恢复原 TH 记录并向上层抛出异常。
- 仅在跨模块清理成功后写入兼容镜像和备份快照。
- 保持 TD 的累计时长由上层显式维护，底层更新只负责 TH 记录与旧反向引用安全。

## 验证

- 记录删除、更新与存储边界专项：`26 passed`。
- 桌面端生产构建：Vite `1879 modules`，成功。
- 全量 Python 回归将在提交前执行。

## 边界

该补偿路径与删除路径一样，属于跨 IndexedDB store 的可恢复操作，不等同于原生多 store 单事务；补偿写入若再次失败，会保留错误并交由启动修复与恢复链路处理。
