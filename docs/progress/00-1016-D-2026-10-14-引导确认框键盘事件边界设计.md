# [设计] 引导确认框键盘事件边界

## 创建信息

- 创建时间：2026-10-14
- 执行者：Codex
- 所属阶段：第 0 阶段（阶段未递增）
- 类型：可访问性与模态事件设计

## 背景

首次引导关闭确认框已完成层级和鼠标事件修复，但确认框内部的 Esc 事件仍会继续冒泡到引导层的全局键盘监听。若引导层再次调用关闭确认逻辑，可能重新创建确认请求，破坏 Esc 的可预测性。

## 设计决策

- 引导层的 document 键盘监听将把 `.confirm-dialog` 内的按键视为确认模态私有事件并直接放行。
- 确认框自身继续负责 Esc 关闭、焦点陷阱和按钮操作；引导层不复制这些逻辑。
- 该规则与此前的点击放行规则对称，适用于桌面键盘和移动端外接键盘。

## 验收条件

- 确认框打开时按 Esc，确认框关闭且不产生第二个确认框。
- 确认框打开时按 Tab，焦点仍限制在确认框内。
- 引导正常关闭/取消及其他页面确认框不回归。
