# 00-1196-T-2026-10-14 发布目标命名门禁

## 类型与阶段

T（发布链路实现）。当前仍为第 0 阶段；本报告只递增序列号，不增加阶段。

## 背景

Windows 本地产物曾出现 `windows-x64-nsis` 与当前发布矩阵 `windows-nsis` 不一致的 manifest 目标名。生成器此前接受任意字符串，无法在产物生成阶段阻止旧目标名重新出现。

## 实现内容

- 在 `generate_release_manifest.py` 固化当前受支持的规范目标：`windows-nsis`、`linux-deb`、`linux-appimage`、`macos-dmg`、`android`；
- 生成未知或旧目标名时立即失败；
- 增加回归测试，锁定旧目标名 `windows-x64-nsis` 必须被拒绝；
- 不改变发布工作流目标、不影响安装包内容。

## 验证

- 发布相关定向测试：`36 passed`；
- 清理本轮测试启动的 1420–1422 端口残留进程后，全量 Python 测试：`1284 passed`。

## 结论

发布 manifest 的目标命名现在在生成源头受控，能够防止产物元数据漂移重新进入发布链路。阶段保持第 0 阶段。
