# 0869 启动器实际诊断与发布边界复核

## 背景

启动器此前已经具备统一工作台、Plan Helper companion、端口冲突和安装包版本诊断能力。本轮对当前开发机执行实际 `--diagnose`，核对代码报告与运行环境是否一致。

## 诊断结果

- 统一工作台开发服务 `127.0.0.1:1420` 已健康运行，可被启动器复用。
- Plan Helper companion `127.0.0.1:8765/api/health` 已健康运行，可被统一工作台复用。
- TD 兼容 Web 入口 `1421` 当前未启动，不影响统一工作台主流程。
- 当前工作区版本为 `1.7.0`。
- 本机没有 Rust/Cargo、Android SDK/ADB 或 iOS/Xcode 工具链，原生安装包和移动真机验收仍应在对应发布环境执行。
- 工作区内存在非空 NSIS 安装包，但文件版本为 `1.0.11`，与当前 `1.7.0` 不匹配；启动器将其标记为 `installer-artifact-stale`，没有误报为可分发版本。

## 结论

开发测试启动链路当前可用，统一工作台和 companion 的复用逻辑没有发现新的端口或健康检查问题。旧安装包仅可作为历史构件，不能作为当前版本发布物；本轮不删除它，也不把缺少原生工具链误报为应用运行失败。

## 验证

- `python launcher/start.py --diagnose`
- 输出包含 `issues: []`。
