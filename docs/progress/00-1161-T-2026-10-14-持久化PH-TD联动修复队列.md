# 00-1161-T-2026-10-14 持久化 PH-TD 联动修复队列

## 类型与阶段

T（技术实现）。当前仍为第 0 阶段；本报告只递增序列号，不增加阶段。

## 问题

此前 PH 与 TD 联动失败后的重试入口只存在于当前页面内存中。用户离开页面或重启应用后，失败关联仍可能存在，但没有统一的后台修复任务记录。

## 实现

- IndexedDB schema 升级到版本 4，增加 `pending_plan_todo_sync` 存储。
- 联动失败时持久化稳定的 `planId + planTaskId` 修复任务。
- 应用启动后非阻塞地尝试修复待处理投影，成功后清除队列，失败则保留到下一次启动或人工重试。
- 首页、PH 计划中心、TD 独立页面的失败路径均写入该队列；人工重试成功后清理对应记录。
- 队列写入和清理采用 best-effort：存储不可用时记录诊断，不把已完成的用户操作误报为失败，也不阻塞工作台启动。
- 不改变 PH、TD 数据结构和领域边界；修复队列只记录明确由用户触发且已发生部分成功的联动操作。

## 边界

启动修复是非阻塞维护任务，不替代当前页面的即时重试入口；真实浏览器重启后故障恢复仍需在后续烟测中注入 TD 写入失败并验证队列跨会话保留。
