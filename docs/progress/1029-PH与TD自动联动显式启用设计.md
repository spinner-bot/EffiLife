# 1029 PH 与 TD 自动联动显式启用设计

## 日期

2026-10-02

## 背景

HOTL-1 要求 PH 是完整事件计划，TD 是独立快速待办。统一启动器当前默认注册 `PlanTodoLinker`，虽然旧 handler 只有在事件显式携带 `auto_create_todos` 或 `auto_todo` 时才创建待办，但默认注册仍使 PH→TD 自动化成为隐式集成能力，也容易被未来调用方误解为产品默认行为。

## 目标与非目标

- 目标：默认集成启动不启用 PH 自动创建/完成 TD 的行为。
- 目标：保留旧 handler 作为兼容能力，由明确的集成调用方显式开启。
- 目标：不影响 TD→TH 时间记录、统一查询、历史关联和存档迁移。
- 非目标：不删除已有关联字段，不重写 PH Plan 数据结构，也不把模块拆回独立应用。

## 设计决策

为 `register_all_handlers` 增加 `enable_plan_todo_automation=False` 开关。默认只注册 TH 相关联动；只有明确传入 `True` 的调用方才注册 `PlanTodoLinker`。返回值保留稳定键，未启用时使用 `None`，便于诊断当前集成能力。

## 验收条件

- 默认启动路径不订阅 `plan.created`、`plan.task_added` 等自动 PH→TD 事件。
- 显式 opt-in 路径仍能注册兼容 handler。
- 既有集成测试和全量测试通过。
