# 1126 构建与启动器验证

日期：2026-10-05  
类型：验证报告

## 背景与目标

此前直接在 PowerShell 执行 `npm run build` 时显示找不到 npm，容易误判为前端工具链缺失。本次按统一启动器的工具发现规则复核 Node/npm、生产构建和统一启动流程。

## 验证结论

- `scripts/check_build_environment.py` 正确发现 `F:\dev-tools\node\node.exe` 与 `F:\dev-tools\node\npm.cmd`；
- 启动器的 `node_environment()` 会把该目录加入子进程 `PATH`，现有 `tests/test_launcher.py` 已覆盖这一契约；
- 直接调用 `npm.cmd` 不会自动继承该目录，必须先将 `F:\dev-tools\node` 加入当前 shell 的 PATH；
- 统一启动器本身不依赖当前 shell 的 PATH，能够按自身规则启动前端与 PH companion。

## 实际验证

- `$env:PATH = 'F:\\dev-tools\\node;' + $env:PATH; npm run build`（目录：`time-helper/desk`）→ `vue-tsc` 与 Vite 构建通过，1877 modules；
- `python scripts/smoke_startup.py` → 前端就绪、PH 健康检查通过、端口已释放；
- `python -m pytest -q tests/test_launcher.py tests/test_startup_smoke.py` → 相关启动器测试通过；
- `python -m pytest -q` → `878 passed`；
- `python launcher/start.py --doctor` → 统一工作区可启动；Rust、Android SDK/ADB、iOS 工具链未安装，原生发布仍需 CI/发布机。

## 兼容性与边界

- 不改变启动器命令、端口、数据目录或前端代码；
- 当前验证覆盖开发/静态工作台和 PH companion，不等价于真实 Tauri 安装包验收；
- 当前存在的旧版本安装包与 `VERSION` 不匹配，不能作为 1.7.0 发布物；
- 主题保存后退出恢复问题仍按用户要求暂缓。
