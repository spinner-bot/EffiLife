# 0762 移动构建缓存键同步顺序修复

## 发现

上一轮已让手动 Android/iOS 构建在 `npm ci` 前同步版本和 lockfile，但 Node setup 仍位于同步之前。这样虽然安装阶段顺序正确，npm 缓存键仍可能基于旧 lockfile 计算，导致不必要的缓存失配。

## 处理

- 将 Android 和 iOS job 的 Node setup 移到版本同步之后。
- 现在两个移动构建 job 均按“Python → 版本/lockfile同步 → Node/npm缓存 → npm ci”的顺序执行。
- 增强 workflow 契约，验证同步位于 Node setup 和 `npm ci` 之前。

## 验证

- 通过 workflow 静态契约测试后执行全量 Python 测试。
- 未修改用户保护的 lockfile；CI runner 在 checkout 工作区内完成同步。
