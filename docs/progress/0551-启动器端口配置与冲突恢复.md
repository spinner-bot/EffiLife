# 1057 启动器端口配置与冲突恢复

日期：2026-10-02

## 问题

统一启动器默认使用工作台 `1420`、兼容待办 Web `1421` 和 plan-helper API `8765`。当旧开发进程或其他本地服务占用端口时，严格端口模式会直接失败；同时用户无法在不修改代码的情况下调整端口。

## 实现

- 增加 `EFFILIFE_WORKSPACE_PORT`、`EFFILIFE_TODOS_PORT`、`EFFILIFE_PLAN_HELPER_PORT` 三个环境变量。
- 端口统一经过 `1024-65535` 范围校验；缺失或非法值回退到原默认值。
- Vite、静态服务器、plan-helper sidecar、健康检查 URL 和诊断报告全部使用同一组有效端口。
- 保持默认端口不变，正式打包模式的 Tauri 二进制不受影响。
- `--diagnose` 报告增加实际生效端口，便于定位本地冲突。

## 验证

- 启动器端口专项测试及相关构建/CI 契约测试：`13 passed`。
- 后续执行 Python 全量回归和启动器 doctor 检查。

## 影响范围

提升开发启动、兼容入口和本地 sidecar 的可恢复性；不改变 TH、PH、TD 的职责边界或统一数据协议。
