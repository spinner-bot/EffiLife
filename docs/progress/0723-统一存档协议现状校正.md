# 1234｜统一存档协议现状校正

## 对早期报告的校正

`docs/进展报告/0003-T-2026-09-25-统一数据交换层首版.md` 记录的是交换层首版状态，其中“真实数据尚未接入交换包”已经过时。本报告保留历史记录，不修改历史结论，仅说明当前实现。

## 当前已实现

- 统一 `.efl` 存档由 `time-helper/desk/src/services/ArchiveService.ts` 生成和读取。
- canonical 数据集包含 `app`、`records`、`todos`、`todo_categories`、`plan_helper`，覆盖 TH、TD、PH 及应用配置。
- manifest、数据集大小、总大小、条目数量、路径名、JSON 结构和 SHA-256 校验均在导入前检查。
- 导入前提供预览，导入失败会回滚；导入后刷新模块存储和跨模块链接。
- 旧版 `archive.json` 存档仍可读取，并会规范化待办、记录、分类及 PH 关联。
- Python `common/data_exchange.py` 保持同一 canonical 数据集协议，供迁移/诊断脚本使用。

## 尚未宣称完成的能力

- 当前协议版本校验以兼容读取为主，尚未建立面向未来协议版本的通用 schema 迁移注册表。
- 当前导入是“预览后替换/恢复”流程，不提供两个本地工作区之间的逐条冲突合并界面。
- 因本机缺少 Rust/Cargo、Android SDK/adb 和 Xcode，尚未完成安装包级别的跨端迁移验收。

## 决策

在没有明确第二阶段协议变更和冲突语义前，不擅自引入自动合并规则，以免破坏 PH 嵌套组、任务编号和 TD/TH 引用。下一阶段应先定义 schema 迁移与冲突优先级，再实现并加入 `.efl` 版本回归样本。
