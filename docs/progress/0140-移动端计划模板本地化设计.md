# 移动端计划模板本地化设计

日期：2026-09-30

## 背景

桌面端通过 Plan Helper `/api/templates` 获取内置模板；移动端没有 sidecar，`listPlanTemplates()` 返回空数组，导致移动端只能手工创建计划。移动端已经支持完整的本地 Plan 快照编辑，因此模板能力应在本地补齐，而不是把 PH 与 TD 混合或把模板降级成待办列表。

## 目标

- 在移动端提供与桌面端相同的三个内置模板入口：工作日、休息日、备考冲刺。
- 模板创建结果仍严格写入 PH 原始结构：`head/main/log`、section、任务槽位和 group。
- 模板名称、说明和任务内容跟随统一 locale；不把可见文案硬编码到组件。
- 桌面端继续使用 PH 服务，保持服务端模板和自定义模板行为不变。

## 非目标

- 不在移动端复制 PH 的自定义模板文件系统或归档列表。
- 不把模板任务转换成 TD；只有用户明确选择关联时才创建 TD。
- 不修改原始 Plan 编号、软删除、分组嵌套或日志语义。

## 方案

在 `planGateway.ts` 中维护仅用于移动端的内置模板定义。定义只包含模板 ID、i18n key、时间和结构元数据；运行时通过 `translate()` 生成当前语言的内容。创建时先生成本地 Plan，再按模板的 section/group 顺序写入，最终通过统一的 `getPlanFull()` 返回编辑器。

移动端模板创建失败时不写入 TD，也不伪造桌面服务状态；桌面端代码路径保持原 API 调用。模板列表只在 `mobile-unavailable` runtime 使用本地定义。

## 验收条件

- 移动端模板列表返回三个内置模板且名称/说明双语一致。
- 选择模板后生成完整 Plan，而不是空计划或单条待办；section、任务时间、group 结构可见并可继续编辑。
- 现有桌面模板 API、统一存档、PH/TD 关联测试继续通过。
- 生产构建和全量回归通过。
