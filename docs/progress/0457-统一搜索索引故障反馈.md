# 统一搜索索引故障反馈

## 背景

统一搜索同时读取 TD 待办、PH 计划、归档计划和 TH 时间记录。此前使用 `Promise.allSettled` 后直接将失败数据当作空数组，服务暂时不可用时会表现为“没有搜索结果”，容易误导用户，也无法判断是数据为空还是读取失败。

## 本轮调整

- 区分四类核心索引源全部不可用与部分不可用两种状态。
- 全部不可用时显示明确的故障状态和重试入口。
- 部分不可用时保留可用数据的搜索能力，同时提示用户并提供重试入口。
- 重试开始时清理旧故障状态，避免重试期间继续显示过期提示。
- 增加中英文提示文案和源代码级回归测试。
- 不改变搜索结果路由、实体语义及跨模块数据结构。

## 验证

- 定向测试：22 passed
- 全量测试：722 passed
- 桌面端生产构建：`npm run build` 通过
- `git diff --check`：通过

## 边界

本轮只处理核心索引源的可见故障反馈；计划任务子索引仍按可用计划逐项加载，单个计划任务读取失败不会阻断其他领域的搜索。
