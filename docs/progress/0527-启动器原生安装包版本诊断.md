# 启动器原生安装包版本诊断

日期：2026-10-02

## 背景与发现

前端生产构建已经可以在本机真实完成，但启动器 `--doctor` 仍报告原生安装包为
`stale (version mismatch)`。经核对，仓库工作区确实存在旧的 Tauri NSIS 产物：

`time-helper/desk/src-tauri/target/release/bundle/nsis/浪兮效率时钟_1.0.11_x64-setup.exe`

该文件大小为 2,850,045 bytes，当前应用版本来自 `tauri.conf.json`，为 `1.7.0`。
因此这是旧构建产物残留，不是启动器、前端构建或工作区服务的启动故障。

## 目标与非目标

- 目标：让诊断结果能直接定位过期安装包，并显示产物版本与当前版本。
- 非目标：不自动删除、覆盖或移动本地安装包；不把旧产物误当成可发布版本。
- 非目标：不改变启动器选择开发模式、打包模式和统一工作区的既有逻辑。

## 实施内容

1. `print_doctor_report` 在检测到过期安装包时追加文件路径、产物版本和当前版本。
2. 保留原有机器可读诊断字段 `artifact_version`、`version_matches` 和既有状态文本，避免破坏脚本兼容性。
3. 增加启动器诊断回归测试，覆盖过期安装包详情输出。

## 兼容性与安全边界

- 旧文件仍保留在本地，用户可自行决定是否清理或重新构建。
- 文件名无法解析版本时仍按原有规则视为可接受的未知版本，不改变既有行为。
- 诊断仍是只读操作，不会触发安装、构建或删除。

## 验证

已验证：

```text
python -m pytest tests/test_launcher.py -q

```

已知真实环境状态：当前版本 `1.7.0`；本地 NSIS 产物 `1.0.11`；启动器应继续提示
需要重新构建安装包后再分发。旧安装包未被删除。
