# 文档编号体系全面纠正

状态：[完成]

日期：2026-10-12

作者/执行者：Codex

## 触发原因

设计方案和进展报告后期出现编号跳变、重复编号以及不同文档体系编号混用的问题。审计确认，部分编号沿用了批次或并行开发序列；当前进展规范还错误地写成了“六位递增编号”。

## 目标与实际完成

- 保留阶段 `0`，不新增阶段。
- 保留三个独立文档体系，不合并编号池。
- 将每个体系内部的普通文档重排为连续四位序列号。
- 保留日期信息在原文件名的独立信息块中，不把日期或时间戳当作编号。
- 更新仓库内已发现的旧文档路径引用和设计文档首行编号。

以上目标均已完成。

## 编号结果

| 文档体系 | 规范文件 | 普通文档编号 |
| --- | --- | --- |
| `docs/设计方案` | 无单独 `0000` 文件 | `0001–0372` |
| `docs/进展报告` | `0000-报告与文档管理规范.txt` | `0001–0444` |
| `docs/progress` | `0000-进展报告规范.md` | `0001–0810` |

三个体系分别编号；历史目录 `docs/进展报告` 不与当前目录 `docs/progress` 合并。后续新增进展只写入 `docs/progress`，接续 `0810` 使用 `0811` 及后续序列。

## 变更范围

- 重排三个文档目录内的文件名前缀，共 1386 个文件发生编号迁移。
- 更新 45 个文本文件中的旧文档路径引用。
- 更新 161 个设计文档首行中的旧编号。
- 修正规范文件对阶段、四位序列号和三个独立文档体系的描述。
- 增加 `scripts/normalize_doc_numbering.py`，保留本次迁移的可复现规则和双阶段重命名逻辑。

## 验证

执行：

```powershell
python scripts/normalize_doc_numbering.py --mapping-out .doc-numbering-map.json
```

结果：迁移后再次执行时无新增重命名，说明编号已经稳定。

目录连续性检查结果：

- `docs/设计方案`：372 个普通文档，`0001–0372`，无重复、无跳号。
- `docs/进展报告`：444 个普通文档，`0001–0444`，无重复、无跳号；`0000` 规范文件保留。
- `docs/progress`：810 个普通文档，`0001–0810`，无重复、无跳号；`0000` 规范文件保留。
- 阶段前缀均为 `0`；未新增阶段。
- 用户未提交的 `plan-helper/test.py`、`time-helper/desk/src-tauri/Cargo.toml` 和 `plan-helper/ph导出txt示例.txt` 未纳入本次变更。

## 风险与后续

编号迁移会改变文档路径，因此已同步仓库内检测到的路径引用；历史正文中仅写作普通数字的叙述不作语义替换，避免篡改历史事实。后续新增报告不得重新使用旧编号，也不得从日期、时间戳或其他目录复制编号。
