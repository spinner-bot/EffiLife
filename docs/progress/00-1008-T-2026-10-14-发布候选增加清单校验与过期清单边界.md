## 发现

复核发布清单时，发现仓库外生成的 `release-checksums/EffiLife-windows-nsis.manifest.json` 记录的安装包大小为 11,596,552 bytes，而当前 NSIS 安装包为 11,604,189 bytes，清单不能作为当前产物证据。该差异属于过期构建清单，不应静默放行。

## 本次实现

- 为 `scripts/verify_release_candidate.py` 增加可重复的 `--verify-manifest <清单> <目录> <target>` 参数。
- 复用清单校验器验证 schema、产品、版本、target、相对路径、文件大小和 SHA-256。
- 在 JSON 结果中分别记录安装包校验和清单校验是否显式执行。
- README 补充清单校验调用方式。
- 未修改过期的生成物清单，也未把本地构建产物混入源代码提交。

## 验证结果

- `python -m pytest -q tests/test_release_candidate_script.py`：2 passed。
- 当前 NSIS 安装包直接校验：通过。
- 当前构建目录 `release-manifest-current.json` 校验：通过，target 为 `windows-x64-nsis`，大小和 SHA-256 均匹配。
- 过期 `release-checksums` 清单被单独识别为不匹配，没有被当作有效发布证据。

## 结论

发布候选现在可以同时验证安装包和机器可读清单，并明确区分“过期清单”和“当前构建证据”。阶段保持第 0 阶段。
