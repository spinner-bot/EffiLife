# 启动器诊断区分开发与分发就绪

日期：2026-10-09

## 背景

启动器的 `--doctor` 已能发现正式安装包不存在、过期或版本不匹配，但此前在开发环境可以启动时仍只输出 `Result: READY`。这容易让人误以为当前版本已经具备正式分发条件。

## 目标与非目标

目标是明确区分“当前工作区可以启动”和“正式安装包可以分发”两种状态，并让机器可读诊断结果提供对应字段。

本次不自动构建安装包、不改变启动流程，也不宣称已完成 Windows/Linux/macOS 安装包或移动端设备验收。

## 影响范围

- `launcher/start.py`：诊断结果与人类可读输出。
- `tests/test_launcher_startup_hints.py`：启动器诊断契约。

## 实现

`collect_diagnostics()` 新增：

- `launch_ready`：开发启动所需检查是否通过。
- `distribution_ready`：是否存在版本匹配且非空的可用安装包。

`print_doctor_report()` 保留阻塞状态的 `Result: BLOCKED`，在开发启动可用但分发未就绪时输出 `Launch status: READY` 与 `Result: READY (development launch; distribution status shown above)`，避免把两个状态混为一谈。

## 兼容性

旧调用仍使用布尔返回值表示启动器是否被阻塞；新增字段只扩展 `--diagnose` 的 JSON 结果。现有模块启动、端口检查和发布门禁逻辑不变。

## 验证

已执行：

```text
python -m pytest -q tests/test_launcher.py tests/test_launcher_startup_hints.py
# 79 passed in 5.59s

python -m pytest -q
# 927 passed in 19.87s

python launcher/start.py --doctor
# Launch status: READY
# Result: READY (development launch; distribution status shown above)
# Distribution status: not ready; build a version-matched installer before shipping
```

## 未验证项与边界

- 当前机器仍缺少 Rust/Cargo，不能据此完成真实 Tauri 安装包构建。
- 现有旧安装包版本与当前桌面版本不一致时，诊断应明确显示分发未就绪。
- 尚未进行真实安装、升级、签名或 Android/iOS 设备验收。
