# CI 测试失败诊断输出增强

## 基本信息

- 日期：2026-10-14
- 执行者：Codex
- 所属阶段：第 0 阶段（阶段未递增）
- 类型：持续集成可维护性修复

## 背景

`EffiLife CI` 在 GitHub Actions 上持续失败于全量 Python 测试，但匿名 API 只能返回失败步骤，无法读取 job 原始日志；当前失败后上传的诊断文件只包含启动器环境信息，不能证明哪个测试失败。这使继续修复会退化为猜测和重复回归。

## 实施内容

- 将 CI pytest 命令改为 `--maxfail=1 -ra`，尽快暴露首个失败用例及摘要。
- 使用 `tee pytest-failure.log` 保留完整 pytest 输出，同时保持非零退出码传递给 CI。
- 将 pytest 日志与已有启动器诊断一并上传到失败 artifact。
- 保持全量测试门禁、集成测试、启动烟测和发布契约顺序不变。

## 验证

- 本地 `python -m pytest -q`：1179 passed，1 warning。
- 本地 `python scripts/run_integration.py test`：55/55 passed。
- 本地发布配置与移动边界检查：通过。
- 工作流契约测试需在提交后随全量套件验证；远端 artifact 可读取性需以新的 GitHub Actions run 为准。

## 边界

- 本次没有忽略测试、降低门禁或将失败改成成功。
- 该提交只增强证据链，不能单独宣称远端 CI 根因已修复。
- 阶段保持第 0 阶段，未创建分支，直接提交 `main`。
