# 0874－CI 依赖审计稳定性

类型：T（发布链路与工程可靠性）  
日期：2026-10-13  
阶段：0  
执行者：Codex  
状态：已完成

## 1. 触发原因

GitHub Actions 曾出现运行失败通知。按 CI 原路径复现时，兼容性 `to-dos/ui` 的 `npm audit --audit-level=high` 在本地 npm 10.8.2 上向 npm 审计服务提交已安装依赖树，返回 400（Invalid package tree），导致安全审计步骤失败；这不是应用依赖存在高风险漏洞。

## 2. 目标与完成情况

- 将 CI 审计目标固定为提交物 `package-lock.json`，使用 `npm audit --audit-level=high --package-lock-only`；
- 保留 high 级别漏洞门禁，不通过删除审计或忽略错误来规避失败；
- 增加 CI 工作流契约测试，防止审计命令回退到不稳定的已安装树模式；
- 保持 `npm ci`、兼容性 UI 构建和现有发布流程不变。

## 3. 变更文件

- `.github/workflows/ci.yml`
- `tests/test_ci_workflow.py`

## 4. 验证

- `npm audit --audit-level=high --package-lock-only`（`to-dos/ui`）：通过，`found 0 vulnerabilities`。
- `python -m pytest tests/test_ci_workflow.py tests/test_todos_ui_dependencies.py tests/test_todos_ui_build_entrypoint.py -q`：10 passed。
- `python scripts/build_todos_ui.py`：通过，Vite 转换 1768 个模块。
- 未验证项目：GitHub 托管 runner 的实际执行；需要下一次 push 后观察 workflow 状态。

## 5. 风险与下一步

npm registry 审计服务仍属于外部依赖，若服务不可用，CI 仍可能失败；本次只消除了已安装树的跨平台不稳定输入。下一步在推送后检查 CI workflow，并继续补齐桌面安装升级与真实设备验收证据。
