# [完成] TH 存储边界删除补偿

## 背景

上一轮已修复三个界面删除入口的操作顺序，但 `DataService.deleteRecord` 与 `deleteRecordById` 仍可能由其他调用方直接触发。原实现先提交 TH 删除，再清理 TD 反向引用；跨存储写入失败时会留下部分完成状态。

## 实现

- TD 反向引用清理改为失败即抛出，不再把异常降级为 warning。
- 多个 TD 反向引用清理过程中发生失败时，恢复本轮已经修改的 TD 条目。
- `deleteRecord` 与 `deleteRecordById` 在反向引用清理失败时恢复原 TH 记录，并将异常交给上层处理。
- 备份和兼容镜像写入移动到跨模块清理成功之后，避免为未完成删除生成成功快照。
- 增加存储边界契约测试，确保保留补偿写入和禁止静默失败。

## 验证

- TH/TD 删除与引用专项：`14 passed`。
- 桌面端生产构建：Vite `1879 modules`，成功。
- 全量 Python 回归将在提交前再次执行。

## 边界

当前仍采用跨 IndexedDB store 的补偿式事务，而非单个多 store 原生事务；如果恢复 TD 或 TH 的补偿写入再次失败，会保留原始错误并记录回滚错误，后续启动修复流程继续作为兜底。真实浏览器故障注入仍是发布前验收项。
