# 0872－PH 确认态防重复提交

类型：T（用户路径与操作可靠性）  
日期：2026-10-13  
阶段：0  
状态：已完成

## 1. 问题

PH 归档、删除区段、删除分组、删除任务和批量建立 TD 关联都需要确认弹窗。原实现是在等待确认返回后才设置 `isLoading`，用户快速点击时可以同时打开多个确认弹窗；多个确认均通过后，会产生重复归档、重复删除请求或重复 TD 关联操作。

## 2. 实现

- 增加统一 `confirmationPending` 状态和 `confirmPlanAction` 门控。
- 确认弹窗打开期间拒绝第二个 PH 确认操作，并在 `finally` 中释放状态，保证异常时也能恢复。
- 归档、区段删除、分组删除、任务删除和批量 TD 关联全部使用统一门控。
- 相关按钮在确认期间显示禁用状态；原有持久化队列、错误提示和确认语义保持不变。

## 4. 边界

本次防止的是同一 PH 工作区内的重复确认与重复提交，不改变 PH 计划数据结构、任务编号、嵌套组语义或 TD 独立数据模型。阶段保持第 0 阶段。
