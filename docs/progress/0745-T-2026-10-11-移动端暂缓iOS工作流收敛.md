# 移动端暂缓 iOS 工作流收敛

日期：2026-10-11

## 背景与发现

当前项目已明确暂不推进 iOS，但 `.github/workflows/tauri-mobile-build.yml` 仍提供 `all`/`ios` 选项，并在 `all` 下启动 macOS iOS 构建。该配置与当前阶段决策不一致，误触发时会产生无意义的失败通知和资源消耗。

## 目标与非目标

- 目标：让手动移动端发布工作流只提供当前已推进的 Android 构建入口，并保持 Android 产物校验、校验和、manifest 和 artifact 上传链路完整。
- 非目标：不删除 iOS 的 npm 脚本、平台检测器、Tauri 配置或未来实现所需的测试基础；不宣称 iOS 已完成或已验证。

## 影响范围

- `.github/workflows/tauri-mobile-build.yml`：仅保留 Android job，默认目标改为 Android，移除 iOS 触发选项。
- `tests/test_mobile_workflow.py`、`tests/test_workflow_version_sync.py`：契约改为验证 Android-only 工作流。
- 不改变应用运行时、统一数据格式或 PH/TD/TH 业务逻辑。

## 实施内容

- 将 workflow_dispatch 的默认目标从 `all` 改为 `android`。
- 移除 `ios` 选项和整个 iOS 构建 job，Android job 只在 `inputs.target == 'android'` 时运行。
- 保留 iOS 构建命令和脚本在 `package.json`、发布预检与测试体系中，待未来重新启用时仍有基础，不将“暂缓”误做成不可逆删除。
- 更新 workflow 契约测试，防止 iOS job 或 iOS 产物步骤被意外重新加入当前发布入口。

## 兼容性与迁移

- 现有 Android 手动触发方式保持不变，可选择 `android` 并生成 APK、校验和及发布 manifest。
- 旧的 `ios`/`all` 手动输入不再是有效选项；这是有意的阶段边界收敛，不影响桌面端和 Android 端。

## 验证命令与结果

```powershell
# 17 passed

# 996 passed in 20.42s
```

## 未验证项与后续事项

- 本地 Windows 不执行 Android APK 的完整打包；该链路由具备 Android SDK/NDK 的 CI 手动工作流负责真实构建。
- iOS 保持暂缓，未来恢复时需重新评估 macOS 工具链、签名和设备验收，不得仅恢复 workflow 文本就视为完成。
