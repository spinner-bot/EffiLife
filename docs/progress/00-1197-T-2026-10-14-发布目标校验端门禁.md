# 00-1197-T-2026-10-14 发布目标校验端门禁

## 类型与阶段

T（发布链路实现）。当前仍为第 0 阶段；本报告只递增序列号，不增加阶段。

## 背景

上一轮已在 manifest 生成端拒绝旧的发布目标名，但独立 verifier 仍可能被调用方传入任意目标字符串。生成与校验的目标契约需要保持对称，才能防止手工验收或未来脚本修改绕过规范。

## 实现内容

- 在 manifest verifier 中复用同一组规范目标；
- 传入旧目标或未知目标时立即失败；
- manifest 自身包含非规范目标时也立即失败；
- 增加 verifier 回归测试，覆盖 `windows-x64-nsis` 旧目标名；
- 不改变当前桌面、Linux、macOS 和 Android 发布矩阵。

## 验证

- 发布相关定向测试：`37 passed`；
- 全量 Python 测试：`1285 passed`。

## 结论

发布 manifest 的生成端和验证端已经使用同一规范目标集合，目标命名漂移会在发布链路早期失败。阶段保持第 0 阶段。
