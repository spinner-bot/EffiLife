# 00-1154-T-2026-10-14 版本化存储迁移标记

## 类型与阶段

T（技术实现）。当前仍为第 0 阶段；本报告只递增序列号，不增加阶段。

## 背景与问题

统一工作台已经把旧版 localStorage 数据迁移到 IndexedDB，但迁移完成标记原先只有布尔值 `true/false`。这对首次迁移足够，却无法支持后续产品升级：一旦未来增加第 2 版存储迁移，已经写入 `true` 的用户会被永久判定为“迁移完成”，新迁移逻辑不会执行。

## 实现

- 将迁移完成标记改为整数版本号，当前版本为 `1`。
- 保留旧用户兼容：历史值 `true` 按迁移版本 `1` 解释。
- 非法、空值和负数标记按版本 `0` 处理，允许重新执行迁移。
- `isMigrationDone()` 改为比较已存版本与当前版本，为后续追加迁移版本预留入口。
- 暴露 `getStoredMigrationVersion()`，便于启动诊断和未来升级提示读取当前状态。
- 当前版本迁移完成后写入字符串 `"1"`，不改变现有各数据表的迁移顺序、备份和失败重试策略。

本次没有改变 PH 数据结构、TD/PH 领域边界或归档协议；这是升级基础设施改进，不是对已有业务数据的重写。

## 后续边界

当确实需要新的存储 schema 时，应新增版本号和对应迁移步骤，并在迁移前保留可恢复备份；不能仅修改当前常量而跳过数据转换和回滚验证。
