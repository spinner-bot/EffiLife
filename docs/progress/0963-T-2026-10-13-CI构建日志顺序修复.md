# [完成] CI 构建日志顺序修复

## 问题

桌面统一前端和兼容 UI 的 Python 构建脚本会先启动 npm 子进程，再因标准输出缓冲延后打印构建上下文。CI 日志中因此可能出现构建产物输出早于“构建目标/工作目录”，降低失败定位效率。

## 实现

- `scripts/build_frontend.py` 和 `scripts/build_todos_ui.py` 的构建上下文日志改为立即 flush。
- 增加契约测试，确保后续脚本修改不会丢失该诊断行为。

## 验证

- 统一前端构建脚本：成功，Vite 1879 modules。
- 兼容 UI 构建脚本：成功，Vite 1768 modules。
- 全量回归与发布门禁在本轮提交前复核。
