# 1146 主存储与兼容镜像写入隔离

日期：2026-10-05  
类型：统一数据可靠性修复

## 背景与问题

`DataService` 使用 IndexedDB 作为统一工作区的主存储，同时写入 `localStorage` 兼容旧版本和恢复路径。此前兼容镜像写入失败会让整个保存方法抛错，但 IndexedDB 已经完成写入；上层因此可能回滚内存状态，重启后又读取到新值，形成“当前界面与持久化数据不一致”。

## 实现

- 新增 `writeLegacyMirror`，集中处理兼容镜像写入。
- IndexedDB 写入仍是成功条件；兼容 `localStorage` 写入失败只记录警告，不否定主写入。
- 配置、计划、日程规则、手动计划和时间记录的保存路径全部采用该隔离策略。
- 保留原有 JSON 镜像格式和 IndexedDB 不可用时的读取回退，不改变数据结构或导入导出协议。
