# 1326-T：跨运行时 JSON 数值规范化

## 元信息

- 日期：2026-10-12
- 类型：统一存档协议 / 数据完整性
- 状态：已完成
- 关联：`effilife.bundle`、Python 数据交换层、前端 `ArchiveService`

## 问题

统一存档通过 dataset JSON 字节计算 SHA-256。前端使用 `JSON.stringify`，Python 使用 `json.dumps`；两者对数值的文本表示并不完全相同。例如 JavaScript 将 `1.0` 和 `-0.0` 序列化为 `1` 和 `0`，而 Python 默认会保留为 `1.0` 和 `-0.0`。这会让合法的 Python 导出包在前端导入时出现 checksum mismatch。

## 修复

1. Python 数据交换层新增 canonical JSON 值归一化。
2. 整数浮点数统一写成整数，负零统一写成 `0`。
3. 拒绝 NaN 和 Infinity，避免生成无法被标准 JSON/前端一致解析的 bundle。
4. 保留对象键排序、UTF-8 和双字节缩进规则，与前端 canonical serializer 对齐。
5. 增加数值拼写和非有限数回归测试。

## 验证

- Python canonical JSON 输出与 JavaScript `JSON.stringify` 的数值表示一致。
- 非有限数在写包前被拒绝，不产生半成品文件。
- 全量测试将在提交前执行。

## 兼容性边界

该修复只改变 bundle 的 canonical 序列化字节，不改变 TH 记录、PH plan 结构、嵌套组、软删除编号或 TD 待办字段；读取已有合法 JSON 数据的语义保持不变。
