# 兼容待办构建门禁设计

## 背景

统一工作台已经承载 to-dos 的主要能力，但旧 to-dos Web 仍作为迁移和兼容入口保留。桌面发布 workflow 原先只构建统一前端，兼容入口可能在独立回归中失效而未被发布门禁发现。

## 方案

- 在发布 workflow 增加独立 `compatibility` job。
- 使用 `to-dos/ui/package-lock.json` 执行 `npm ci`，再执行 `npm run build`。
- 不把兼容 UI 打进正式 Tauri 安装包，继续保持统一工作台为日常入口。
- 发布预检和契约测试同时检查该 job 存在，保证三模块的兼容边界持续可构建。
