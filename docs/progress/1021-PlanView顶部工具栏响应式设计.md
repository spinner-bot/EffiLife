# 1021 PlanView 顶部工具栏响应式设计

## 日期

2026-10-02

## 背景

TH 的 PlanView 顶部同时包含返回入口、两个工作区 Tab 和新增记录按钮。当前工具栏固定为单行 flex 布局，在窄桌面窗口和平板横向窗口中，Tab 可用宽度会被压缩，按钮和文字存在挤压或溢出的风险。这与 HOTL-1 要求桌面/平板充分利用横向空间、并避免控件堆叠的目标不一致。

## 目标与非目标

- 目标：保证顶部控件在窄桌面和平板宽度下仍可完整操作，保持桌面端横向层级。
- 目标：在移动宽度下把 Tab 独立放到下一行，保留足够的触控宽度。
- 非目标：不改变 TH/PH/TD 的路由、数据结构、计划记录语义或主题变量。

## 设计决策

- 工具栏允许换行，但返回按钮和新增操作仍保持在第一行。
- Tab 在移动断点下占满第二行，两个选项均等分可用宽度。
- Tab 容器设置 `min-width: 0`，避免 flex 子项以内容宽度反向撑破窗口。
- 使用现有主题 Token 和断点，不引入硬编码颜色或新的交互模式。

## 验收条件

- 源码契约能证明工具栏具备换行、Tab 可收缩和移动端独立整行布局。
- Python 全量测试通过。
- 前端构建在具备 Node/npm 的 CI 环境执行；当前本地环境尚未提供 Node/npm。
