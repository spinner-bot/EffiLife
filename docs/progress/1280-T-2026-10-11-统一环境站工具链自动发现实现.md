# 统一环境站工具链自动发现实现

## 1. 背景

工作站已按统一环境站约定将 Node、Rust 和 Android SDK 放置在 `F:\dev-tools`。但启动器和构建环境检查器只依赖当前进程的 PATH 与 Android 环境变量，导致实际可用的 Cargo、Rustc 和 ADB 被报告为缺失。PATH 中的 Cargo 还是 rustup 代理，在未设置默认 toolchain 时不能正常执行；稳定版 toolchain 的真实二进制已经存在。

## 2. 本次目标

- 启动器诊断自动识别统一环境站中的稳定 Rust toolchain。
- 构建环境检查器使用同一套发现规则，避免“启动器说可用、构建检查说缺失”或相反。
- 自动识别统一环境站 Android SDK 的 `adb` 与 SDK 根目录。
- 保留 `EFFILIFE_RUST_TOOLCHAIN_DIR`、`ANDROID_HOME`、`ANDROID_SDK_ROOT` 等显式配置优先级。
- 不移动、不覆盖、不修改系统级开发环境。

## 3. 实现范围

### 3.1 启动器

`launcher/start.py` 新增统一环境站 Rust/Android 路径发现：

- Rust 默认查找 `F:\dev-tools\rustup\toolchains\stable-x86_64-pc-windows-msvc\bin`。
- Android 默认查找 `F:\dev-tools\android-sdk` 及其 `platform-tools\adb.exe`。
- 显式环境变量存在时优先使用显式路径。
- 诊断输出增加 Android SDK 根目录，方便定位实际使用的工具链。

### 3.2 构建环境检查器

`scripts/check_build_environment.py` 与启动器采用同样的 Windows 管理工具链兜底路径，并将统一 Android SDK 作为无环境变量时的可用根目录。这样桌面和 Android 检查可以在当前工作站直接复现真实环境状态。

### 3.3 回归测试

补充了管理 Rust toolchain 的自动发现测试；原有“模拟缺失工具链”的测试改为显式隔离统一环境站路径，避免测试环境被真实机器状态污染。


桌面 Rust `cargo check` 已在 Visual Studio x64 开发者环境中使用统一 toolchain 完成：

```text
Finished `dev` profile [unoptimized + debuginfo] target(s) in 2m 04s
```

普通 PowerShell 会话仍需要先加载 `D:\VisualStudio\Packages\VC\Auxiliary\Build\vcvars64.bat`，否则 Cargo 会因缺少 MSVC C/C++ 编译环境而失败；这属于编译会话初始化，不是 Rust 或项目依赖缺失。

## 5. 边界与未完成项

- 本次没有启用 iOS 检查或构建，遵循当前项目暂不推进 iOS 的范围。
- 环境自动发现不等同于发布包已在所有平台完成安装验收；Linux/macOS 仍需各自发布机验证。
- 历史系统环境没有被迁移或删除。
