# PH 空计划全屏编辑设计

日期：2026-09-30

## 背景

`docs/req/7[ph][td]-优化.txt` 要求创建计划时只填写名称和日期，先生成空白 Plan，再进入全屏编辑。当前创建弹窗还混入首个 section、任务、用时、TD 关联和模板选择，信息密度高且把“创建计划”和“编辑计划”两个阶段混在一起。

## 设计方向

采用 Linear 风格的工作台分层：创建弹窗是短流程入口，只承担身份信息；创建成功后进入 Plan 详情工作台，由 section、任务、分组、执行记录和 TD 关联工具分别承担编辑职责。弹窗保留明确的标题、说明、名称、日期、取消和创建按钮，默认日期为当前本地日期。

## 行为决策

- PH 创建弹窗只显示名称与日期两个输入项。
- 提交后调用 `createEventPlan(name, date)` 创建 `head/main/log` 完整但 `main` 为空的 Plan。
- 成功后自动关闭弹窗、加载新 Plan，并路由到全屏详情编辑视图；用户可立即添加 section 和任务。
- 模板创建 API 与移动端本地模板定义继续保留，作为服务层能力；本次不在基础创建弹窗中混入模板流程，避免改变“从零创建”的语义。
- `createTodos` 不再属于创建阶段；TD 关联继续通过详情页的“关联全部待办/关联单项任务”显式触发，保持 PH 与 TD 的独立定位。

## 非目标

不改变 Plan 的编号、空 section、嵌套 group、软删除、log 或归档语义；不引入日历；不改变 TD 数据结构和同步协议。

## 桌面与移动布局

桌面端详情工作台继续使用横向分区；移动端详情编辑器按单列排列。创建弹窗仅做窄而短的身份表单，避免在小屏中滚动填写计划内容。

## 验收标准

- 创建弹窗源码只包含名称、日期、取消、创建四类核心控件。
- 空计划创建后 `selectedPlan.sections.length === 0`，并进入 `view === 'detail'`。
- 详情页仍可新增 section、task、group、log，并能显式关联 TD。
- 中英文文案完整，定向契约测试与全量 Python 回归通过。
