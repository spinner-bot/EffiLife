# 发布安装包真实构建与历史构件过滤

## 1. 背景

使用 Windows 原生构建包装脚本真实构建当前版本后，NSIS 输出目录同时存在新 EffiLife 安装包和旧品牌历史安装包。发布验证器会扫描目录中的全部 `.exe`，因此把历史文件的版本差异误报为当前发布失败。

## 2. 实现

- 使用 `scripts/build_windows_native.ps1 -Action build -Bundle nsis` 完成 sidecar、Vue 前端、Tauri release 和 NSIS 安装包的完整链路。
- 修正 `scripts/verify_release_artifacts.py`，默认只验证当前产品名前缀 `EffiLife` 的非空构件。
- 保留历史构件，不删除、不移动、不修改。
- 增加旧品牌安装包与当前 EffiLife 安装包共存时的验证回归测试。

## 3. 验证

本次实际生成：

```text
time-helper/desk/src-tauri/target/release/bundle/nsis/EffiLife_1.7.0_x64-setup.exe
SHA-256: EDE611DA402D19929C95A670947F98A072DAEBA0148AA474FD1FB83D98DA7635
```

修正后应使用：

```text
python scripts/verify_release_artifacts.py --directory time-helper/desk/src-tauri/target/release/bundle/nsis --extension .exe --version-file time-helper/VERSION
```

该命令只验证当前 EffiLife 构件，不再被旧品牌文件阻断。完整 Python 回归与本轮新增验证器测试将在提交前执行。

## 4. 边界

本次只改变发布验证器的文件筛选范围，不改变安装包内容、不删除历史文件，也不替代签名、安装、升级和真实设备验收。
