## 触发原因

统一 `.efl` 文件基于 ZIP。ZIP 允许同一路径出现多个条目；如果导入器分别使用名称查找和顺序读取，重复数据集可能产生歧义，破坏清单、校验和与实际导入内容的一致性。

## 完成情况

- Python 交换层在读取 manifest 前枚举 ZIP 条目并拒绝重复文件名。
- 数据集文件存在性检查复用同一份已验证条目名称。
- 增加重复条目回归测试。
- 未改变正常 `.efl` 导出格式和旧版缺省校验和兼容行为。

## 变更文件

- `common/data_exchange.py`
- `tests/test_data_exchange.py`

## 验证

专项数据交换测试和全量 Python 回归将在提交前执行；重复条目输入必须以明确错误拒绝，不得进入模块存储。

## 风险与下一步

风险为低：仅收紧非法 ZIP 输入。浏览器端 JSZip 路径仍按现有清单与数据集边界解析，后续若升级归档协议，应继续保持两端对重复/未知条目的策略一致。
