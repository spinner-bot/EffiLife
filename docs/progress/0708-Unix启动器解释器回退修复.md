# 1214｜Unix 启动器解释器回退修复

日期：2026-10-10  
状态：已完成并推送

## 背景与目标

为后续桌面与移动端开发环境提供一致的测试入口，Unix 启动脚本不应假定系统一定存在可用的 `python3` 命令。本次与 Windows 启动器保持同一解释器选择语义。

## 实施内容

1. 默认优先选择可执行且能成功导入 `sys` 的 `python3`。
2. `python3` 不存在或不可用时，回退到同样经过探针验证的 `python`。
3. 两者都不可用时输出明确诊断并以退出码 `127` 结束。
4. 显式设置 `EFFILIFE_PYTHON` 的行为保持不变。

## 验证

- 启动器定向测试：`81 passed`。
- 全量 Python 测试：`962 passed`。
- Windows 本机无 `bash`/`sh`，POSIX 原生语法检查未执行，待 Unix CI 或实际 Unix 环境验证。

## 边界

本修复增强的是统一测试/开发启动器，不改变正式 Tauri 应用的原生启动路径。
