# Windows 原生构建环境包装实现

## 1. 背景

统一环境站中的 Rust、Node 和 Visual Studio MSVC 均已存在，但普通 PowerShell 会话没有加载 MSVC 环境变量。直接执行 Tauri Cargo 检查时，Rust 编译会在 C/C++ 构建脚本阶段失败；每次手工打开 Developer PowerShell 也不利于复现。

## 2. 实现

新增 `scripts/build_windows_native.ps1`：

- 使用 `vswhere.exe` 定位带 `Microsoft.VisualStudio.Component.VC.Tools.x86.x64` 的 Visual Studio；
- 调用 `vcvars64.bat -arch=x64`，将 MSVC 环境导入当前脚本进程；
- 接入 `F:\dev-tools` 中的 Rust stable toolchain 和 Node，且支持 `EFFILIFE_RUST_TOOLCHAIN_DIR`、`EFFILIFE_NODE_DIR` 覆盖；
- `-Action check` 执行桌面 Tauri Cargo 检查；
- `-Action build -Bundle nsis|msi` 执行 Windows Tauri 安装包构建；
- 不安装、移动或修改系统级开发环境。

README 已加入使用命令，测试覆盖 VS/MSVC 初始化、工具目录覆盖和 check/build 边界。

## 3. 验证

```text
python -m pytest -q tests/test_native_build_script.py

```

此前的全量 Python 回归为 `1001 passed`；本轮新增脚本后将继续执行启动器、环境检查和全量回归。

## 4. 边界

- 该脚本面向 Windows 本地原生验证与构建，不替代 GitHub Actions 的跨平台发布矩阵。
- iOS 仍按当前范围暂缓。
- 安装、升级覆盖、签名和真实 Android 设备验收仍需对应发布/设备环境。
