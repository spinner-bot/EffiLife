# TD 兼容入口编号唯一性修复

## 背景

统一工作台使用自己的稳定待办编号生成器；但旧版 `to-dos/ui` 兼容入口仍按当前数组长度生成 `TODO-YYYYMMDD-XXXX`。删除任务后，数组长度下降，下一次创建可能复用仍存在的编号，破坏跨模块迁移和引用的唯一性。

## 本次调整

- 兼容入口按当天已有 `TODO-YYYYMMDD-序号` 的最大序号递增生成新编号。
- 不再使用数组长度作为编号来源。
- 保留旧版编号格式，既有数据无需迁移。
- 仅修复 TD 兼容入口自身的编号算法，不改变统一 TD 数据模型，也不绑定 PH 的任务编号。

## 验证

- 增加 Python 静态契约测试，防止回退到数组长度算法。
- 计划执行 `to-dos/ui` 的生产构建验证 TypeScript 编译。
