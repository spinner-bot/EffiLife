# 1013 主题配置统一持久化边界

## 背景

主题编辑器已经具备实时预览、退出确认和持久化回读校验，但此前只有设置页主动调用了 `normalizeConfig`。其他配置写入入口仍可能把不完整的旧配置直接写入存储，导致丰富主题的其他配置段在重启后退回默认值。

## 变更

- `appStore.saveConfig` 在更新 Pinia 状态和调用持久化服务前统一规范化配置。
- `DataService.saveConfig` 在 IndexedDB、localStorage 和备份触发前再次规范化，形成最终防线。
- 保留所有主题段的合并默认值，避免部分配置覆盖整个 rich-theme 配置。

## 设计边界

- 不改变主题选择、实时预览或退出确认行为。
- 不增加新的保存按钮；主题仍通过退出确认流程保存。
- 同一规范化结果用于内存状态、IndexedDB、localStorage 和备份，降低多端/多窗口差异。
