# 0738 启动器统一工作区诊断复验

日期：2026-10-01

## 背景

统一启动器需要同时区分开发态工作区、兼容 plan-helper companion 和正式安装包，避免旧安装包或 debug 构件被误认为当前发布物。

## 目标与非目标

目标是用当前工作树真实运行 `--diagnose` 和 `--doctor`，确认统一前端、PH 服务、版本信息和旧安装包提示均可解释。

非目标是把开发态启动当成 Tauri 安装包验收，也不删除仓库中用于诊断的旧构件。

## 实测结果

- 命令：`python launcher/start.py --diagnose`
  - `launch_mode`：`development`
  - 统一工作区端口 `1420`：`service_ready: true`
  - plan-helper API `8765`：`service_ready: true`
  - `issues`：空
  - 提示旧安装包 `1.0.11` 与当前 `1.7.0` 不匹配
- 命令：`python launcher/start.py --doctor`
  - 输出 `Unified workspace: already running`
  - 输出 `plan-helper API: ready`
  - 输出 `Blocking issues: none`
  - 输出 `Result: READY`

## 影响范围

仅验证 launcher 诊断和当前本地开发服务状态，不改变 TH、PH、TD 数据及存档协议。

## 验证等级与边界

本次属于已验证的开发态运行证据。旧安装包提示属于信息级诊断，不是当前发布成功证据；真实 Tauri 安装、升级和卸载验收仍需发布环境完成。
