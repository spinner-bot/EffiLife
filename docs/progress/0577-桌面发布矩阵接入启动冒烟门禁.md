# 1083 桌面发布矩阵接入启动冒烟门禁

## 背景

主 CI 已接入统一工作区启动冒烟检查，但正式桌面发布 workflow 仍可能直接进入 Tauri 打包。这样会遗漏某个平台 runner 上 Node、Python、sidecar 或服务探测差异导致的启动回归。

## 本次调整

- 在桌面发布矩阵的每个 Windows/Linux/macOS job 中，Tauri 打包前执行 `python scripts/smoke_startup.py`。
- 保持与主 CI 相同的端口冲突保护、前端/PH 身份检查和进程树清理。
- 增加 workflow 契约测试，锁定冒烟检查必须位于打包步骤之前。
- 不改变安装包目标、签名配置、PH/TD 数据边界或发布产物格式。

## 验证边界

本地已验证冒烟命令、workflow 契约、全量测试和桌面前端构建；Windows/Linux/macOS 原生 Tauri 打包仍由对应 GitHub runner 执行。
