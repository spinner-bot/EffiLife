# 0688：启动后自动补打卡维护兜底

## 背景

统一工作台完成启动和数据 hydration 后，会执行跨天自动补打卡及昨日记录提醒。该维护路径此前位于主初始化错误边界之外，历史数据异常时可能产生未处理 rejection，影响用户对启动状态的判断。

## 实现

- 将自动补打卡与昨日记录提醒包入独立的可恢复错误边界。
- 维护失败时保留已完成 hydration 的工作台，只记录诊断信息；不回滚用户数据，也不阻断后续使用。
- 保持正常自动补打卡、断签提醒和收件箱行为不变。
