# PH 归档读取故障反馈

## 背景

计划中心原先将归档接口失败处理为空数组。用户看到“暂无已归档计划”时无法判断是确实没有归档，还是计划服务暂时不可用；统一工作区中的搜索索引也会因此丢失归档结果。

## 调整

- 在 `planGateway` 增加独立的 `planArchivesState` 状态，区分初始、可用和不可用。
- 桌面端和移动端归档读取均记录失败状态；移动端仍保持本地快照语义。
- 计划中心在归档服务不可用时显示明确提示和重试按钮，不再伪装成空列表。
- 活动计划读取和编辑路径保持不变，归档失败不会阻断 PH 主工作区。
- 保持 PH 归档数据结构、内部编号和 TD 独立实体边界不变。

## 验证

- 桌面端生产构建：`npm run build` 通过
- 全量测试：724 passed
- `git diff --check`：通过
