# 1044 启动器依赖完整性判断修复

日期：2026-10-02

## 问题

启动器原先仅检查 `node_modules/vite` 目录是否存在来决定是否跳过首次依赖安装。若 npm 安装中断，目录可能残留但 `.bin` 启动脚本已经缺失；启动器随后会错误地跳过安装，直到 `npm run dev` 才失败。

## 实现

- 依赖就绪判断改为检查实际 `.bin` 入口。
- 统一工作台要求 `vite` 与 `vue-tsc` 均存在。
- to-dos 兼容 Web 入口要求 `vite` 存在即可。
- 保留 Windows `.cmd` 与 POSIX 无后缀脚本差异处理。

## 验证

- 启动器与构建环境专项测试：`77 passed`。
- Python 全量测试：`798 passed in 8.15s`。
- `python launcher/start.py --doctor`：Node/npm 正确发现，统一工作台可启动，阻塞问题为 0。

## 影响范围

只改变启动前的依赖完整性判断，不改变模块数据、启动命令、端口或正式安装包行为；检测到不完整依赖时，启动器会重新执行既有安装流程。
