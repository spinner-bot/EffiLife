## 背景与证据

GitHub Actions 的移动端边界工作流持续成功，但 `EffiLife CI` 从提交 `a50c30cf`（统一环境站工具链自动发现）开始持续失败，失败步骤为 `Run full Python test suite`。最近一次失败为 run `38442474741`，提交 `cbda9bc`；本地 Windows 全量测试通过，问题集中在新增的跨平台工具链测试隔离方式。

## 根因判断

新增测试通过 `monkeypatch.setattr(module.os, "name", "nt")` 模拟 Windows。`os` 是全局模块对象，在 POSIX runner 上修改它会影响 `pathlib.Path` 等其他代码的运行时平台判断，尤其可能在 `tmp_path` 生命周期清理时触发 WindowsPath/PosixPath 不一致。该测试方式污染了进程级平台状态，不能作为跨平台测试契约。

## 实施内容

- `launcher/start.py` 增加 `is_windows()` 平台判断函数，工具链发现逻辑使用该函数。
- `scripts/check_build_environment.py` 增加同名可注入平台判断函数，Rust 工具链发现逻辑使用该函数。
- 工具链测试改为替换模块级 `is_windows` 函数，不再修改全局 `os.name`。
- 保持生产行为不变：真实 Windows 仍使用统一环境站的 Rust toolchain，POSIX 仍使用系统工具发现逻辑。
