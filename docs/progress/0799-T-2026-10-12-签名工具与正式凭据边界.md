# 1322-T：签名工具与正式凭据边界

## 元信息

- 日期：2026-10-12
- 类型：发布工程 / 启动器诊断
- 状态：已完成
- 关联：HOTL-1 发布门禁、桌面端与 Android 构建验收

## 本轮目标

修正启动器对“发布签名已就绪”的判断。系统中可能已经安装签名工具，但这不代表正式证书或发布密钥已经配置；两者必须分开报告，避免把可构建误判为可正式分发。

## 实施内容

1. Android 诊断拆分为工具可用、密钥路径已配置、正式签名可用三个层次。
2. Windows 诊断拆分为 `signtool` 可用、证书路径已配置、正式签名可用三个层次。
3. 支持通过 `EFFILIFE_ANDROID_KEYSTORE` 与 `EFFILIFE_WINDOWS_SIGNING_CERT` 指定受控发布环境中的凭据路径。
4. 未配置正式凭据时增加信息级提示，不读取证书内容、不生成密钥、不改变本机凭据。
5. `formal_distribution_ready` 只有在存在可用安装包且 Windows 正式证书已配置时才为真；工具存在本身不再满足正式发布门禁。
6. 增加启动器回归测试，覆盖“工具存在但正式凭据缺失”和“工具及凭据均存在”两种边界。

## 验证结果

- `python -m py_compile launcher/start.py`：通过
- `python -m pytest -q`：1032 passed
- 已确认本机可发现 Windows SDK 中的 `signtool.exe`，以及 Android SDK 中的 `apksigner.bat`、`zipalign.exe`。
- 当前工作站仍未配置 EffiLife 的正式发布证书/发布 keystore，因此诊断应继续报告正式分发未就绪；这属于预期安全边界。

## 后续事项

- 在受控发布环境配置正式 Windows 证书和 Android release keystore 后，再执行签名、安装验证与发布清单生成。
- 正式凭据不提交仓库，不写入进展文档，不通过启动器输出敏感内容。
