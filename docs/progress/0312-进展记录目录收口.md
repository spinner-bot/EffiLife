# 0736 进展记录目录收口

日期：2026-10-01

## 背景与发现

`docs/progress/0000-进展报告规范.md` 已规定：`docs/进展报告/` 仅保留历史阶段资料，新的工作、引用和 README 入口统一使用 `docs/progress/`。最近的 0732–0735 报告仍误写入历史目录，形成了新旧记录并行的风险。

## 目标与非目标

目标是从本报告起将新增进展、设计决策和阶段审计统一写入 `docs/progress/`，并在报告中保留真实命令、提交和未验证边界。

非目标是批量移动或重写历史报告；历史目录中的既有文件保持原样，避免破坏已有引用和提交历史。

## 影响范围

- 文档入口：后续新增报告使用 `docs/progress/NNNN-主题.md`。
- 工程实现：不改变 TH、PH、TD 数据结构和运行时逻辑。
- Git：直接在 `main` 迭代；若发生合并，仍遵守 no-FF 规则。

## 依据与验证

- 规范依据：`docs/progress/0000-进展报告规范.md`。
- 已核对历史目录与当前目录，确认旧目录已有大量阶段资料，不能通过删除或重命名“一次性整理”。
- 后续报告将至少包含背景、目标/非目标、影响范围、实现或决策、验证命令、提交状态和未验证边界。

## 当前提交与状态

- 本次仅新增目录收口说明，不修改历史报告和用户保护文件。
- 提交前应运行与后续变更匹配的测试，并在报告中填入实际结果。

## 未验证项

目录收口本身不代表真实桌面安装包、Android、iOS 或人工视觉验收已完成；这些仍按发布规范单独记录。
