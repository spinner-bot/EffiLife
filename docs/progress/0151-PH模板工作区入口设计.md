# PH 模板工作区入口设计

日期：2026-09-30

## 背景

基础创建弹窗已按 req7 收敛为名称和日期，但模板仍是 PH 的既有能力。Plan Helper 的模板 API 语义是“从模板新建 Plan”，不是向已有 Plan 覆盖内容；直接把模板套入空 Plan 会产生重复创建、ID 冲突或破坏日志/关联引用的风险。

## 决策

- 普通“创建计划”保持纯粹，只创建空 Plan 并进入编辑器。
- 在计划中心增加独立的“从模板开始”工作区入口，不与基础创建弹窗混用。
- 模板工作区显示模板选择、名称和日期，提交仍调用现有 `createEventPlanFromTemplate`；成功后进入同一详情编辑器。
- 桌面端继续调用 PH `/api/templates` 与 `/api/plans/from-template`；移动端继续使用本地内置模板定义。
- 不新增“覆盖已有 Plan”接口，不改变 Plan ID、日志、嵌套 group、软删除和 TD 关联语义。

## 布局

模板工作区作为计划中心内的可关闭面板，桌面端使用双栏模板选择与表单布局，移动端自动单列；加载、空列表、错误和提交中状态均有反馈。

## 验收

- 基础创建弹窗只包含名称和日期。
- 计划中心存在可达的模板入口。
- 桌面/移动模板创建路径均进入同一详情编辑器。
- 模板未创建 TD，既有模板 API 和全量回归保持通过。
