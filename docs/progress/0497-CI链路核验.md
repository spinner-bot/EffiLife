# CI 链路核验

日期：2026-10-02

## 核验范围

检查 `.github/workflows/ci.yml`、桌面发布工作流和移动端边界工作流，确认工作目录、依赖安装、Python 测试、跨模块集成测试、前端构建以及发布配置检查仍与当前仓库结构一致。

## 结果

- 主 CI 使用 Node 22，在 `time-helper/desk` 和 `to-dos/ui` 分别执行 `npm ci` 与构建。
- Python 测试和 `scripts/run_integration.py test` 在仓库根目录执行，路径正确。
- 桌面发布工作流先同步版本，再执行 `npm ci`、测试、Tauri 构建和产物校验。
- 移动端工作流仍明确依赖 Android/iOS 原生 runner；本地不具备工具链，因此不伪造真机或安装包通过结论。
- 本机执行 `npm ci --ignore-scripts --dry-run` 成功。Node 20.18 对 `eslint-visitor-keys` 给出 engine warning；CI 使用 Node 22，当前没有证据表明这会导致工作流失败。

## 决策

本轮不修改 `package-lock.json`、工作流和发布配置：没有发现可复现的 CI 逻辑错误，避免以猜测性改动掩盖真实失败原因。后续若再次收到失败通知，应优先取得具体 job、step 和日志，再按失败平台处理。
