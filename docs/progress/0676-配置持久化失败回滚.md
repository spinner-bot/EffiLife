# 0676：配置持久化失败回滚

## 背景

应用配置保存原先先更新 Pinia 内存状态，再写入持久化存储。写入失败时，设置页虽然可以显示失败提示，但应用仍保留未落盘的新配置，造成运行时状态与真实存档不一致。

## 实现

- `appStore.saveConfig()` 保存前记录旧配置。
- 持久化写入失败时恢复旧内存配置并继续向调用方抛出原异常。
- 成功路径保持原有设置事件通知不变，调用方仍可保留草稿并重试。
- 增加回归契约测试，锁定失败回滚行为。

## 兼容性

- 不改变配置数据结构、主题架构、跨窗口事件协议或导入导出格式。
- PH、TD、TH 的独立数据职责不变。
