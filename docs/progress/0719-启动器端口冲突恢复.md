# 1229｜启动器端口冲突恢复

## 变更目的

测试启动方式使用 Vite 的 `--strictPort`。当本机已有程序占用默认端口 1420 或 1421 时，原启动器会直接失败，用户只能手动排查进程或修改环境变量。本次迭代改善这一类常见启动失败。

## 实现内容

- 新增 `launcher.start.frontend_port()`：优先使用配置端口；若端口被占用，则在后续有限范围内寻找第一个空闲端口。
- TH 统一工作台和 TD 兼容 UI 均使用该端口选择逻辑。
- 同一轮统一启动会把 TH 已选端口传给 TD，避免两个前端在默认端口同时冲突时选择同一个备用端口。
- 启动命令仍保持 `--strictPort`，避免开发服务器静默换端口；启动器会把实际选中的 URL 交给浏览器和健康检查流程。
- 默认端口未被占用时保持原行为，不改变已有配置、服务端口和 PH API 端口。
