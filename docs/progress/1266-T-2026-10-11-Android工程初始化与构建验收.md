# Android 工程初始化与构建验收

日期：2026-10-11

## 本次目标

在暂不推进 iOS 的前提下，确认 EffiLife 桌面端与 Android 端的本地开发链路，并生成 Tauri Android 工程。

## 已完成

- 执行 `npm run mobile:android:init`，生成 `time-helper/desk/src-tauri/gen/android`。
- `scripts/check_build_environment.py --target android` 通过，Node、npm、Rust、Java、ADB、Android SDK 路径均可识别。
- `scripts/check_mobile_release_config.py` 通过。
- 修复 `src-tauri/src/lib.rs` 对旧版 Tauri `Builder::run(context, callback)` 的调用，改为当前 Tauri API 的 `build(context)` + `App::run(callback)`，保留桌面端 sidecar 退出清理逻辑。
- 桌面端 `cargo check --target x86_64-pc-windows-msvc` 通过。
- Android `aarch64-linux-android` Rust 原生库编译通过，生成 `libefflife_desk_lib.so`。
- 对移动端编译路径不需要的 Rust 导入和变量增加条件编译/命名处理，桌面端检查无新增警告。

## 当前阻塞

Tauri Android 构建在将 `.so` 放入 `gen/android/app/src/main/jniLibs` 时需要创建符号链接。当前 Windows 工作站未开启开发者模式，也没有 `SeCreateSymbolicLinkPrivilege`，因此 APK 打包阶段失败。

这不是项目代码、Rust、JDK、Android SDK 或 NDK 缺失。开启 Windows 开发者模式后，应重新运行：

```powershell
cd time-helper/desk
npm run mobile:android:build
```
