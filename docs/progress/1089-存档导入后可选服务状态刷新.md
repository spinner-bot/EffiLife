# 1089 存档导入后可选服务状态刷新

## 背景

统一存档导入会立即写入 IndexedDB 与兼容性镜像。设置页允许用户在不重启应用的情况下继续使用，因此仅刷新 Pinia 工作区和数据统计不足以覆盖音频、事件、打卡三个仍持有内存状态的服务。

## 本次调整

- `AudioManager` 增加 `refreshFromStorage()`，重新读取音频设置。
- `EventSystem` 增加 `refreshFromStorage()`，重新读取事件设置、预警收件箱、事件收件箱和每日触发状态。
- `CheckinSystem` 增加 `refreshFromStorage()`，重新读取打卡数据并同步连续天数与全局响应式状态。
- 存档导入成功且用户选择暂不重启时，设置页并行刷新上述服务；单个可选服务刷新失败不会阻断其他刷新。
- 任务中心收到 `archive` 工作区事件时，同时重新读取 TD 设置、待办和分类，避免导入后仍使用旧的排序刷新频率或展开数量。

## 验证

- 新增可选服务刷新契约测试。
- 运行集成测试、全量 pytest 和桌面端构建。

## 边界

本次只解决导入后的运行时状态一致性，不改变存档格式、PH/TD 数据边界，也不涉及当前待后续处理的主题编辑问题。
