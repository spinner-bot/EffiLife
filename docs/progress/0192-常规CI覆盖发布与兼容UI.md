# 0593｜常规 CI 覆盖发布契约与兼容 UI

## 背景

正式桌面安装包由独立的 tag 发布工作流构建，`to-dos/ui` 则作为迁移和兼容边界保留。此前常规 CI 只验证统一前端和 Python 测试，发布配置或兼容 UI 的回归可能直到打 tag 才被发现。

## 实施

- 在常规 CI 中执行 `check_release_config.py`，验证桌面版本、sidecar、安装包矩阵、校验和与发布依赖关系。
- 在常规 CI 中执行 `check_mobile_release_config.py`，验证移动端不携带桌面 sidecar 的边界。
- 安装并构建 `to-dos/ui` 兼容 UI，确保旧数据迁移/兼容入口仍可编译。
- 扩展 npm 缓存依赖路径，使两个前端锁文件都参与缓存失效判断。
- 保持正式发布工作流的跨平台 Tauri 构建职责不变；常规 CI 只增加可复现的配置和前端门禁。

## 验证

- `python scripts/check_release_config.py`
- `python scripts/check_mobile_release_config.py`
- `python -m pytest -q tests/test_ci_workflow.py`
- 完整 Python 测试与两个前端构建将在提交前执行。
