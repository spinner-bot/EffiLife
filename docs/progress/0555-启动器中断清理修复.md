# 1061 启动器中断清理修复

日期：2026-10-02

## 问题

统一启动器在服务就绪后等待主前端进程退出。用户按下 Ctrl+C 时，原处理路径只清理 companion，没有显式终止主 Vite/Node 进程，可能留下占用工作台端口的残留进程。

## 实现

- 在 `run_module` 中保存主进程引用。
- 捕获 `KeyboardInterrupt` 时调用既有的 `terminate_process`，沿用 Windows 进程树和 POSIX 进程组清理策略。
- 不改变正常退出码、健康服务复用和外部服务不受影响的行为。

## 验证

- 启动器专项测试：`74 passed`。
- Python 全量测试：`817 passed`。
- `python -m py_compile launcher/start.py`：通过。
- 真实启动验收中已验证前端和 PH sidecar 可就绪；本修复覆盖其后的 Ctrl+C 回收路径。

## 影响范围

减少开发启动器端口残留和重复启动失败；正式 Tauri 安装包的进程管理边界不变。
