# 0898 发布链路当前边界审计

## 审计目的

HOTL 一号规范要求统一应用最终具备正式桌面安装包和移动端适配能力。当前仓库已经有对应 workflow，但“存在 workflow”不能等同于“所有平台都已完成真实验收”，因此单独记录当前证据边界。

## 已验证

- 本地桌面发布配置检查通过：版本、Tauri 配置、Plan Helper sidecar、兼容 UI、安装包校验、校验和与 manifest 步骤均存在。
- 本地移动发布配置检查通过：Android/iOS workflow 与移动边界契约存在。
- 跨模块集成测试通过：schemas、DataManager、EventBus、TodoAPI、PH/TD/TH 关联与统一网关均通过。
- 最近一次 `EffiLife CI`（提交 `289d4d1`）在 GitHub 上显示成功。
- 统一启动器提供开发模式、打包模式、诊断、doctor、release-check、端口冲突检查和子进程清理。

## 尚不能宣称完成

- 当前 Windows 开发环境未执行真实 Tauri 安装包安装/启动验收。
- 当前环境没有 Android SDK/ADB 和 macOS/Xcode，因此没有真实 Android/iOS 设备或原生构建证据。
- 浏览器自动化视觉验收尚未替代人工检查，不能据此宣称桌面、平板、移动端视觉层级全部达标。

## 后续边界

发布环境具备 Rust、平台 SDK 与签名条件后，应执行对应 workflow，并对安装、启动、升级/卸载、统一存档读写和三种屏幕尺寸进行验收；在此之前，仓库状态应描述为“发布链路已配置并有契约验证，原生平台验收待执行”。

## 验证命令

- `python scripts/check_release_config.py`
- `python scripts/check_mobile_release_config.py`
- `python scripts/run_integration.py test`
- `python -m pytest -q`
