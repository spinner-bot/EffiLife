# 1206｜全局搜索模块筛选设计

日期：2026-10-10  
状态：设计完成，待实现

## 背景

EffiLife 的全局搜索已经同时索引 TD 待办、PH 整份计划/计划任务/归档计划和 TH 时间记录。数据域已经统一，但结果列表没有显式的模块筛选。当多个模块存在相同或相近名称时，用户只能依赖结果副标题判断来源，控制台的跨模块检索效率不足。

## 目标与非目标

- 目标：在全局搜索中提供 All、TH、PH、TD 四个筛选范围；筛选只影响展示和键盘选择，不改变底层数据和路由。
- 目标：让结果明确体现模块身份，保留当前结果排序、深链接和部分数据不可用提示。
- 非目标：不把 PH 任务转换成 TD，不改变 PH/TD 独立生命周期，不新增日历功能，不修改存档协议。

## 美学与交互方向

采用 Linear 风格的“命令面板”：搜索输入保持主视觉，下面使用低干扰的胶囊式分段控件作为上下文过滤器。桌面端横向展示四个筛选项；窄屏端允许横向滚动并保持触控目标不小于 40px。筛选控件只使用现有主题 token（边框、主色、背景层级），不引入新的硬编码色值。

## 字体、色彩与布局

- 延续统一工作台现有字体层级；筛选项使用 11–12px 的辅助层级，选中态通过主色边框、浅色背景和文字同时表达，不依赖单一颜色。
- 桌面搜索面板宽度维持现有 `min(620px, 100%)`，筛选条占满面板宽度并水平排列。
- 移动端筛选条 `overflow-x: auto`，按钮保持足够触控高度，结果区域不被挤出视口。

## 状态覆盖

- 默认：All 选中，保持现有搜索结果。
- 悬停/聚焦/按下：沿用搜索结果和按钮的主题 token 状态。
- 加载：筛选条仍可见但按钮禁用，避免用户误以为索引消失。
- 空结果：显示当前模块范围对应的空状态。
- 错误/部分可用：保留现有重试提示，筛选不掩盖数据源错误。
- 关闭/再次打开：恢复 All 和空查询，避免上一次筛选造成隐性状态。

## 验收条件

1. All、TH、PH、TD 四项存在中英文文案，且资源键成对覆盖。
2. TH 只显示 record，TD 只显示 todo，PH 显示 plan、planTask、archivedPlan。
3. 查询、键盘上下选择、Enter 深链接、Esc 关闭和部分索引错误行为保持不变。
4. 前端生产构建与全量 Python 契约测试通过。
5. 不修改 `.efl` 数据集、PH 原始结构或用户保留文件。
