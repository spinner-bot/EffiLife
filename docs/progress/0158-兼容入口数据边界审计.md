# 兼容入口数据边界审计

## 结论

当前产品主入口是 `time-helper/desk` 统一工作台。旧 `plan-helper/web` 与 `to-dos/ui` 在启动器中明确标记为兼容入口，仅用于迁移、调试和回归，不作为正式产品的第二套工作区。

## 数据边界

- 统一工作台：以 IndexedDB（正式桌面版为应用数据目录）作为运行时主存储，通过 `.efl` 统一存档交换 `TH`、`PH`、`TD` 数据。
- Plan Helper 兼容入口：保留原始 Plan JSON/API 语义，供迁移和底层模型回归使用。
- TD 兼容入口：保留 `to-dos-data` 本地存储和旧 JSON 操作，供旧数据迁移与算法调试使用；不向统一工作台伪装成实时共享数据源。
- 统一工作台提供显式的旧 TD JSON 导入路径，迁移数据经统一服务归一化后再进入主存储。

## 防偏差规则

1. 新功能优先进入统一工作台和共享服务层，不在兼容 UI 中复制一套产品能力。
2. 兼容入口可以修复数据安全、空状态和迁移问题，但不得改变 PH 是整份计划、TD 是单条待办的实体边界。
3. 任何跨入口数据同步必须通过统一存档或显式迁移，不读取另一个入口的临时 UI 状态。

## 本轮证据

- 启动器默认进入统一工作台，兼容入口需显式选择。
- README 已将旧 TD Web 标记为迁移和调试用途。
- TD 兼容入口已移除首次启动示例数据，避免产生虚假主数据。
