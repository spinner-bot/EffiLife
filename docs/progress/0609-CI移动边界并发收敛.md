# 0609｜CI 移动边界并发收敛

## 背景

连续提交期间，移动端边界工作流会为同一分支排队多个运行。旧运行的失败通知可能在新运行修复后仍持续到达，增加判断噪声；同时工作流本身的修复此前不在 push path 过滤范围内。

## 目标与范围

- 同一 ref 只保留最新的移动端边界验证。
- 让移动边界工作流自身的修改触发一次验证。
- 不改变移动端是否使用 sidecar、构建命令或发布产物边界。

## 实现

- 为 `tauri-mobile-boundary.yml` 增加按 ref 分组的 `concurrency`，启用 `cancel-in-progress`。
- 将工作流文件自身加入 push path 过滤。
- 增加工作流契约测试，防止并发策略回退。

## 兼容性与架构决策

取消的是同一 ref 上已过时的验证运行，不会取消手动移动端构建工作流，也不改变通用 CI 和桌面发布工作流。

## 验证

```text
python -m pytest -q tests/test_mobile_workflow.py
```

结果：`9 passed in 0.13s`，并通过 `git diff --check`。
