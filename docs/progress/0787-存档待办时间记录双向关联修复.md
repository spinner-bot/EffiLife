# 0787｜存档待办—时间记录双向关联修复

## 状态

已完成，2026-10-01。

## 背景与问题

统一 `.efl` 存档同时保存 TD 的 `related_time_record_ids` 和 TH 记录的 `todo_id`。原导入逻辑会过滤待办侧不存在的记录，并从记录侧补齐待办引用，但不会处理记录侧指向不存在待办的孤儿引用，也不会把仅存在于待办侧的有效关联补回记录侧。

## 目标与边界

- 目标：导入时让两侧引用保持可解释、可恢复，清除能够确定无效的记录 `todo_id`，并在另一侧明确给出有效关联时补齐。
- 不改变 PH、TD、TH 的实体边界；不根据缺失的计划服务数据擅自删除计划关联。

## 实现

- 收集导入待办 ID 和待办侧记录 ID。
- 对每个记录优先保留指向已存在待办的 `todo_id`；若待办侧能确定唯一归属则补齐；否则清除无效/孤儿引用。
- 记录侧有效关联再反向合并到待办的 `related_time_record_ids`，同时继续过滤不存在的记录 ID。
- 解析 canonical archive 与 legacy archive 均使用修复后的记录桶继续写入。
- 修复数量继续通过既有 `importRepairs.todoRecordLinks` 汇总并在导入结果中提示。
