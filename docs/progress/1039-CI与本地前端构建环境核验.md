# 1039 CI 与本地前端构建环境核验

日期：2026-10-02

## 核验目的

针对此前 GitHub Actions 失败通知，区分仓库构建问题、Node/npm 环境问题和本地进程占用问题，避免把本机测试失败误判为 CI 配置失败。

## 结果

- 使用仓库当前桌面前端依赖和 `F:\dev-tools\node` 中的 Node 运行时，执行 `npm run build` 成功。
- 构建结果：`vue-tsc` 通过，Vite 完成 `1877 modules transformed`，生产构建成功。
- Python 全量测试：`792 passed in 8.12s`。
- `check_release_config.py` 通过。
- `check_mobile_release_config.py` 通过。
- 当前本机 Node 为 `v20.18.0`，npm 为 `10.8.2`；npm 对少数依赖给出 engine warning，但没有影响生产构建。
- 本机执行 `npm ci` 时遇到 `EPERM`，目标是 `node_modules/@esbuild/win32-x64/esbuild.exe`；进程检查确认有两个 EffiLife Vite/Node 开发进程正在占用该文件。这是本地进程占用，不是依赖锁解析错误。

## CI 配置判断

`.github/workflows/ci.yml` 已显式使用 Node 22，并在安装依赖前执行 `setup-node`；GitHub runner 不会继承本机 PATH，也不会继承本机正在运行的 Vite 进程。因此本轮证据支持“仓库前端构建链可用”，但不足以定位 GitHub 某一次历史 run 的具体失败步骤。后续若再次收到失败通知，应以该 run 的具体 job/step 日志为准，不应仅依据本地 `npm ci` 的 EPERM 推断。

## 后续动作

保持当前锁文件不动（工作区已有用户预存改动），继续优先处理可复现的产品行为问题；若要清理本机依赖，应先由进程所有者正常停止 EffiLife 开发服务器，再重新执行 `npm ci`。
