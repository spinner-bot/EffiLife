# 统一启动与跨模块回归验收

日期：2026-10-11

## 背景与目标

在移动端工作流收敛为 Android-only 后，重新验证统一应用壳、启动器、PH sidecar 和跨模块数据契约，确保 CI 边界调整没有造成主工作流回归。

## 影响范围

- 统一启动器及其端口/服务健康检查；
- TH、PH、TD 的统一 schema、引用关系和 API gateway；
- 当前 Android-only 移动构建入口的 Python 契约测试。

## 验证结果

### 跨模块集成测试

执行：

```powershell
python scripts/run_integration.py test
```

结果：`TOTAL: 55/55 passed`。

覆盖 unified schema、DataManager、EventBus、认证边界、TD 基础 API、PH 关联、TH 时间记录关联、API Gateway 和 dashboard 汇总。

### 统一启动 smoke

执行：

```powershell
python scripts/smoke_startup.py
```

结果：

```json
{
  "ok": true,
  "frontend_url": "http://127.0.0.1:1420/",
  "plan_health_url": "http://127.0.0.1:8765/api/health",
  "ports_released": true,
  "frontend_ready": true,
  "plan_helper_ready": true
}
```

这证明统一启动器可以同时拉起前端和计划服务，并在 smoke 结束后释放端口。

## 兼容性与边界

- 本次未修改 PH 原始 Plan 数据结构、嵌套组、软删除编号或稳定引用语义。
- TD 仍是独立待办实体，PH 仍是完整计划实体，TH 仍是时间维度；集成测试只验证引用协作。
- Android-only 工作流边界已由 `1268` 报告记录；iOS 仍保留为未来能力，不参与当前发布入口。
