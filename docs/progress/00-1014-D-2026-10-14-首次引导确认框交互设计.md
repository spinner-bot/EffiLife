# [设计] 首次引导确认框交互层级

## 创建信息

- 创建时间：2026-10-14
- 执行者：Codex
- 所属阶段：第 0 阶段（阶段未递增）
- 类型：首次使用与弹层交互设计

## 背景

真实移动浏览器验证发现，首次引导点击关闭后会打开确认框，但引导遮罩仍处于更高层级，并且 document 捕获监听会继续处理确认框点击，导致“确认/取消”无法操作。

## 设计决策

- 确认框是当前最高优先级的模态交互，应位于引导层之上；将确认层级提升到高于引导层的独立 token 数值。
- 引导点击捕获逻辑明确放行 `.confirm-dialog` 内部事件，确认框打开期间不推进或阻止引导步骤。
- 保持确认框原有 Esc、取消、确认、焦点陷阱和遮罩行为。
- 不让引导层直接操纵确认服务状态，继续通过 `requestConfirm` / `settleConfirm` 解耦。
- 桌面与移动端统一采用同一层级规则，避免仅修复某一视口。

## 非目标

- 不取消关闭引导所需的确认，避免误触丢失引导进度。
- 不改变引导步骤内容、持久化键或首次使用策略。
- 不把所有弹窗粗暴提升到同一层级；只调整确认模态与引导的明确关系。

## 验收条件

- 首次引导点击关闭后，确认框可见且确认/取消均可点击。
- 取消后引导仍存在；确认后引导关闭并可进入 PH/TD/TH 页面。
- 移动浏览器真实路径通过，现有确认框键盘可访问性测试不回归。
