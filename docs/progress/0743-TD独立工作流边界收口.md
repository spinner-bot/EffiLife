# 0743 TD 独立工作流边界收口

## 背景

0741 已移除 PH 页面主动创建和同步 TD 的行为，但 TD、主页和记录页仍保留从待办进入 PH 条目、从记录进入 PH 条目、以及 TD 完成时反向完成 PH 条目的旧入口。HOTL-1 要求 PH 与 TD 保持不同基本单元，不能在界面和操作逻辑上融合。

## 实现

- TD 新建和编辑不再提供计划/计划条目选择器。
- TD 完成与批量完成只更新 TD 自身，不再调用 `completePlanTask`。
- TD 编辑不再回写 PH 条目。
- 主页待办快速完成只更新 TD；主页仍独立展示 PH 计划摘要，但不显示待办的 PH 关联按钮。
- 记录页保留“记录 ↔ TD”的关联，移除“记录/TD ↔ PH”的跳转入口。
- 历史数据中的 `related_plan_id`、`related_plan_task_id` 字段暂不删除，保证导入和旧数据读取兼容；新建、编辑和完成流程不再产生或修改这些关联。

## 验证

- `python -m pytest -q`：631 passed。
- `time-helper/desk` 执行 `npm run build`：通过，Vite 转换 1874 个模块。
- `vue-tsc` 类型检查通过。

## 设计边界

TH、PH、TD 通过统一应用壳、主页摘要、独立导航和统一数据层协同；它们的核心数据单元和编辑流程保持分离。后续若要增加跨模块关联，应采用显式、只读的历史兼容或独立引用模型，不能把 PH 条目自动变成 TD。
