# 发布产物与本地验收边界

日期：2026-09-30

## 本轮结论

本轮复核确认，EffiLife 的桌面发布链路已经包含真实构建后的产物门禁，而不是只检查配置文件：

- GitHub Actions 按 Windows NSIS、Linux DEB、Linux AppImage、macOS DMG 分矩阵构建。
- 每个矩阵任务在 Tauri 构建后执行 `scripts/verify_release_artifacts.py`，拒绝缺失或空文件安装包。
- 安装包随后生成 SHA-256 校验文件，并与安装包一起上传。
- tagged release 仅在兼容性构建和全部桌面构建成功后发布。
- 移动端当前执行 `scripts/check_mobile_release_config.py`，用于保证移动配置不携带桌面 sidecar；尚未宣称已有 Android/iOS 安装包。

## 本机验证

在当前 Windows 开发环境执行：

```text
python -m pytest -q
457 passed in 4.46s

time-helper/desk: npm run build
vite production build succeeded
```

仓库的 `launcher/start.py --release-check` 与 `scripts/check_release_config.py` 用于只读验证发布配置；启动器的 `--diagnose --packaged` 用于检查本机已有 Tauri 二进制或静态构建。

## 环境边界

当前机器缺少 Cargo/Rust，因此本轮没有伪造新的 Tauri 安装包，也没有把前端 `dist` 构建误报成正式安装包。正式桌面安装包必须在具备对应平台工具链的 CI runner 上生成并通过产物校验；Android/iOS 则需要各自的 SDK、签名与平台工程初始化。

## 后续验收条件

1. 在目标平台 runner 上完成 Tauri bundle 构建。
2. 通过对应扩展名的非空产物校验和 SHA-256 生成。
3. 对移动端增加真实构建与签名策略后，再把移动产物纳入发布流水线。
