# 0761 CI 依赖安装版本同步修复

## 问题

桌面发布 workflow 已经在 `npm ci` 前同步 `VERSION` 与 lockfile，但主 CI、移动边界和手动移动构建仍可能直接使用工作区中滞后的 lockfile。当前 `package.json` 与受保护的 lockfile 存在版本差异，这会造成依赖安装阶段的脆弱性，并可能解释 GitHub 的 run fail 通知。

## 处理

- 在 `.github/workflows/ci.yml` 中把桌面版本同步放到 Node/npm 安装之前。
- 在 `tauri-mobile-boundary.yml` 中加入同样的同步步骤。
- 在手动 Android/iOS 构建 workflow 的两个 job 中都加入同步步骤，确保 `npm ci` 使用对齐后的版本元数据。
- 版本同步脚本仍只改版本字段，不重新解析依赖树，不覆盖用户本地 lockfile。
- 增加 workflow 契约测试，逐个 job 检查同步步骤位于 `npm ci` 之前。

## 验证

- 新增 workflow 版本同步测试。
- 变更前相关 Python 测试基线为 641 passed；提交前将执行完整测试套件。
- 当前本机没有 Node/npm，因此前端安装和构建仍由 GitHub runner 验证。
