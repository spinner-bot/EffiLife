# 主题编辑草稿与持久配置解耦

## 背景

用户反馈主题选择或修改后，离开设置再回来时可能恢复原样。此前主题编辑器的部分配置对象直接引用 Pinia 中的运行时配置，导致 `v-model` 可能在预览阶段提前修改持久配置对象，草稿、脏状态和退出保存的边界不稳定。

## 本次处理

- 主题编辑器初始化时为纯色、渐变、玻璃、霓虹配置建立独立对象，不再直接引用 `appStore.config.theme` 的子对象。
- 生成预览和待保存主题时复制配置对象，避免将编辑器内部引用泄漏到应用配置。
- 保留“修改后立即预览、退出主题面板自动保存”的交互，不恢复独立保存按钮。
- 保留保存失败时阻止离开并保留草稿的行为。

## 验证

- `python -m pytest -q tests/test_theme_persistence_contract.py`：9 passed
- `python -m pytest -q`：603 passed
- 桌面端 `npm run build`：成功，Vite 转换 1874 个模块

## 结论

主题编辑器现在明确区分编辑草稿、运行时预览和持久配置，降低退出保存被旧引用或异步刷新覆盖的风险。后续若出现具体主题仍无法持久化，应继续以实际主题类型和存储层数据进行端到端复现。
