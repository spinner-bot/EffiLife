# 1210｜可注册多语言基础设计

日期：2026-10-10  
状态：设计完成，待实现

## 背景

前端已有中文/英文目录、回退机制和 `LOCALE_DEFINITIONS`，但 `Locale` 类型与系统语言识别仍直接写死 `zh-CN`、`en-US`。这会让新增日文、繁体中文或其他语言必须修改核心解析逻辑，不能通过独立目录注册扩展。

## 目标与非目标

- 目标：将语言代码、显示元数据、回退关系和目录纳入可注册的运行时 registry。
- 目标：保留当前中文/英文行为、存档兼容性、跨窗口同步和 LocaleSwitcher 行为。
- 非目标：本次不新增第三种完整翻译，不改变现有翻译文案，不引入异步网络翻译或自动机器翻译。

## 设计决策

1. `Locale` 改为可表示任意 BCP-47 代码的字符串类型；内置语言仍由 registry 声明。
2. 新增 `registerLocale(definition, catalog, navigationFallback?)`，在应用启动前注册扩展目录；重复代码拒绝覆盖，避免插件静默破坏内置文案。
3. 浏览器语言初始化先做已注册代码的精确匹配，再按语言前缀匹配，最后回退到中文；删除 `en`/`zh` 的硬编码分支。
4. `translate` 对动态目录使用安全空对象，并继续遵循当前语言 → 注册 fallback → key 的查找顺序。
5. 现有双语静态目录仍保持完整性测试；注册 API 只扩展能力，不改变现有 UI。

## 影响范围

- `time-helper/desk/src/i18n/index.ts`：registry、语言解析、动态目录注册。
- i18n registry 契约测试和实现记录。
- 不涉及 PH/TD/TH 数据、不涉及 `.efl` 协议、不涉及主题或路由。

## 兼容性与状态覆盖

- 已保存的 `zh-CN` / `en-US` 值完全不变。
- 未注册或损坏的语言值回退到中文。
- 缺少某个翻译键时沿用注册语言的 fallback；仍找不到时显示 key，保持现有诊断行为。
- 重复注册返回失败而不覆盖目录；注册非法空代码时返回失败。

## 验收条件

1. 中文/英文现有 i18n 全量契约继续通过。
2. 可以在测试中注册一个临时 locale，并验证选择、目录查找、fallback 和清理/隔离行为。
3. 浏览器 `navigator.languages` 不再依赖固定语言分支。
4. 前端生产构建和全量 Python 测试通过。
