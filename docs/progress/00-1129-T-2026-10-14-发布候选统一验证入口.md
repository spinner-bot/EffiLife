# 发布候选统一验证入口

## 触发原因

本地发布候选检查此前需要人工分别执行全量 Python 测试、桌面发布配置检查、移动发布配置检查和前端构建。命令容易遗漏，也无法统一输出结果，不符合可维护的产品发布流程。

## 实现

新增 `scripts/verify_release_candidate.py`，默认按固定顺序执行：

1. `python -m pytest -q`；
2. `scripts/check_release_config.py`；
3. `scripts/check_mobile_release_config.py`；
4. `scripts/build_frontend.py`。

脚本输出每个步骤的返回码和最终 JSON 摘要，并支持 `--skip-tests`、`--skip-build`。它不会自动启动服务、安装程序、签名制品或修改用户数据；浏览器 smoke、正式签名和真实设备验收仍保持显式边界。

## 结果

执行：

```text
python scripts/verify_release_candidate.py
```

结果：各验证步骤均返回 `0`；本次全量回归为 `1243 passed`，桌面和移动发布配置均通过，前端生产构建成功并转换 1880 个模块。新增脚本契约测试：`2 passed`。

`git diff --check` 仍会报告用户原有未提交文件 `plan-helper/test.py` 第 14 行的尾随空白；该文件受保护，本次没有修改或纳入提交。阶段保持第 0 阶段。
