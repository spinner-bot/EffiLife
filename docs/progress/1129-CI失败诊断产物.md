# 1129 CI 失败诊断产物

日期：2026-10-05  
类型：实现报告

## 背景与目标

此前 CI 失败或启动冒烟失败时，通知只暴露最终状态，缺少可下载的启动器环境、端口和模块状态。为降低定位成本，在主 CI 的失败路径增加机器可读诊断产物。

## 实现与兼容性

- 主 CI 仅在前序步骤失败后执行 `python launcher/start.py --diagnose`；
- 诊断输出写入 `ci-launcher-diagnostics.json` 并通过 Actions artifact 上传；
- 诊断步骤使用 `|| true`，不会覆盖原始失败原因，也不改变成功路径；
- 不改变统一启动器、数据协议、模块路由或发布构建逻辑。

## 实际验证

- `python -m pytest -q tests/test_ci_workflow.py` → `5 passed`；
- `python scripts/check_release_config.py` 与 `python scripts/check_mobile_release_config.py` → 配置检查通过；
- `python -m pytest -q` → `881 passed`；
- GitHub Actions 真实失败产物需下一次 CI 失败或手动模拟后确认。

## 提交与推送

- 实现提交：`fa5bd63 ci: upload launcher diagnostics on failure`；
- 报告提交后推送至 `origin/main`；
- 工作直接在 `main`，不创建分支。

## 未验证项与边界

- 本地无法完全模拟 GitHub Actions 的 artifact 上传；
- 该改动改善诊断，不会自动修复原始构建/测试失败；
- 主题保存后退出恢复问题继续暂缓。
