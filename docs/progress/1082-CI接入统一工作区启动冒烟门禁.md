# 1082 CI 接入统一工作区启动冒烟门禁

## 背景

`scripts/smoke_startup.py` 已能在本机验证统一前端和 plan-helper 的真实启动，但主 CI 之前只执行 Python 契约、跨模块集成和前端构建，无法阻止启动器、服务识别或 companion 生命周期回归。

## 本次调整

- 主 CI 在全量 pytest 和统一跨模块集成测试之后执行 `python scripts/smoke_startup.py`。
- 门禁使用已安装的桌面 Node 依赖，启动真实 Vite 与 plan-helper 服务。
- 冒烟命令拒绝接管已有端口，验证两个服务身份，并在结束时回收进程树、确认端口释放。
- 增加 workflow 契约测试，防止后续重构移除该启动门禁或改变其位置。

## 边界

该门禁覆盖 Ubuntu CI 上的开发统一工作区启动，不替代 Windows/macOS 安装包、Android/iOS 原生构建、签名和真机验收。

## 验证

- 本地冒烟命令通过。
- 相关 workflow 测试、全量 pytest 和桌面生产构建通过后提交。
