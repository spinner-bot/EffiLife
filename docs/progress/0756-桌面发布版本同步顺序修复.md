# 0756 桌面发布版本同步顺序修复

## 问题

桌面发布工作流原先在 `npm ci` 之后才同步 `time-helper/VERSION` 到前端、Tauri、Cargo 和 lockfile。虽然契约测试阶段可以看到同步后的文件，但依赖安装阶段仍使用未同步的版本元数据。

## 处理

- 将 `sync_desktop_version.py` 前移到 Node.js 缓存配置和 `npm ci` 之前。
- 让 npm 缓存键、依赖安装、契约检查和 Tauri 打包使用同一套版本元数据。
- 保留脚本的“只更新版本字段、不重解析依赖树”约束。
- 增加 workflow 顺序测试，防止同步步骤回退到依赖安装之后。

## 验证

- 发布元数据与 workflow 契约测试覆盖同步顺序。
- 未修改当前工作区已有的 `package-lock.json` 用户文件。
