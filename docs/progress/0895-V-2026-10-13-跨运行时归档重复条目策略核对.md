# 0895 跨运行时归档重复条目策略核对

- 创建时间：2026-10-13
- 作者/执行者：Codex
- 状态：[完成]
- 阶段：第 0 阶段

## 核对原因

0894 收紧了 Python 交换层的 ZIP 重复条目策略。由于统一 `.efl` 也由前端 `ArchiveService` 通过 JSZip 读取，需要确认两条运行时路径对相同异常输入的实际行为，避免把静态契约误认为端到端一致。

## 核对结论

- Python `common/data_exchange.py` 直接读取 ZIP 中央目录，并拒绝重复的 `entry.filename`，错误为 `Bundle contains duplicate archive entries`。
- 前端 JSZip 在 `loadAsync` 阶段按安全路径写入 `zip.files` 映射；同名条目在进入 `ArchiveService.parseArchiveData` 前已折叠，业务层只会看到一个文件，因此不会按两个数据集导入。
- 前端仍执行 manifest 数据集去重、文件存在性、大小、JSON 形状和 SHA-256 校验；被折叠条目的最终内容若与清单校验和不一致，会被拒绝。

## 决策

当前保留两端的安全边界：Python 工具链对重复条目显式拒绝，前端依赖 JSZip 的解析折叠并继续执行清单校验。暂不引入自维护 ZIP 中央目录解析器，因为它会扩大移动端包体与维护面，且当前不存在重复条目绕过前端校验的证据。

该边界已明确记录；若未来需要向用户展示“重复条目”专门错误，应先选定可跨平台复用的 ZIP 解析实现，再同步修改两端和协议测试。

## 验证依据

- `common/data_exchange.py` 的 `inspect_bundle` 重复条目检查。
- `time-helper/desk/src/services/ArchiveService.ts` 的 JSZip 加载、清单去重、数据集校验和 SHA-256 校验路径。
- Python 全量回归：`1112 passed`（0894 记录）。

## 未验证边界

未在真实 Android WebView 或生产安装包中构造恶意重复条目归档；当前结论基于项目锁定的 JSZip 实现和源码路径核对。
