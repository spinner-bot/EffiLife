# 统一存档导出形状校验

## 背景

EffiLife 的 `.efl` 存档协议由前端和 Python 工具共同使用。此前 Python 端 `export_workspace_bundle()` 直接写入 canonical 数据集，形状错误要到另一个运行时导入时才被发现，容易产生无法恢复或无法交换的存档文件。

## 本次处理

- Python 端统一工作区导出现在复用 canonical 数据形状校验。
- `app`、`records`、`todos`、`todo_categories`、`plan_helper` 任一形状无效时，在创建目标文件前立即失败。
- 增加测试确保失败导出不会留下半成品 `.efl` 文件。

## 验证

- 数据交换专项测试：通过
- 全量测试：605 passed
- 前端桌面构建：待本轮代码提交后执行

## 结论

跨运行时存档协议现在在导出端和导入端形成对称边界，减少无效统一存档进入备份、迁移和跨设备交换流程的机会。
