# TD 兼容入口真实空状态设计

## 问题

独立 `to-dos/ui` 的 Pinia store 在首次加载时把内置示例待办和示例业务分类放入响应式状态。即使用户没有创建任何数据，兼容入口也会展示“完成项目文档”等虚假内容，与统一工作台的真实空状态约定不一致，并可能让用户误以为这些数据已经进入统一存档。

## 方案

- 首次启动的待办集合从空数组开始。
- 仅保留一个用于新建待办默认归属的系统分类 `default`；工作、学习、生活、健康等业务分类必须由用户创建或从存档导入。
- 已存在的 `to-dos-data` 本地数据继续由 `loadFromStorage()` 原样读取，不做破坏性清理。
- 不改变 TD 的优先级算法、导入导出格式、分类编辑及与统一工作台的实体边界。

## 验收标准

1. 无本地存储时首次状态不含示例待办。
2. 无本地存储时不自动生成示例业务分类，仅有默认分类元数据。
3. 现有本地数据仍可正常加载。
4. `to-dos/ui` 生产构建和 Python 回归测试通过。
