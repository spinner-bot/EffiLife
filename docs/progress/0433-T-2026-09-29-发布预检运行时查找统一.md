# 发布预检运行时查找统一

## 背景

启动器会优先发现 `EFFILIFE_NODE_DIR` 或开发机的 `F:/dev-tools/node`，但发布预检脚本只查系统 `PATH`。这会把实际可用的 Node/npm 错报为缺失，降低诊断结果可信度。

## 本次变更

- 发布预检脚本新增与启动器一致的 Node/npm 查找顺序。
- 支持 `EFFILIFE_NODE_DIR` 显式配置，Windows 开发环境保留 `F:/dev-tools/node` 兼容回退。
- 系统 PATH 仍作为回退来源，不改变 Cargo、Rust、Android SDK、ADB、Java、Xcode 等真实构建门槛。
- 新增自定义目录优先和系统 PATH 回退测试。

## 验证

- 工具查找测试：4 passed。
- 全量 Python 测试：330 passed。
- 实际桌面预检现在正确识别 Node/npm，结果仅报告当前缺少 `cargo`、`rustc`。
