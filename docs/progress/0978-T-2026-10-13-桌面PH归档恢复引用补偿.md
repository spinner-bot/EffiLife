# [完成] 桌面 PH 归档恢复引用补偿

## 背景

桌面端 PH 归档恢复由服务端恢复计划后，再逐个迁移 TD 的 `related_plan_id`。此前 TD 更新中途失败时，已经迁移的对象会停留在新计划，未处理对象仍指向旧计划。

## 实现

- 记录桌面恢复过程中已成功迁移的 TD ID。
- 任一后续 TD 更新失败时，将已迁移对象恢复到原计划 ID。
- 保留服务端恢复错误和 TD 回滚错误的诊断信息，不伪装为恢复成功。
- 与移动端归档恢复采用一致的“快照/逐项更新/失败补偿”原则。

## 验证

- 桌面/移动 PH 归档恢复与统一存档专项：`19 passed`。
- 桌面端生产构建：Vite `1879 modules`，成功。
- 全量 Python 回归将在提交前执行。

## 边界

服务端已完成的 PH 恢复无法由前端撤销；本次确保 TD 引用不会部分迁移。若回滚本身失败，错误会继续抛出并交由存档恢复链路处理。
