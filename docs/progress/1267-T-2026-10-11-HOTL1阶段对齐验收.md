# HOTL-1 阶段对齐验收

日期：2026-10-11

## 背景与目标

`docs/HOTL/1.txt` 指出早期版本混淆 PH、TD 定位，桌面布局未充分利用宽屏，主题切换无法可靠持久化，并缺少统一控制台体验。本报告对当前代码和构建结果进行一次可追溯复核。

## 目标与非目标

- 目标：确认 HOTL-1 中的 PH/TD/TH 职责、入口、首页工作台、桌面/移动布局、主题持久化和日历入口要求已经落实。
- 非目标：本阶段不处理 iOS；不把 Android APK、签名、升级和真实设备验收用静态构建替代。

## 影响范围

- 应用壳：`time-helper/desk/src/App.vue`、`src/router/index.ts`。
- 首页工作台：`src/views/HomeView.vue`。
- PH：`src/views/PlansHubView.vue`、`src/views/PlanView.vue`。
- TD：`src/views/TaskCenterView.vue`、`src/services/todoService.ts`。
- TH：`src/views/PlanView.vue`、时间记录相关视图和服务。
- 主题与设置：`src/views/SettingsView.vue`、`src/stores/app.ts`、`src/theme/ThemeEngine.ts`。

## 对齐结论

### A 级：模块职责与入口

- PH、TD、TH 在应用壳中分别提供独立入口：`/plans`、`/tasks`、`/time`；路由与导航均保留模块代码标识。
- PH 仍以完整 plan 为基本单元，TD 仍以单条快速待办为基本单元，TH 仍以时间记录和日计划为时间维度；跨模块只通过关联字段和深链协作，不把三者合并为同一种实体。
- 首页通过 `HomeView.vue` 展示 TH、PH、TD 的关键摘要，并提供进入对应模块的深链和快捷操作。

### B 级：桌面与移动交互

- `App.vue` 在 `min-width: 1200px` 下启用左侧纵向工作台导航和内容区偏移，利用宽屏进行分区展示。
- `max-width: 680px` 下隐藏桌面导航，启用适合触控的底部导航和安全区内边距；移动布局不是桌面布局的简单缩放。
- 首页、计划中心、任务中心和设置页均保留加载、空数据、错误/不可用和重试状态，避免内容未加载时出现空白区域。

### C 级：主题与日历边界

- 设置页通过 `ThemeEngine` 统一读取 TH 的丰富主题注册表，支持基础、渐变、玻璃和霓虹等主题配置。
- 主题保存路径为“构造草稿 → `appStore.saveConfig` → `DataService.loadConfig` 回读校验 → 更新 Pinia 快照”；离开主题页时会弹出确认并完成保存，不依赖单独的保存按钮。
- 主题切换后由应用壳重新应用 CSS 变量，并监听系统主题变化；因此重启后以持久化配置为准。
- 路由中的旧 `/calendar` 仅保留兼容重定向到 `/records`，主导航不再提供日历入口。

## 兼容性与迁移

- 保留 `/plan`、`/management`、`/calendar` 的旧书签重定向，不改变现有用户入口的可达性。
- PH 的完整计划结构、嵌套分组、软删除显示编号和稳定内部标识不因本次复核改变。
- 未修改用户明确保留的工作树文件。

## 验证命令与结果

在 `time-helper/desk` 执行：

```powershell
npm.cmd run build
```

结果：`vue-tsc` 通过，Vite 转换 1878 个模块，生产构建成功。

此前同阶段已验证：Python 测试 `996 passed`；桌面 Rust `cargo check --target x86_64-pc-windows-msvc` 通过；NSIS 安装包构建通过；正式 sidecar 健康检查 HTTP 200，进程树可由 2 个进程递归清理到 0 个。

## 未验证项与后续边界

- Android APK 仍受 Windows 符号链接权限影响，需启用开发者模式或授予对应权限后再执行真实 APK 打包；Android 真机验收未宣称完成。
- iOS 按当前决策暂不处理。
- 主题在真实安装包中跨重启的 GUI 手工验收仍应在发布候选版本完成；当前已有持久化回读逻辑和生产构建证据。
