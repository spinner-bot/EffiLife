## 发现

发布候选门禁已经检查配置和前端构建，但对当前机器上已经生成的安装包没有统一的本地调用入口。这样可能出现配置和源码构建通过、实际安装包版本或文件状态不符合预期的情况。

## 本次实现

- 为 `scripts/verify_release_candidate.py` 增加可重复的 `--verify-artifact <目录> <扩展名>` 参数。
- 该参数复用安装包校验器，检查产物存在、非空、EffiLife 命名和版本号与 `time-helper/VERSION` 一致。
- 默认不要求开发机必须存在安装包；只有显式提供参数时才执行产物校验。
- README 补充调用方式和发布边界说明。

## 验证结果

- `python -m pytest -q tests/test_release_candidate_script.py tests/test_release_artifacts.py`：7 passed。
- 对当前 Windows NSIS 产物执行：
  `python scripts/verify_release_candidate.py --skip-tests --skip-compatibility-build --skip-build --verify-artifact time-helper/desk/src-tauri/target/release/bundle/nsis .exe`
  结果通过，识别 `EffiLife_1.7.0_x64-setup.exe`，大小 11,604,189 bytes。

## 结论

发布候选现在同时覆盖配置、源码构建和可选的实际安装包产物校验，减少本地候选与正式发布之间的证据断层。阶段保持第 0 阶段。
