# PH 与 TD 入口身份澄清设计

## 背景

HOTL-1 要求 PH 与 TD 保持独立：PH 的基本单元是一整份有主题的事件计划，TD 的基本单元是一条可快速完成的待办。当前路由和数据边界已经分离，但入口标题仍偏抽象，用户仅看到“计划中心”和“统一工作台”，存在再次误解为同一模块的风险。

## 方案

- PH 入口在标题区域明确显示“事件计划 · PH”，并说明其用于组织目标、章节、任务和进展记录。
- TD 入口明确显示“快速待办 · TD”，并说明其用于记录单条即时事项、优先级和截止时间。
- 保留现有 `/plans` 与 `/tasks` 独立路由、数据结构和关联同步；文案只澄清产品定位，不改变 PH/TD 的功能边界。
- 中文和英文目录同时补齐，避免入口在切换语言后丢失说明。

## 验收

- 两个入口均有独立的模块身份标签和定位说明。
- PH 仍可在同一入口切换时间工作台与事件计划，TD 仍只管理快速待办。
- i18n 覆盖测试、全量 Python 测试和桌面前端构建通过。
