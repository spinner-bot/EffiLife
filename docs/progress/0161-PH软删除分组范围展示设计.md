# PH 软删除分组范围展示设计

## 问题

PH 使用内部槽位保存任务，以保证软删除后日志、嵌套组和稳定引用不被破坏；API 会在展示数据中压缩有效任务的 `display_id`。统一计划详情目前仍直接显示分组键中的内部起止索引，例如 `1_3`，删除任务后用户看到的范围可能与可见任务编号不一致。

## 方案

- 保留分组键 `start_end` 及其内部槽位语义，不重排或改写 PH 数据。
- 展示分组时，从当前有效任务中找到位于内部范围内的首尾任务，并使用它们的 `display_id` 组成范围，如 `A1–A2`。
- 如果范围内没有有效任务，显示本地化的“无有效任务”提示，不渲染过期内部编号。
- 嵌套深度仍按原始内部范围计算，避免改变嵌套关系。

## 验收标准

1. 软删除中间任务后，任务列表和分组范围都不显示跳号或内部槽位编号。
2. 嵌套组仍按原始范围正确计算层级。
3. 桌面端和移动端快照展示保持同一语义。
4. 不改变日志、待办关联和原始 Plan 快照。
