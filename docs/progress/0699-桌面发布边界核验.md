# 1205｜桌面发布边界核验

日期：2026-10-10  
状态：阶段核验完成

## 核验范围

本次检查覆盖桌面 Tauri 配置、发布工作流、Plan Helper sidecar、移动边界配置和本地构建环境，不把开发 launcher 的成功误认为安装包已经生成。

## 目标与非目标

- 目标：确认正式桌面发布链路的配置、sidecar、校验物和本机工具链状态真实可追溯。
- 非目标：不在缺少 Cargo/Rust 的机器上伪造安装包，也不把旧版本安装包当作当前版本产物。

## 影响范围

- 模块：统一工作台、Plan Helper sidecar、launcher 与发布脚本。
- 平台：Windows、Linux、macOS 桌面发布边界，以及 Android/iOS 配置边界。
- 数据：不修改用户数据，不改变 `.efl` 数据结构和 PH/TD/TH 的职责边界。

## 结果

- `python scripts/check_release_config.py`：通过。
- `python scripts/check_mobile_release_config.py`：通过。
- 桌面发布工作流包含 Windows NSIS、Linux DEB、Linux AppImage 和 macOS DMG 矩阵。
- Tauri 构建前会生成 Plan Helper sidecar；发布后会校验安装包、checksum 和机器可读 manifest。
- 统一前端构建入口已通过真实生产构建，前端可生成 `dist`。
- 本机 `check_build_environment.py --target desktop` 仍报告缺少 Cargo/Rust，因此当前机器不能完成 Tauri 安装包的编译、安装和升级验收。

## 结论

发布配置与 CI 边界已经具备继续交付的条件；正式安装包验收仍必须在带 Rust/Cargo 的发布环境完成。当前继续开发和测试应使用 launcher 或统一前端构建入口，不能将旧的本地 NSIS 文件当作当前版本产物。

## 兼容性与迁移

本次仅做静态发布核验和文档记录，不产生数据迁移。开发环境继续使用 launcher；正式包继续由 Tauri 管理 sidecar，并使用统一应用数据目录。
