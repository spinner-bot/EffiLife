# 0822 启动初始化阻塞修复

日期：2026-10-01

## 发现

实际使用独立浏览器 profile 访问统一工作区时，页面在 12 秒后仍停留在“正在准备工作台”。启动流程在进入核心 `appStore.init()` 前，使用 `Promise.all` 无期限等待音频、签到和事件三个辅助服务的 IndexedDB hydration；任一请求不返回都会隐藏整个应用。

## 修复

- 为三个辅助服务增加 5 秒有界等待，并与核心工作区初始化并行启动。
- 辅助服务超时只记录 warning，不改变核心工作区启动错误状态。
- 保留服务自身的异步 hydration，不把可选服务的异常升级为应用整体不可用。
- 增加启动契约测试，锁定 timeout、竞速等待和清理定时器行为。

## 验证

- `python -m pytest -q tests/test_startup_initialization.py`：2 passed
- 在 `time-helper/desk` 执行 `npm run build`：通过（vue-tsc 与 Vite，1874 modules）
- 独立浏览器渲染：修复前确认持续显示启动占位页；修复后 headless profile 未稳定返回 DOM，因此不将修复后视觉启动结果标记为已验收

## 边界

本轮不改变数据结构、主题保存协议或辅助服务业务逻辑；原生安装包和真实设备验证仍需对应平台工具链。
