# 1159 统一存档导入大小边界

日期：2026-10-05  
类型：统一数据交换安全与可靠性优化

## 背景与问题

`.efl` 是三个模块共用的数据交换边界。此前导入流程验证了 manifest、数据集名称和摘要，但没有限制归档文件、数据集数量和解压后数据量；异常归档可能造成过量内存占用，且 Python 与前端的导入行为不一致。

## 实现

- Python 交换层和前端存档服务统一采用：归档 64 MB、单数据集 32 MB、数据集总量 64 MB、最多 16 个数据集。
- Python 在读取 JSON 前检查 ZIP 条目大小，并以有上限的读取方式再次保护解压数据。
- 前端在加载 ZIP 前检查文件大小，在读取 manifest 和数据集时检查数量及解压后数据量。
- 保留已有 manifest、SHA-256、数据集形状和旧版存档兼容校验；超限数据不会写入任何模块存储。
- 错误信息接入中英文目录。
