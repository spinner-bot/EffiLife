## 背景

项目已有 `smoke_windows_upgrade.py`，可在隔离目录中验证旧版安装、当前版本升级、卸载以及用户数据探针保留，但该能力此前只能由 CI 工作流直接调用，无法从统一发布候选命令显式执行。

## 本次实现

- 为 `scripts/verify_release_candidate.py` 增加可重复的 `--verify-upgrade <旧版> <当前版> <隔离安装目录> <隔离数据目录>` 参数。
- 复用现有 Windows 升级烟测，不新增安装逻辑，不接触用户现有目录。
- 在候选 JSON 结果中记录升级验收是否被显式执行。
- README 补充使用边界：必须提供不同版本安装包和隔离目录。

## 验证结果

- `python -m pytest -q tests/test_release_candidate_script.py`：2 passed。
- `python scripts/verify_release_candidate.py --help`：成功展示升级验收参数。
- 默认候选流程仍不启动安装程序；升级烟测仅在显式传入参数时执行。
- 当前机器没有第二个历史版本安装包，因此本轮只完成入口契约验证，真实跨版本安装仍由具备历史产物的 Windows 发布环境执行。

## 结论

安装升级验收已纳入统一发布候选入口，补齐了“安装、升级、卸载、数据保留”链路的本地调用能力。阶段保持第 0 阶段。
