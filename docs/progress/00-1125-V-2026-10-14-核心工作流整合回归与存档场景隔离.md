# 核心工作流整合回归与存档场景隔离

## 触发原因

将移动 PH 任务编辑、桌面 PH↔TD、TD 专注、TH 记录、搜索和 EFL 故障恢复放入同一轮浏览器回归时，发现 smoke 脚本的多个存档场景共享页面状态：前一个归档导入流程停留在归档子页，后一个流程却直接按设置主页的按钮下标操作。

这不是产品运行时缺陷，但会使组合验收产生时序/页面状态误报，不能作为产品级门禁长期保留。

## 修复

每个归档场景开始前显式回到 `/settings` 并等待设置页状态，再进入存档管理。这样 `archive-roundtrip`、非法存档和写入失败恢复可以任意组合执行，不依赖前一个场景的页面残留状态。

## 整合回归结果

使用真实 Plan Helper 服务和隔离浏览器存储执行：

```text
python scripts/smoke_browser_workspace.py --url http://127.0.0.1:4173 \
  --ph-plan-flow --mobile-ph-plan-flow --td-task-flow --td-focus-flow \
  --th-record-flow --archive-roundtrip --archive-write-failure-flow \
  --archive-invalid-flow --global-search-flow --mobile-search-flow
```

结果：`ok: true`。

- 桌面 PH 创建/编辑、PH↔TD 联动：通过；
- 移动 PH 创建/任务编辑/长标题无溢出：通过；
- TD 创建、完成、专注、跨窗口同步：通过；
- TH 创建、修改、关联记录：通过；
- EFL 正常往返、非法导入恢复、导入写入失败恢复：通过；
- 桌面与移动搜索：通过；
- 主题 25 项、无保存按钮、主题持久化和语言持久化：通过。

回归修复只改变 smoke 的场景隔离，不改变 PH、TD、TH 数据结构或用户功能。阶段保持第 0 阶段。
