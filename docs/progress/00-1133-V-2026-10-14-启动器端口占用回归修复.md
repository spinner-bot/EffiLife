# [完成] 启动器端口占用回归修复

- 创建时间：2026-10-14
- 执行者：Codex
- 触发原因：发布候选检查中的 Python 回归出现 3 项失败。
- 本次目标：确认失败是否来自启动器功能回归；修复会受工作站真实端口状态影响的测试，使发布门禁稳定反映代码行为。

## 一、问题定位

失败测试均位于 `tests/test_launcher.py`，涉及统一工作台和兼容 Web 入口的默认端口断言。启动器本身会检查本地端口：当 1420 已被占用时，统一工作台会按设计选择下一个可用端口，兼容 Web 入口也会避开已分配端口。

发布候选检查运行时，工作站的 1420 端口处于占用状态，因此启动器实际返回 1421/1422；测试却直接断言 1420/1421，形成了环境相关的误报。这不是端口冲突处理逻辑的缺陷，而是测试没有隔离外部端口状态。

## 二、变更

- `tests/test_launcher.py`
  - 在需要验证默认端口契约的测试中显式模拟“端口均空闲”。
  - 保留独立的端口冲突测试，继续验证占用时向后寻找可用端口的行为。
  - 不改变启动器的端口选择逻辑、环境变量配置或用户可见行为。

## 四、边界与后续

- 该修复仅稳定测试环境，不掩盖真实端口冲突；启动器仍会在运行时选择可用端口并发布实际 URL。
- 后续应继续推进真实用户路径和跨端运行验收，而不是继续重复检查同一端口契约。
