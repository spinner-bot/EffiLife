## 1. 问题定位

工作站具备 Android SDK、NDK、Java、Cargo 和生成的 Tauri Android 工程，但直接执行 Android 构建时发现两类 Windows 构建问题：

- 项目路径包含中文字符，NDK linker 无法稳定打开 Rust 生成的 response/version-script 文件；
- Windows 未启用符号链接权限，Tauri 默认流程无法把 Rust `.so` 链接到 Android `jniLibs`。

另外，项目使用自定义 `tauri.mobile.conf.json`，而 Android 应使用 Tauri 的平台配置合并机制。Tauri 官方文档说明 Android 平台配置文件应使用 `tauri.android.conf.json`，并由 `build.frontendDist` 指定前端产物目录。[Tauri Configuration](https://v2.tauri.app/reference/config/)

## 2. 实现调整

- 新增标准 `time-helper/desk/src-tauri/tauri.android.conf.json`：使用 `npm run build`、`../dist`，不携带桌面 sidecar。
- Android npm 构建入口改为 `tauri android build`，使用标准平台配置自动合并。
- `build_android_managed.ps1` 增加 `CargoTargetDir` 参数，默认使用 ASCII 路径 `F:\android-target\EffiLife`，并让 fallback 从该目录读取新生成的 Rust release 库。
- 保留现有 managed Gradle 回退：符号链接失败后复制 `.so` 到 `jniLibs`，再执行 ARM64 release Gradle 构建。
- 移动发布配置检查增加 Android 平台配置校验。
