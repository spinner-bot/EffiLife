# [完成] TH 启动引用修复补偿

## 背景

启动维护 `repairTodoTimeRecordLinks` 会同时修复指向已删除 TD 的 TH 记录，以及 TD 中指向不存在 TH 记录的反向列表。此前多个日期或多个 TD 逐项写入时发生异常，只返回 `0`，可能留下部分修复结果。

## 实现

- 预先收集所有待修改的 TH 日期快照和 TD 反向引用快照。
- 所有修复写入成功后才视为本轮维护完成。
- 任一写入失败时恢复已修改的 TH 与 TD 数据，并保留错误交由启动错误边界处理。
- 保持“只修复可证明失效引用”的既有安全原则。

## 验证

- TH/TD 启动修复、删除与存档专项：`25 passed`。
- 桌面端生产构建：Vite `1879 modules`，成功。
- 全量 Python 回归将在提交前执行。

## 边界

该维护路径仍采用跨对象的补偿式写入，不宣称为原生 IndexedDB 多 store 单事务；若补偿写入也失败，启动流程会保留失败状态并交由恢复链路继续处理。
