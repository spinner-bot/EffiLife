# 启动器历史安装包过滤实现

## 1. 背景

启动器诊断会扫描桌面端 NSIS 安装包，并根据当前应用版本判断安装包是否过期。发布目录中仍保留着旧品牌“浪兮效率时钟”的历史安装包，这类文件不属于当前 EffiLife 发布产物，却会被扫描并触发版本过期提示，造成启动器诊断误报。

## 2. 本次目标

- 诊断只识别当前 EffiLife 产品命名空间下的安装包。
- 继续识别当前产品的旧版本安装包，并提示其过期。
- 保留历史品牌安装包，不删除、不移动、不修改。

## 3. 实现

在 `launcher/start.py` 的安装包扫描逻辑中增加当前产品名前缀过滤，仅将文件名以 `EffiLife`（大小写不敏感）开头的文件纳入诊断。历史品牌文件仍可存在于发布目录，但不会参与当前版本比较。

在 `tests/test_launcher.py` 增加回归测试，覆盖“只有历史品牌安装包时不产生过期提示”的场景；原有当前产品旧版本安装包测试继续保留。

## 4. 验证

执行：

```text
python -m pytest -q tests/test_launcher.py
```

结果：`82 passed`。

## 5. 影响范围与未覆盖项

本次只影响启动器诊断中的安装包识别，不改变安装包构建、不删除历史文件，也不改变实际启动流程。图形界面端到端自动化验证仍受当前工作站浏览器会话接管限制，未将其冒充为已完成验证。

## 6. 后续

提交并推送本次启动器修复；后续发布诊断应继续以当前 EffiLife 产物为准。
