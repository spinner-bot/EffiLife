# 00-1144-T-2026-10-14 Android 多 ABI 发布工作流一致性

## 类型

T（技术实现与验证）。阶段仍为 0；本编号只递增序列号，不表示阶段变更。

## 背景

本地 Android 托管构建脚本已经支持 `arm64` 与 `x86_64`，并已分别完成构建验证。但移动发布工作流此前没有显式使用 Tauri 的 ABI 拆分参数，正式签名步骤也只处理找到的第一个未签名 APK，存在“本地支持多架构、CI 发布单架构”的一致性风险。

## 本次调整

- 将 CI Android 构建命令改为 `npm run mobile:android:build -- --split-per-abi`。
- 正式发布签名步骤枚举并排序全部 `*-unsigned.apk`，逐个调用签名脚本。
- 保留后续统一的 APK 非空校验、校验和及发布清单生成流程，使每个 ABI 产物都进入同一套发布校验链。
- 增加工作流契约测试，锁定拆分构建和全量签名行为。

## 验证

执行：

```text
python -m pytest -q tests/test_mobile_workflow.py tests/test_mobile_build_scripts.py tests/test_mobile_release_config.py tests/test_ci_workflow.py
```

结果：定向测试 23 passed；完整 Python 回归 1257 passed。

## 边界

- 本次不宣称 Android 真机或模拟器验收完成；当前工作站仍缺少可用的 Android 系统镜像与设备。
- iOS 继续按当前明确范围暂不推进。
- 本次不改变产品功能和数据结构，只修复移动发布链路的一致性。
