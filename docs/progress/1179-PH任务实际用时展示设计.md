# 1179 PH 任务实际用时展示设计

日期：2026-10-09  
类型：设计报告

## 背景

TH 记录和 TD `time_spent` 已经可以通过关联链路同步，但 PH 任务行目前只展示计划预估时间。用户在 PH 推进事件计划时无法直接判断某个任务已经投入了多少时间，TH↔PH 的协同反馈不完整。

## 目标与非目标

目标是在 PH 任务行中只读展示关联 TD 的累计实际用时，并明确这是协同数据而非 PH 自身字段。非目标是把 `time_spent` 写入 PH Plan、让 PH 修改 TD 用时，或把多个模块合并成同一种实体。

## 设计决策

- PH 刷新关联 TD 时同时建立 `taskId -> accumulated minutes` 的内存映射；同一任务存在多个关联待办时累加，避免丢失数据。
- 只有存在关联 TD 的任务显示实际用时；没有关联时保持现有布局。
- 文案使用统一 i18n，显示 0 分钟也有意义，表示关联已建立但尚未记录 TH 时间。
- TD 服务不可用或读取失败时清空映射并保留原 PH 任务内容，不把不可用误显示成 0 分钟。

## 验收条件

1. PH 任务关联 TD 后能够显示 TD `time_spent`。
2. 多个关联 TD 的用时相加。
3. TD 读取失败时不显示伪造的实际用时。
4. PH 仍是 Plan/section/task/log 的唯一编辑者。
5. 中英文、响应式布局、全量测试和桌面构建通过。

## 未验证边界

真实浏览器中的长任务标题、窄屏换行和 TD 服务断开视觉状态需要手动验收；主题持久化受阻、正式安装包和移动真机验收不在本设计范围内。
