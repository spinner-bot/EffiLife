# 1177 TH 手动记录与 TD 累计用时一致性设计

日期：2026-10-09  
类型：设计报告

## 背景

TD 的“记录用时”入口通过 `TodoService.trackTime` 同时维护 `time_spent` 与 `related_time_record_ids`。但 TH 的时间记录表单在用户选择 TD 后，只维护反向记录 ID，导致同一条跨模块操作从不同入口产生不同的待办累计用时。

## 目标与非目标

目标是让 TH 新建并关联 TD 时间记录时，按照实际记录时长增加 TD 的 `time_spent`，并继续保持记录 ID 幂等。非目标是把 TH 记录实体合并进 TD、修改删除记录保留历史用时的既有语义，或改变 PH/TD 的关联结构。

## 设计决策

- TH 保存新记录后调用 TD 现有 `trackTime(todoId, minutes, recordId)` 服务边界，而不是在视图中直接计算和写入 `time_spent`。
- `minutes` 使用记录时长换算并四舍五入到分钟，至少按 1 分钟处理；服务仍负责重复记录 ID 的幂等保护。
- 编辑已有记录时不重复累计同一个记录 ID；从无关联改为关联时按新记录累计；更换关联对象时旧 TD 仍保留历史累计，仅清理反向 ID，遵循现有历史数据语义。
- 关联同步失败时 TH 记录仍保留，界面沿用现有“记录已保存但关联同步失败”反馈。

## 验收条件

1. TH 新建带 TD 关联的记录调用 `trackTime`，并传入该记录 ID。
2. 记录时长换算为正整数分钟。
3. 编辑同一记录不重复调用累计逻辑，改为关联新 TD 时可以累计新 TD。
4. PH→TD→TH 关联链路与既有删除/修复逻辑不变。
5. 中英文文案、全量测试和桌面构建通过。

## 未验证边界

真实浏览器中修改已有记录时的累计数值需要手动验收；本设计不处理主题持久化受阻、原生安装包或移动真机验收。
