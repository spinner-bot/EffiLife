# 冷启动存储读取边界修复

日期：2026-10-02

## 背景与问题

HOTL-1 要求统一应用壳可靠启动。使用本机 Edge 无头模式直接访问运行中的统一工作区时，曾观察到启动错误：

```text
Workspace initialization stalled at today workspace
```

源码中每个 Pinia 初始化阶段只有 5 秒超时，而应用核心启动总边界为 15 秒。冷启动时 IndexedDB 初始化或读取稍慢，会被阶段边界提前判定为整个工作区失败。

## 目标与非目标

- 目标：给冷启动存储读取留出合理时间，同时保留有限的失败边界和 localStorage 降级路径。
- 非目标：不无限等待，不改变 canonical 数据结构、主题协议或 PH/TD 职责边界。
- 非目标：不修改用户提供的 `docs/HOTL/` 和受保护的 `package-lock.json`。

## 实施内容

1. Pinia 单阶段初始化超时从 5 秒调整为 15 秒。
2. 统一应用核心启动超时从 15 秒调整为 30 秒。
3. IndexedDB 单键读取和 raw `getAll` 增加 3 秒读取超时；超时后沿用既有 localStorage 降级机制。
4. 增加初始化边界和 IndexedDB 读取边界契约测试。

## 兼容性与行为

- 正常 IndexedDB 读取路径不变。
- IndexedDB 打开或读取异常时仍不会覆盖或删除本地数据，只切换到已有降级读取路径。
- 30 秒是核心启动的硬上限；失败时仍显示可重试的本地化诊断。

## 验证

已验证：

```text
python -m pytest -q
792 passed in 7.61s

npm run build
vue-tsc passed
1877 modules transformed
✓ built in 5.25s
```

无头 Edge 已真实加载统一页面并读取到当前 Vue 应用 DOM。首次冷启动曾复现上述阶段超时；修复后的 `--dump-dom` 受开发服务器/无头虚拟时间限制仍显示启动态，尚不能作为主题交互和完整启动成功的替代验收证据。
