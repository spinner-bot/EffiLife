# PH 与 TD 边界复核

日期：2026-10-02

## 复核结论

HOTL-1 要求 PH 是完整的事件计划，TD 是独立的单条待办。当前统一工作台应保持 `/plans` 与 `/tasks` 两个独立入口；TD 的 `related_plan_id` / `related_plan_task_id` 只能作为可选数据引用，不能反向把 PH 任务列表嵌入 TD，或在 PH 页面自动生成 TD。

## 本轮判断

代码中已经存在用于未来协同的多语言键和稳定引用字段，但现有模块边界测试明确要求 PH 页面不直接持有 TD 关联字段。仅凭文案不能推断应该增加“加入待办”按钮，因此没有把该设想落地为 UI 功能。

这样可以保留数据层的可扩展性，同时避免把“模块协同”错误实现为“模块合并”。后续若要增加显式跨模块动作，应先在新的需求/评审文件中明确授权及交互语义。
