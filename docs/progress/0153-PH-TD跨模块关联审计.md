# PH-TD 跨模块关联审计

日期：2026-09-30

## 审计结论

PH 与 TD 继续保持不同基本单元：PH 保存整份 `Plan`，TD 保存单条待办。两者只通过稳定的 `related_plan_id` 与 `related_plan_task_id` 协同：

- PH 详情页可以为单个任务或全部未完成任务显式创建 TD。
- TD 编辑会先更新源 Plan 任务，再更新待办，失败时保留错误反馈。
- PH 任务完成会同步已关联 TD；TD 入口可以返回对应 Plan 与复合任务编号。
- 删除/软删除任务时会解除待办引用，不重排或改写 PH 历史 log。
- 移动端本地 Plan 仍保留原始 section、任务索引与嵌套 group 结构，模板创建不会隐式生成 TD。

## 边界

本轮未将 PH 与 TD 合并为同一种实体，也未把 TD 自动化为模板创建副作用；这符合 HOTL-1 对两模块定位的纠偏要求。
