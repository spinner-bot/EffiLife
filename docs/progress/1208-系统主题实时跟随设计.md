# 1208｜系统主题实时跟随设计

日期：2026-10-10  
状态：设计完成，待实现

## 背景

ThemeEngine 的 `system` 主题会通过 `matchMedia('(prefers-color-scheme: dark)')` 计算浅色或深色样式，但当前应用壳只在初始化和配置变更时调用主题应用逻辑。操作系统在 EffiLife 运行期间切换外观时，页面不会即时跟随，用户会误认为主题持久化或主题引擎失效。

## 目标与非目标

- 目标：当用户选择 `system` 主题时，实时响应操作系统明暗模式变化，并更新统一应用壳、TH 页面、PH/TD 页面和主题画布。
- 目标：监听生命周期清晰，应用卸载或主题切离后不残留监听器。
- 非目标：不修改用户保存的主题类型，不改变丰富主题预设，不将系统主题强制写入 `light`/`dark`。

## 设计决策

1. 监听器放在 `App.vue` 应用壳，而不是某个设置页面，确保所有路由和模块共享同一主题源。
2. 使用 `window.matchMedia` 的标准 `change` 事件；旧浏览器仅在缺少现代 API 时使用兼容的 `addListener/removeListener`。
3. 只有当前配置类型为 `system` 时才注册和响应；切换到其他主题立即移除监听器。
4. 复用既有 `applyTheme()` 和 `getThemeCssVariables()`，不复制主题颜色或破坏 TH 的 Canvas 渲染链。

## 状态覆盖

- 浏览器不支持 `matchMedia`：保持现有静态回退，不阻断启动。
- 主题切换中：先清理旧监听，再按新类型决定是否注册。
- 组件卸载：移除监听，避免热更新或测试重复注册。
- 减少动效：不新增动效；既有主题画布继续遵循系统减少动效设置。

## 影响范围

- `time-helper/desk/src/App.vue`：系统主题监听生命周期。
- 主题契约测试与进展记录。
- 不涉及 PH 原始数据、TD 数据、TH 记录和 `.efl` 存档协议。

## 验收条件

1. `system` 主题注册 `change` 监听并在变化时重新应用 CSS 变量。
2. 非 `system` 主题不保留媒体查询监听。
3. 组件卸载清理监听，兼容现代和旧版 MediaQueryList API。
4. 主题相关测试、全量 Python 测试和前端生产构建通过。
