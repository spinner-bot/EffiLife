# 1181 PH 实际用时跨模块即时刷新设计

日期：2026-10-09  
类型：设计报告

## 背景

PH 任务行现在可以只读显示关联 TD 的累计 `time_spent`。TH 新增、编辑或删除时间记录时，会更新记录数据并通知 `records`；关联 TD 的反向累计更新会通知 `todos`。当前 PH 工作台只处理 `plans/archive/network`，因此在 PH 页面保持打开时，用时徽标可能停留在旧值。

## 目标与非目标

目标是让已打开的 PH 工作台在关联 TH/TD 数据变化后，自动重新读取关联 TD 的累计用时，同时保留当前计划编辑状态和已有的刷新串行机制。

非目标是把 TH 记录或 TD 实体合并进 PH，也不把累计用时写回 PH Plan；PH 仍然是 Plan/section/task/log 的唯一编辑入口。

## 设计决策

- `todos` 和 `records` 都视为 PH 用时只读投影的刷新源。
- 只要当前打开计划，就刷新计划详情和关联 TD 用时；计划数据本身若未变化则由现有读取保持一致，避免另建一套跨模块状态缓存。
- `archive` 仍按原逻辑刷新计划/存档；`plans` 与 `network` 仍按原逻辑刷新计划。
- 延续 `pendingWorkspaceSources` 队列和 `isLoading` 门控，多个通知合并处理，避免 TH 保存过程中出现并发读取或事件丢失。
- TD 服务读取失败时清空用时映射并保留 PH 任务内容，不显示伪造的 0 分钟；恢复后由下一次通知或重新进入页面重建映射。

## 兼容性与边界

不新增数据字段、不改变 PH/TD 关联协议、不改变 `.efl` 存档格式；移动端沿用同一工作台逻辑。真实浏览器多窗口和 TD 服务暂时不可用时的视觉状态仍属于手工验收边界。

## 验收标准

1. PH 页面打开时，TH 新增/编辑/删除关联记录能触发用时显示刷新。
2. 同一批次的 `records` 与 `todos` 通知不会产生并发刷新或丢失后续事件。
3. PH 原有计划编辑、存档、重试和 TD 不可用降级行为不变。
4. 新增回归测试、全量 Python 测试和桌面端构建通过。
