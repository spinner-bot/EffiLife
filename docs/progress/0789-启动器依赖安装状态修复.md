# 0789｜启动器依赖安装状态修复

## 状态

已完成，2026-10-01。

## 背景与问题

legacy 菜单允许在同一启动器进程中反复打开兼容模块。模块首次运行的 `npm install` 成功后，原逻辑仍保留 `needs_setup=true`，再次打开模块会重复执行安装，造成不必要的等待，并可能被误认为启动器卡住。

## 实现与边界

- 仅在 setup 命令返回码为 0 后将当前模块的内存状态更新为 `needs_setup=false`。
- 失败、超时和异常路径仍保留待安装状态，下一次尝试可以重试。
- 不改变磁盘依赖检测、统一工作区默认入口或正式 Tauri 包行为。

## 验证

- `tests/test_launcher.py` 增加“成功安装后复用模块不重复安装”的启动流程测试。
- 需运行完整 pytest 与启动器相关集成测试。
