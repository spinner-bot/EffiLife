# Android ARM64 本机构建验证

## 1. 背景

当前阶段暂不做 iOS 端，但需要确认统一环境站已经具备继续推进 Android 端的基础条件。由于项目路径包含中文，且当前 Windows 未开放创建符号链接权限，Tauri CLI 的 Android 构建在生成工程阶段无法直接完成。

## 2. 本次处理

- 使用统一环境站中的 Node、Rust、Android SDK/NDK、Java 17 和 Gradle 缓存重新执行 Android 构建。
- Rust `aarch64-linux-android` release 库构建成功。
- 将已构建的 Rust 动态库放入 Android 工程的 `jniLibs/arm64-v8a`，并将当前前端产物同步到生成工程 assets。
- 对生成的 Android 工程启用 `android.overridePathCheck=true`，允许中文项目路径参与 Gradle 构建。
- 使用 `F:\dev-tools\gradle-home` 作为 Gradle 用户目录，避开 C 盘中已损坏的旧缓存；未删除原缓存。
- 执行 `app:assembleArm64Release -x rustBuildArm64Release` 完成 ARM64 APK 构建。

## 4. 边界与后续

- 这是 ARM64、未签名的本地验证包，不等同于正式发布包，也尚未替代真实 Android 设备安装验收。
- 当前 Tauri CLI 直接 Android 构建仍受 Windows 符号链接权限限制；本次通过生成工程的 Gradle 构建完成了可验证的替代路径。
- iOS 端按当前决策暂不推进。
- 后续应将上述替代路径收敛为正式构建脚本，并补充 Android 真机安装、启动和升级验证。
