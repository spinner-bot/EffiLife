# 1243｜启动器备用端口身份校验

创建时间：2026-10-10  
执行者：Codex  
状态：[完成]

## 触发原因

上一轮已为 TH/TD 前端增加备用端口选择，但启动器的 HTTP 就绪探测只在默认工作台端口校验 EffiLife 页面标识。若工作台切换到备用端口，任意返回 200 的本地服务都有可能被误认为可复用的统一工作台。

## 本次目标与完成情况

- 为启动模块声明服务类型：统一工作台为 `workspace`，旧版待办 Web 为 `todos`。
- 对 `workspace` 无论使用默认端口还是备用端口，都要求页面包含 EffiLife 应用标识。
- 为兼容 Web 保留独立的待办页面标题校验。
- 对未声明服务类型的旧调用保留原有兼容探测行为，避免破坏旧版菜单和外部调用。

## 变更文件

- `launcher/start.py`：服务类型元数据、模块探测和启动等待流程。
- `tests/test_launcher.py`：备用端口误识别回归测试、兼容 Web 身份测试。

## 验证

- `py -m pytest -q tests/test_launcher.py`：通过。
- `py -m pytest -q`：待本轮提交后再执行一次全量回归。
- `py scripts/smoke_startup.py`：此前已验证 TH、Plan Helper 健康检查和端口释放；本轮未改变其端口分配协议。

## 风险与未验证项目

- 未在两个真实竞争服务同时抢占端口的物理竞态下验证；探测和启动之间仍存在不可完全消除的时间窗口。
- 正式 Tauri 包的原生 sidecar 启动不受本次开发启动器探测逻辑影响，仍需发布环境验收。

## 被否决方案

- 不采用“所有 HTTP 200 都算就绪”：会掩盖备用端口上的错误服务。
- 不把 PH API 的健康检查改成页面标题校验：其 `/api/health` JSON 协议已有明确且更稳定的服务标识。
