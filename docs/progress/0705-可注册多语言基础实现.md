# 1211｜可注册多语言基础实现

日期：2026-10-10  
状态：已完成并推送

## 背景与目标

前端语言层已有中英文和回退机制，但 `Locale` 类型、语言识别和目录存储仍把语言集合固定在两个代码上。本次实现可注册 locale 目录，为后续增加第三语言提供稳定扩展点，同时保持当前双语用户体验完全兼容。

## 非目标

- 本次不新增第三种完整翻译，不改变现有中文/英文文案。
- 不修改存档协议、用户数据、TH/PH/TD 数据关系或主题系统。
- 不引入网络翻译和异步语言包下载。

## 影响范围

- `time-helper/desk/src/i18n/index.ts`：语言 registry、语言识别和动态目录注册。
- `tests/test_locale_registration_contract.py`：新增扩展能力契约。
- 现有 i18n、存档、日期和组件文案调用保持原 API。

## 实施内容

1. `Locale` 改为可表示注册语言代码的字符串类型，内置 `zh-CN` 与 `en-US` 不变。
2. 新增 `registerLocale(definition, catalog, navigationCatalog?)`；空代码或重复代码拒绝注册，不覆盖既有目录。
3. 浏览器语言初始化改为注册表精确匹配与语言前缀匹配，不再硬编码 `en`/`zh` 分支。
4. 动态目录继续遵循当前语言、注册 fallback、key 的查找链；缺失动态目录时安全回退。
5. 注册成功后同步更新 `LOCALE_DEFINITIONS` 与 `SUPPORTED_LOCALES`，LocaleSwitcher 可复用同一来源。

## 兼容性与迁移

已有 `efflife_locale` 中的 `zh-CN`、`en-US` 值无需迁移。未知值仍回退到中文。现有双语静态目录和导航 fallback 的键集合未改变；新增语言只需在应用挂载前注册定义与目录。
