# 0815 移动构建前端早期门禁

日期：2026-10-01

## 背景

移动原生 workflow 原先在契约测试后直接初始化并构建 Tauri Android/iOS 工程。共享前端编译错误因此可能延迟到原生构建阶段才暴露，增加失败诊断成本。

## 目标与非目标

目标是在原生工程初始化前独立验证共享前端生产构建，并保持 Android/iOS 两条构建路径对称。非目标是把前端构建通过等同于原生安装包、签名或设备验收完成。

## 实施内容

- Android job 在 mobile boundary 契约测试后运行 `npm run build`；
- iOS job 在 mobile boundary 契约测试后运行 `npm run build`；
- 共享前端构建失败会在原生初始化前终止对应 job；
- 更新 workflow 契约测试，要求两个目标均具备该门禁。

## 兼容性

不改变 PH、TD、TH 数据结构、模块边界或移动端运行时配置；仅增加 CI 早期校验步骤。移动 workflow 仍按目标分别执行，Android/iOS 产物目录和 manifest 不互用。

## 验证

- `python -m pytest -q tests/test_mobile_workflow.py tests/test_mobile_build_scripts.py tests/test_mobile_release_config.py`：11 passed；
- `python -m pytest -q`：673 passed；
- 共享前端生产构建已在本阶段前置验证通过：`vue-tsc` 与 Vite build 均通过。

## 未验证项

本机没有 Android SDK、Cargo 或 Xcode，未执行真实 Android/iOS 原生构建；原生安装、签名和设备验收仍需对应 runner。

## 提交与推送

本报告随 workflow 修复提交并推送。
