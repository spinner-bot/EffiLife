# 00-1032-D-2026-10-14-启动器 Windows 进程树退出清理设计

## 背景

统一启动器通过 `npm.cmd` 启动 Vite。Windows 下 npm shim 可能先退出，而 node/Vite 子进程仍继续监听工作台端口，导致下一次启动被迫递增端口，最终影响浏览器入口、测试和用户判断。

## 决策

- 启动器创建的进程均视为 launcher-owned。
- Windows 清理始终执行 `taskkill /PID <parent> /T /F`，不以 shim 的 `poll()` 状态作为前置条件。
- 若 taskkill 失败且父进程仍存活，再使用进程自身的终止方式兜底。
- 复用外部健康服务的路径不调用该清理函数，避免误杀用户自行启动的服务。
- POSIX 的进程组清理语义保持不变。

## 非目标

不扫描或终止非 launcher-owned 的任意端口进程，不改变端口自动配置和正式 Tauri 发布模式。
