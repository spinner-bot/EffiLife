# 1059 PH 与 TD 职责边界审计

日期：2026-10-02

## 审计目标

确认统一工作台的功能融合没有把 PH（事件计划）与 TD（瞬间待办）错误合并。HOTL-1 要求三者协同，但 PH 与 TD 必须保持不同基本单元和独立工作流。

## 当前结论

- PH 的基本单元仍是完整 `plan`，包含基本信息、Section/任务、嵌套分组和独立进展日志。
- TD 的基本单元仍是单条待办，负责快速捕获、优先级、截止日期、子任务和用时记录。
- PH 详情页不自动创建 TD，不批量复制计划任务，不同步 TD 描述或完成状态。
- TD 编辑页不直接修改 PH 任务，也不把 TD 页面伪装成 PH 计划编辑器。
- 需要关联时仅通过统一数据层保留引用字段和存档修复能力，不改变任一领域的核心结构。
- TH 的时间记录与 TD 可建立记录关联，但不替代 PH 自己的进展日志。

## 后续方向

继续优化三模块之间的导航、摘要和引用可见性时，应优先提供“打开关联对象”的只读入口；任何自动复制、双向状态同步或任务结构改写，都必须先经过新的需求评审，不能作为普通 UI 优化引入。
