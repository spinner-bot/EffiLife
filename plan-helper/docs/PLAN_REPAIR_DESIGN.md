# plan-helper 完整性修复设计方案

## 目标

修复 plan-helper 当前从“创建计划”到“编辑、执行、备份”的核心闭环，使计划不再只能创建空壳，并确保日期、导航和数据操作可用。

## 设计方向

采用“桌面工作台式计划编辑器”：左侧保留模块导航与计划列表入口，主区域使用计划详情和分组任务编辑区；新建计划使用分步表单，先填写基本信息，再编辑章节和任务。视觉上沿用现有浅色工作台，但降低 Emoji 依赖，使用统一图标字符与明确的按钮状态。

`plan-helper` 不提供日历功能。日历、日期浏览和时间记录属于 `time-helper`；本模块只负责计划模板、计划内容、任务进度和计划日志。因此需要移除计划助手中的日历导航、日历视图、日历路由及相关无效入口。

## 数据与日期规则

- 内部日期继续使用 `[year, month, day]`，避免破坏现有 JSON/API 兼容性。
- 所有用户可见日期统一显示为 `yyyy/mm/dd`。
- 新建计划日期默认使用浏览器本地当前日期，并在表单打开时填充。
- 接收日期时校验真实日期，错误时保留用户输入并提示原因。

## 新建计划流程

新建表单包含：

- 计划名称（必填）
- 计划日期（默认今天，必填）
- 章节列表：章节名称、说明
- 每个章节的任务列表：任务内容、预计分钟数

创建时先提交基本信息，再按顺序创建章节和任务；任一步失败都显示具体原因，并保留当前表单内容。另提供“从模板创建”作为快速入口。

## 编辑流程

计划详情页增加“编辑计划”入口，支持：

- 修改计划名称和日期
- 新增、删除章节
- 修改章节名称和说明
- 新增、修改、软删除任务
- 修改后重新加载详情和总览数据

后端新增对应的细粒度 API，避免前端直接修改内部数据结构。

## 导航与存档

- 设置按钮打开可关闭的设置面板，支持 Esc 和遮罩关闭。
- 存档按钮执行真实备份，并在设置/存档区域展示最近备份、导出和恢复入口。
- 所有异步按钮具备默认、悬停、聚焦、按下、禁用、加载中、成功和错误状态。

## 实施阶段

1. 后端日期、计划编辑 API 与持久化边界修复。
2. 新建计划表单和默认日期。
3. 计划详情编辑器与任务/章节操作。
4. 移除日历导航、视图和路由，保留日期字段作为计划元数据。
5. 设置、存档入口与反馈状态。
6. 测试、文档和版本日志更新。

每个阶段独立 commit；需要合并分支时必须使用 `git merge --no-ff`，严禁 fast-forward。
